# Путеводитель по библиотеке системных инструкций (`agent-instructions`)

> **Концепция библиотеки:** Данная папка представляет собой универсальный «съемный диск» модульных системных промптов и навыков (скиллов) для любой нейросети (ChatGPT, Claude, Gemini, DeepSeek, Cursor, Antigravity IDE и др.). 
> Архитектура инструкций разделена на два уровня:
> 1. **Базовое ядро (Core Layer):** фундаментальные инструкции по манере мышления, инициативности и качеству русского языка — **подключаются автоматически и работают всегда**.
> 2. **Прикладной слой (Task Layer):** съемные инженерные модули под конкретные типы работ (Python, C++, Word/ГОСТ, Markdown, ревью и т.д.) — **подключаются по согласованию с пользователем под конкретную задачу**.

## 2. Обязательный протокол работы нейросети (Bootstrap Protocol)

Главной точкой входа является файл [`AGENTS.md`](AGENTS.md). Когда пользователь передает нейросети папку `agent-instructions/` или файл `AGENTS.md`, нейросеть обязана следовать протоколу:

```mermaid
sequenceDiagram
    autonumber
    actor User as Пользователь
    participant AI as Нейросеть / Агент
    participant Lib as Библиотека agent-instructions

    User->>AI: Запрос к проекту + папка agent-instructions
    AI->>Lib: Читает AGENTS.md и README.md
    Note over AI,Lib: Шаг 0: Проверка AGENTS.md, запрос расположения или автокоррекция абсолютного пути
    Note over AI,Lib: Шаг 1: Автоматически активирует БАЗОВОЕ ЯДРО (ai_persona_agent + text_humanizer_ru)
    AI->>AI: Сопоставляет задачу пользователя с каталогом прикладных модулей
    AI->>User: ПРЕДЛОЖЕНИЕ: "Базовое ядро активно. Для задачи предлагаю подключить модули: [...] Подтвердите?"
    User->>AI: Подтверждение / Корректировка списка модулей
    AI->>Lib: Загружает согласованные модули в контекст
    AI->>User: Выполняет задачу строго по активным инструкциям
    Note over User,AI: В ходе диалога пользователь может менять прикладные модули ("отключи X, включи Y")
```

### Шаг 0. Самоустановка загрузчика и привязка к Workspace (Self-Bootstrapping)
Чтобы не копировать тяжелую папку библиотеки в корень каждого рабочего репозитория, проект связывается с ней через компактный файл-указатель `AGENTS.md`:
- **Если файла `AGENTS.md` в проекте нет:** агент опрашивает пользователя, где именно его создать (в корне Workspace), и прописывает в нем абсолютный путь к `agent-instructions/AGENTS.md` для конкретного устройства.
- **Если файл `AGENTS.md` уже существует, но путь указан неверно** (например, файл перенесен с другой машины или ОС): агент самостоятельно исправляет ссылку на актуальный абсолютный путь к библиотеке на текущем компьютере.
- **Если файл `AGENTS.md` уже существует и путь корректен:** файл не перезаписывается, агент переходит к шагу 1.

### Шаг 1. Безусловная активация базового ядра
Сразу при старте диалога нейросеть загружает:
- [`ai_persona_agent.md`](ai_persona_agent.md)
- [`text_humanizer_ru.md`](text_humanizer_ru.md)

Они определяют тон общения, глубину анализа и искоренение канцелярита во всех последующих ответах.

### Шаг 2. Запрос на согласование прикладных промптов (Монтирование)
**Перед началом любых действий (написания кода, отчетов или планов)** нейросеть обязана сопоставить запрос пользователя с каталогом и запросить подтверждение на монтирование прикладных модулей:

> ⚙️ **Инициализация системных инструкций:**  
> - 🟢 **Базовое ядро (подключено автоматически):** `ai_persona_agent.md`, `text_humanizer_ru.md`.  
> - 📦 **Предлагаемые прикладные модули под вашу задачу:**  
>   - `[x]` **`<имя_модуля_1.md>`** — `<краткое назначение>`  
>   - `[x]` **`<имя_модуля_2.md>`** — `<краткое назначение>`  
>  
> *Подтвердите подключение прикладных модулей или укажите, какие добавить/отключить.*

### Шаг 3. Удержание в фокусе внимания
После подтверждения пользователем выбранные модули действуют как **постоянные системные инструкции** на протяжении всего диалога. Нейросеть обязана сверяться с ними перед каждым действием.

### Шаг 4. Динамическое переключение («горячая замена»)
Пользователь может в любой момент изменить состав прикладных модулей (например: *«Подключи `doc_word_gost.md` и отключи `code_python.md` — переходим к верстке отчета по ГОСТ»*). Базовое ядро при этом продолжает действовать постоянно.

## 5. Фундаментальные операционные принципы

1. **🔒 Статус Read-Only библиотеки инструкций (`agent-instructions`):**
   - Библиотека системных инструкций по умолчанию имеет для агента статус **строго только для чтения**.
   - При любых запросах пользователя на изменение файлов библиотеки агент **обязан в обязательном порядке переспросить пользователя** (*«Вы действительно хотите внести изменения в библиотеку системных инструкций agent-instructions?»*) и приступать к правкам только после получения прямого подтверждения.
   - **Обязательное тестирование и немедленный пуш:** после внесения подтвержденных изменений агент обязан прогнать сборочные тесты (`pytest agent-instructions/tests`) и при их успешном прохождении сразу отправить коммит в удаленный репозиторий (`git push origin <branch>`), не запрашивая отдельной команды на пуш.

2. **🛡️ Неприкосновенность упавших тестов (Python, C++):**
   - При падении тестов категорически запрещено изменять сам тест или ослаблять проверки ради получения зеленого отчета.
   - Ошибки локализуются и устраняются исключительно в коде реализации.
   - Любое изменение тестов при вынужденных архитектурных решениях согласуется с пользователем в обязательном порядке.
