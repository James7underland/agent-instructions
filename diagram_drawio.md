# Проектирование и генерация диаграмм Draw.io (XML)

> Модуль системных инструкций по созданию, валидации и экспорту схем в формате Draw.io XML (`.drawio` / `*.drawio.svg`).
> Путеводитель по библиотеке — [`README.md`](README.md).
> Оформление Markdown-документов — [`doc_markdown.md`](doc_markdown.md).

---

## 1. Общие принципы

1. **Редактируемый исходник прежде всего.** Результатом работы всегда выступает валидный XML-файл `.drawio`. Растровый экспорт служит лишь для предварительного просмотра.
2. **Разделение логики и представления.** Сначала определяется топология (узлы, связи, вложенность), затем назначаются визуальные стили и точные координаты.
3. **Стабильность идентификаторов.** Каждый элемент схемы имеет уникальный и постоянный `id`. Это исключает смещение связей при обновлениях.
4. **Контейнерная вложенность.** Дочерние блоки привязываются к родителям через `parent="<id_родителя>"`, а их координаты задаются относительно левого верхнего угла родителя.
5. **Аккуратная маршрутизация связей.** Стрелки не должны проходить сквозь чужие блоки, перекрывать текст или накладываться друг на друга.

## 2. Базовый каркас XML и синтаксические ограничения

Любой файл `.drawio` строится на строгой XML-структуре:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<mxfile host="drawio" version="26.0.0">
  <diagram name="Page-1" id="page-1">
    <mxGraphModel dx="1200" dy="800" grid="1" gridSize="10" guides="1" tooltips="1" connect="1" arrows="1" fold="1" page="1" pageScale="1" pageWidth="1169" pageHeight="827" math="0" shadow="0">
      <root>
        <mxCell id="0" />
        <mxCell id="1" parent="0" />
        <!-- Пользовательские элементы начинаются с id="2" -->
      </root>
    </mxGraphModel>
  </diagram>
</mxfile>
```

### Жёсткие правила синтаксиса:

- Ячейки `id="0"` и `id="1"` обязательны. Удалять или переопределять их запрещено.
- Пользовательские блоки получают числовые ID, начиная с `2`, либо осмысленные строковые ключи (`id="api_gateway"`). Запрещено назначать пользовательским блокам ID `0` или `1`.
- Запрещено использовать последовательность двух дефисов `--` внутри XML-комментариев: это ломает XML-парсер.
- Спецсимволы в атрибутах XML экранируются: `&` как `&amp;`, `<` как `&lt;`, `>` как `&gt;`, `"` как `&quot;`.
- Перенос строк внутри атрибута `value="..."` оформляется сущностью `&#xa;`. Литерал `\n` не поддерживается.
- Стиль текстовых блоков всегда содержит `html=1;` для корректного отображения шрифтов.

## 3. Вершины и блоки (Shapes / Vertices)

Вершина объявляется тегом `<mxCell>` с атрибутом `vertex="1"` и дочерним элементом геометрии `<mxGeometry>`.

```xml
<mxCell id="2" value="Название сервиса" style="rounded=1;whiteSpace=wrap;html=1;fillColor=#dae8fc;strokeColor=#6c8ebf;fontColor=#000000;fontSize=12;fontStyle=1;" vertex="1" parent="1">
  <mxGeometry x="120" y="140" width="160" height="60" as="geometry" />
</mxCell>
```

### Основные типы фигур:

| Тип элемента | Стилевые директивы | Область применения |
| --- | --- | --- |
| Прямоугольник | `rounded=0;whiteSpace=wrap;html=1;` | Базовые модули, внешние системы |
| Скругленный блок | `rounded=1;whiteSpace=wrap;html=1;` | Микросервисы, функциональные блоки |
| База данных | `shape=cylinder3;whiteSpace=wrap;html=1;boundedLbl=1;backgroundOutline=1;size=15;` | БД, хранилища данных, кеши |
| Ромб / решение | `rhombus;whiteSpace=wrap;html=1;` | Развилки алгоритмов, условия |
| Круг / овал | `ellipse;whiteSpace=wrap;html=1;` | Начало / конец процесса, очереди |
| Контейнер с заголовком | `swimlane;startSize=30;html=1;collapsible=1;` | Подсистемы, логические уровни, зоны доверия |
| Скрытый контейнер | `container=1;pointerEvents=0;` | Группировка элементов без видимой рамки |

### Правила работы с контейнерами:

1. Дочерний элемент указывает ID контейнера в атрибуте `parent`:
   ```xml
   <!-- Родитель -->
   <mxCell id="group_core" value="Core Backend" style="swimlane;startSize=28;fillColor=#f5f5f5;strokeColor=#666666;" vertex="1" parent="1">
     <mxGeometry x="80" y="100" width="400" height="240" as="geometry" />
   </mxCell>

   <!-- Дочерний блок: x и y считаются от левого верхнего угла group_core -->
   <mxCell id="svc_auth" value="Auth Service" style="rounded=1;whiteSpace=wrap;html=1;fillColor=#dae8fc;strokeColor=#6c8ebf;" vertex="1" parent="group_core">
     <mxGeometry x="30" y="50" width="140" height="60" as="geometry" />
   </mxCell>
   ```
2. Контейнерам без собственных связей задается `pointerEvents=0;`, чтобы границы не перехватывали клики и курсоры связей.

## 4. Соединители и связи (Edges / Connectors)

### Главное правило соединения:
Каждая связь объявляется с атрибутом `edge="1"`, ссылками `source` и `target`, и **обязана содержать развернутый тег `<mxGeometry relative="1" as="geometry" />`**. Самозакрывающийся тег `<mxCell edge="1" />` невалиден и ломает рендеринг.

```xml
<mxCell id="edge_1" value="gRPC" style="edgeStyle=orthogonalEdgeStyle;rounded=1;orthogonalLoop=1;jettySize=auto;html=1;strokeColor=#4d4d4d;strokeWidth=1;" edge="1" parent="1" source="2" target="3">
  <mxGeometry relative="1" as="geometry" />
</mxCell>
```

### Атрибуты и стили связей:

- **Ортодоксальная маршрутизация:** стиль всегда включает `edgeStyle=orthogonalEdgeStyle;rounded=1;orthogonalLoop=1;jettySize=auto;html=1;`. Это гарантирует прямоугольные аккуратные изгибы вместо диагональных прямых.
- **Точки привязки:** чтобы жестко зафиксировать, откуда и куда входит стрелка, используются относительные координаты (от 0.0 до 1.0):
  - Снизу вверх: `exitX=0.5;exitY=1;entryX=0.5;entryY=0;`
  - Слева направо: `exitX=1;exitY=0.5;entryX=0;entryY=0.5;`
- **Промежуточные точки (Waypoints):** для обхода препятствий внутри `<mxGeometry>` создается массив точек:
  ```xml
  <mxCell id="edge_bypass" value="" style="edgeStyle=orthogonalEdgeStyle;rounded=1;orthogonalLoop=1;jettySize=auto;html=1;" edge="1" parent="1" source="node_a" target="node_b">
    <mxGeometry relative="1" as="geometry">
      <Array as="points">
        <mxPoint x="450" y="220" />
        <mxPoint x="450" y="380" />
      </Array>
    </mxGeometry>
  </mxCell>
  ```
- **Анимация потока:** директива `flowAnimation=1;` добавляет движущиеся маркеры вдоль стрелки при просмотре в Desktop и SVG.
- **Типы стрелок:**
  - Обычный вызов: `endArrow=block;endFill=1;`
  - Асинхронный ответ / слабая связь: `dashed=1;endArrow=open;endFill=0;`
  - Наследование (UML): `endArrow=block;endFill=0;`
  - Композиция: `endArrow=diamondThin;endFill=1;`
  - Агрегация: `endArrow=diamondThin;endFill=0;`

## 5. Пресеты типов диаграмм

### Архитектурные схемы (Service & Cloud Architecture)
- Потоки ориентируются сверху вниз (TB) либо слева направо (LR).
- Уровни группируются в контейнеры (`swimlane`): Clients, Gateway, Services, Storage / Queues.
- Внешние зависимости выделяются пунктирным контуром (`dashed=1;strokeColor=#999999;`).
- Очереди и шины сообщений размещаются по центру как связующие хабы.

### Диаграммы "Сущность - Связь" (ERD)
- Таблица: `shape=table;startSize=30;container=1;collapsible=1;childLayout=tableLayout;fixedRows=1;rowLines=0;fontStyle=1;`
- Строка колонки: `shape=tableRow;horizontal=0;startSize=0;fillColor=none;collapsible=0;portConstraint=eastwest;fontSize=11;`
- Связи между внешними ключами: `dashed=1;endArrow=ERmandOne;startArrow=ERmandOne;`
- Первичные ключи выделяются жирным шрифтом и префиксом `PK`.

### Диаграммы последовательности (Sequence)
- Участники (Lifelines): `shape=umlLifeline;perimeter=lifelinePerimeter;container=1;collapsible=0;`
- Время идет строго сверху вниз.
- Шаг между вертикальными линиями: 180-220px.
- Синхронные сообщения: прямая линия со сплошной стрелкой.
- Ответные сообщения: пунктирная линия с открытой стрелкой и приглушенным цветом (`strokeColor=#888888;`).

### Модель C4 (Context / Container / Component)
- Person: `shape=mxgraph.c4.person2;fontColor=#ffffff;fillColor=#083F75;strokeColor=#06315C;`
- Software System / Container: `rounded=1;arcSize=10;fontColor=#ffffff;fillColor=#1061B0;strokeColor=#0D5091;`
- Внешняя система: `rounded=1;arcSize=10;fontColor=#ffffff;fillColor=#8C8496;strokeColor=#736782;`
- Подпись в три строки: `Имя` &#xa; `[Тип: Технология]` &#xa; `Краткое назначение`.

## 6. Правила компоновки и геометрии

1. **Лимит ручной расстановки:** вручную рассчитывать координаты допустимо для графов объемом до 15 узлов. При большем объеме применяется табличный расчет по уровням (уровневая раскладка) либо внешние алгоритмы разметки.
2. **Шаг сетки:** все координаты `x`, `y`, `width`, `height` кратны 10 или 20 пикселям.
3. **Отступы:**
   - Между параллельными блоками одного уровня: не менее 40px.
   - Между слоями архитектуры: не менее 100-140px.
   - Внутренние отступы в контейнерах: не менее 30px от краев.
4. **Габариты блоков:** стандартные сервисные блоки имеют ширину 140-180px и высоту 60-70px. Размер шрифта подбирается так, чтобы надписи не выходили за границы блока.

## 7. Процесс генерации, валидации и исправления

Каждый агент выполняет работу по строгому циклу из 4 шагов:

### Шаг 1. Формирование XML
- Составление списка вершин и связей.
- Назначение уникальных идентификаторов и вычисление координат.
- Запись файла `<name>.drawio`.

### Шаг 2. Структурная валидация
Перед рендерингом выполняется проверка:
- Присутствуют ли ячейки `id="0"` и `id="1"`.
- Все ли ссылки `source` и `target` указывают на существующие `id`.
- Содержит ли каждый edge элемент `<mxGeometry relative="1" as="geometry" />`.
- Экранированы ли символы `<`, `>`, `&`, `"`.
- Нет ли конструкций `--` внутри комментариев.

### Шаг 3. Черновой рендер и визуальная проверка
Диаграмма экспортируется в черновой растр высокого разрешения:
```bash
drawio -x -f png --width 2000 -o draft.png model.drawio
```
*(Флаг `-e` здесь не используется, чтобы не раздувать черновик встроенным XML).*

Агент проверяет:
- Не накладываются ли стрелки на углы блоков.
- Читаются ли подписи связей.
- Нет ли пересекающихся параллельных линий.
- Не обрезаны ли метки контейнеров.

При обнаружении дефектов агент корректирует координаты или добавляет путевые точки (не более 2 итераций правок).

### Шаг 4. Финальный экспорт
После утверждения черновика создаются чистовые файлы:

```bash
# Редактируемый PNG со встроенным XML
drawio -x -f png -e -s 2 -o model.drawio.png model.drawio

# Векторный SVG со встроенным XML
drawio -x -f svg -e --embed-svg-images -o model.svg model.drawio

# Документ PDF
drawio -x -f pdf -e -o model.pdf model.drawio
```

**Запрет:** никогда не объединять флаги `--width` и `-s` в одной команде CLI drawio.

## 8. Инкрементальная синхронизация (Diagram IR)

Если диаграмма создается на основе кода или конфигураций (Terraform, Docker, K8s, OpenAPI):
1. **Сохранение ручной компоновки.** При обновлении схемы нельзя сбрасывать координаты вручную расставленных блоков.
2. **Обработка удалений.** Удаленные из кода компоненты не стираются мгновенно: их стиль переводится в приглушенный (`opacity=40;dashed=1;`) для визуальной сверки пользователем.
3. **Добавление нового.** Новые сущности размещаются ниже основного рабочего холста либо в специально отведенной секции расширения, после чего связываются с существующими узлами.
