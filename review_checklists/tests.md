# Чек-лист: Тестирование (AAA, изоляция, эталонные расчеты)

> Этот документ определяет правила проверки тестового покрытия (Google Test / pytest). Нарушения помечаются как замечания к качеству кода.

---

## 1. Обязательные требования

1. **Запрет оборачивания тестов в `namespace` (C++):**
   - Макросы `TEST(...)` и фикстуры `TEST_F(...)` никогда не помещаются внутрь пространства имен:
     ```cpp
     // ПРАВИЛЬНО:
     TEST(Converters, ReturnsCorrectM3SFromLMin) {
         // ...
     }
     ```

2. **Обязательная структура AAA (Arrange, Act, Assert):**
   - Каждый тестовый метод разделяется на три четкие секции однострочными комментариями:
     * `// Arrange: ...` / `# Arrange: ...` — подготовка входных данных;
     * `// Act: ...` / `# Act: ...` — единичный вызов тестируемого метода;
     * `// Assert: ...` / `# Assert: ...` — проверка условий и инвариантов.
   - Запрещено объединять Act и Assert в одну нечитаемую строчку.

3. **Вынос повторяющихся наборов тестовых данных (DRY в тестах):**
   - Если один и тот же сложный объект параметров многократно подготавливается в разных тестах, он выносится в локальную функцию-фабрику или фикстуру тестового файла.
   - Запрещено копировать простыни с десятком одинаковых полей из теста в тест.

4. **Обязательный тест эталонного расчета (Golden Master / Textbook Example):**
   - В наборе тестов обязательно должен присутствовать хотя бы один сквозной тест, проверяющий способность алгоритма выполнить расчет по эталонному числовому примеру из методички / ТЗ.
   - Это гарантирует, что система не просто формально скомпилировалась, но и правильно считает реальную физико-математическую задачу.

5. **Изоляция и явная подготовка:**
   - Тесты не должны неявно зависеть от результатов выполнения соседних тестов или глобального состояния.
   - Все параметры, влияющие на проверяемое поведение, передаются в Arrange явно.
