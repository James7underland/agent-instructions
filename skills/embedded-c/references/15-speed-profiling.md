# 15. Скорость: профилирование и оптимизация тактов

**Сначала измерь, потом оптимизируй.** Ускорять инициализацию, которая идёт один раз, бессмысленно,
если время съедает главный цикл. Каждое улучшение записывай в таблицу, как и для памяти.

## Профилировщики, которые можно сделать самому
1. **Ножки GPIO + осциллограф или логический анализатор:** ставишь 1 на входе в функцию, 0 на выходе.
   Работает и в ISR, почти не мешает. Видно, кто съедает время и сколько остаётся запаса
   (например, «ожидание данных» сжимается до нуля — скоро начнём терять отсчёты).
2. **Таймер функции:** `t0 = now(); f(); sum += now() - t0; count++;`. Функция должна длиться дольше тика
   (лучше ×10), усреднение по многим запускам повышает точность. Проверь накладные расходы, закомментировав `f()`.
3. **Таймер отклика:** время на N итераций всего цикла.
4. **Сэмплирующий профилировщик:** таймер с «некратной» частотой (например, 1,7 Гц) сохраняет адрес возврата
   прерванного кода в RAM-буфер. Потом скрипт по map-файлу считает долю времени каждой функции.

## Приёмы
- Включи оптимизацию компилятора. Дальше помоги ему держать переменные в регистрах (см. `14`).
- **Ожидания памяти (wait states):** код из flash может быть медленнее RAM. Критичные функции переноси в RAM
  (`ramfunc`, секция в линкере).
- **Родной размер переменных:** на 32-битном МК `uint8_t` локальные переменные могут быть **медленнее**
  `uint32_t` (расширение знака и нуля). Меньше преобразований типов, не смешивай знаковые и беззнаковые.
- **Цепочки вызовов:** в горячем цикле убирай лишние уровни (выбор CS на каждый байт → один раз на блок).
  Это ломает модульность, поэтому оставь комментарии-перекрёстные ссылки. Альтернатива — `static inline`.
- **Меньше вычислений в цикле:** вынеси инварианты, обходи массив указателем, убери `if` из тела.
  Счётчик цикла вниз до 0 (сравнение с нулём дешевле).
- **Развёртка цикла** (loop unrolling): меньше проверок, больше кода. Только в горячих местах.
- **Таблицы поиска** (lookup tables): такты в обмен на flash или RAM (разворот битов байта — таблица из 256
  байт). `switch` компилятор тоже может превратить в таблицу, проверь ассемблер.
- **Ассемблер** — крайняя мера. Начинай с того, что сгенерировал компилятор, а не с чистого листа,
  и оставляй C-код в комментариях.

## Экономика оптимизации
Ресурсы (RAM, flash, такты, энергия) частично взаимозаменяемы, валюта — время разработчика.
Первые 10 % даются легко, следующие 10 % — вдвое дороже. Ставь цель и останавливайся. Закладывай
запас ресурсов с самого начала: в конце проекта нужны резервы на исправления.

## ESP8266
- 80 МГц по умолчанию, 160 МГц: `board_build.f_cpu = 160000000L` (больше потребление).
- Код выполняется из flash через кэш. Промах кэша стоит дорого, горячие функции можно пометить `IRAM_ATTR`
  (IRAM ограничена ≈ 32 КБ).
- `ESP.getCycleCount()` — счётчик тактов CPU для точного профилирования коротких участков.
- `digitalWrite` медленнее прямой записи в `GPOS/GPOC`, но для профилирования ножкой его обычно хватает.
- Float и double считаются программно: деление и `sqrt` стоят сотни–тысячи тактов (см. `16`).
