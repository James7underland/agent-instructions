# 14. Память: RAM, стек, куча, размер кода

## Карта памяти программы
| Секция | Где | Что |
|---|---|---|
| `.text` | flash | код и константы (`.rodata`: строки, `const`-таблицы) |
| `.data` | RAM + копия во flash | глобальные и `static` **с** инициализатором (стоят и RAM, и flash) |
| `.bss` | RAM | глобальные и `static` **без** инициализатора (обнуляются при старте) |
| куча (heap) | RAM | `malloc`, растёт вверх |
| стек (stack) | RAM | локальные переменные, параметры, адреса возврата, контексты ISR; растёт вниз |

Стек и куча растут навстречу. Их встреча, а раньше — наезд стека на глобальные данные, дают «случайные»
сбои. Размеры задаёт скрипт линкера (`.ld`).

## Map-файл — главный инструмент
Включи его генерацию (`-Wl,-Map=out.map`). В нём есть:
- какие библиотеки подтянуты и **из-за какого вызова** (`memcpy` из `aes.o`);
- список глобальных символов с размерами: много публичных глобальных — плохой признак;
- размеры `.text`, `.data`, `.bss`, каждой функции и константы;
- неожиданно большие вещи: `printf` с плавающей точкой, `__aeabi_ldivmod` (64-битное деление),
  библиотека float.

**Правило:** ведите таблицу «изменение → text/data/bss → сэкономлено», сравнивай map до и после (diff).

## Отказ от malloc (правило для МК)
Причины:
1. **Невидимость:** куча не видна в map, объём RAM нельзя посчитать заранее.
2. **Фрагментация:** куча 30 байт — выделили 10 и 5, освободили 10, просим 20 → `NULL`, хотя свободно 25.
3. **Накладные расходы** на каждый блок (заголовок) и время поиска.
4. **Недетерминированность:** одна и та же функция ведёт себя по-разному в зависимости от истории.
5. Ошибка нехватки проявляется через часы или дни работы.

Замены: статические буферы, **кольцевой буфер** для очередей, **ping-pong** для пар буферов, **пул блоков
одного размера** (chunk allocator). Выделение один раз при старте допустимо (и надёжнее всего,
если это `static`). Если в итоге пишешь свой `malloc` — возьми библиотечный.

## Стек
- Локальные массивы и длинные цепочки вызовов раздувают стек. Большие буферы — `static` или глобальные.
- **Рекурсия** на МК почти запрещена: глубина не контролируется.
- **Измерение:** при старте заполни стек шаблоном (0xDEADC0DE или 0xA5), погоняй систему во всех режимах,
  найди границу нетронутого шаблона (high-water mark). Стек = максимум + ≈ 25 %. У каждой задачи RTOS
  свой стек.
- Структуры передавай указателем (`const T *`), а не по значению: копия уходит на стек.

## Регистры и локальные переменные
- Параметров не больше ≈ 4, тогда они идут в регистрах. Тип — «родной» для процессора
  (32 бита на ESP8266): узкие типы добавляют инструкции расширения.
- **Узкая область жизни** переменной освобождает регистр. Не храни счётчик цикла «на потом».
- Хвостовой вызов в конце функции позволяет компилятору не наращивать стек.
- Глобальная переменная всегда занимает RAM, но иногда экономит стек: данные не копируются через
  всю цепочку вызовов.
- Смотри ассемблер (`.lst`, `objdump -d`, godbolt.org), сначала без оптимизации.

## Оверлеи RAM
Большие буферы, которые никогда не нужны одновременно (кадр дисплея, буфер обновления прошивки, буфер записи
датчика), могут разделять одну память: `union` с меткой владельца, доступ через функцию или
секция в скрипте линкера. Экономия большая, но модули связаны неочевидно. Документируй в обоих модулях.

## Размер кода
1. Сначала `-Os`.
2. Самые большие потребители в map — обычно библиотеки: float, `printf`/`scanf`, `iostream`, 64-битное
   деление. Замены: fixed-point вместо float; `log_msg_num()` вместо `printf`; своя `abs` без math-библиотеки.
3. Отладочные строки убирай на этапе компиляции макросами уровня лога по подсистемам. Крайний вариант —
   заменить строки номерами и расшифровывать их скриптом на ПК.
4. Макрос против функции: макрос копирует код в каждое место вызова, функция добавляет вызов.
   На 2–3 вызовах функция уже меньше. Макрос не занимает стек и быстрее. Для RAM и скорости выгоднее
   `static inline`, для размера — функция.
5. Константы: можно ли вычислить при старте, сжать или вынести во внешнюю flash?

## ESP8266
- RAM данных ≈ 80 КБ, после Wi-Fi-стека свободно ≈ 40–50 КБ. IRAM (код ISR) ≈ 32 КБ.
  Стек `loop()` ≈ 4 КБ (`CONT stack`): большой локальный массив в `loop()` вызовет сбой.
- `ESP.getFreeHeap()`, `ESP.getMaxFreeBlockSize()`, `ESP.getHeapFragmentation()` печатай в логе.
  Падение `MaxFreeBlockSize` говорит о фрагментации.
- Класс `String` и `std::string` фрагментируют кучу: для долгоживущих систем используй `char[]`
  с `snprintf`, в крайнем случае `reserve()`.
- Строковые литералы в `Serial.print("...")` занимают RAM, пока не обёрнуты в `F("...")`
  (тогда лежат во flash). Для `const`-таблиц во flash — `PROGMEM` и `pgm_read_byte/word/dword()`.
- Размер: `pio run -v` печатает RAM/Flash, map-файл даёт `-Wl,-Map` в `build_flags`.
