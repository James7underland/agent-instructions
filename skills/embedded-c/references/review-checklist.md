# Чек-лист ревью прошивки

Отмечай каждый пункт: ✅ выполнено / ❌ нарушено (указать строку) / — неприменимо.
Базовые проверки языка C (UB, преобразования, строки) — в чек-листе скилла `c-core`, здесь они не повторяются.

## 1. Сборка
- [ ] Собирается без предупреждений: `-Wall -Wextra` (+ `-Wconversion`, `-Wshadow` по возможности). Предупреждения кода производителя учтены отдельно.
- [ ] Флаги предупреждений реально доходят до **всех** своих файлов, включая библиотеки (PlatformIO: `lib/*/library.json`). Проверено подробной сборкой (`-v`).
- [ ] Код, который зависит от платформы (`port.h`, ISR-атрибуты), собран под целевую платформу, а не только на ПК. Имена макросов не пересекаются с SDK.
- [ ] Версия прошивки определена в одном месте и печатается при старте или по команде.
- [ ] Нет мёртвого и закомментированного кода (история — в VCS).
- [ ] Конфигурация платы (пины, частоты) — в одном заголовке. Неподдерживаемая конфигурация → `#error`.

## 2. Архитектура
- [ ] Логика не обращается к регистрам напрямую, только через драйверы и HAL.
- [ ] У каждого модуля свой `.h` с узким API. Внутреннее — `static`.
- [ ] Нет публичных глобальных переменных без необходимости. Общие ресурсы (шина, flash) имеют владельца и арбитраж.
- [ ] У каждого модуля есть `init()`, и он инициализирует свои пины и ресурсы.
- [ ] Логика тестируется на ПК: время и железо передаются параметрами или интерфейсами.

## 3. Прерывания (по `isr-rules.md`)
- [ ] ISR короткие: без ожиданий, печати, `malloc`, float на МК без FPU.
- [ ] Каждый ISR подтверждает (сбрасывает) своё прерывание и проверяет все причины.
- [ ] Все общие с ISR переменные — `volatile`. У каждой — один писатель.
- [ ] Составные операции над общими данными (`x++`, чтение-сброс, пары значений, переменные шире разрядности) — в критической секции.
- [ ] Критические секции короткие и **сохраняют и восстанавливают** предыдущее состояние (нет вложенного «преждевременного» разрешения).
- [ ] Из ISR вызываются только реентерабельные функции.
- [ ] ESP8266: `IRAM_ATTR` у ISR и у всего, что они вызывают. GPIO16 не используется для прерываний.

## 4. Время и планирование
- [ ] Нет блокирующих `delay` и ожиданий в главном цикле (кроме init). Ожидания — через состояние и таймер.
- [ ] Сравнение времени — `now - start >= period` на беззнаковых типах одной ширины (устойчиво к переполнению).
- [ ] Каждое ожидание события или периферии имеет **таймаут** и обработку его истечения.
- [ ] Периодические задачи не накапливают дрейф (`next += period`), или дрейф допустим.
- [ ] ESP8266: `loop()` возвращается быстро, долгий код вызывает `yield()`, нет длинных `while` без `yield`.

## 5. Автоматы
- [ ] Есть диаграмма или таблица. Для каждой пары состояние × событие определено поведение.
- [ ] `default:` переводит в безопасное состояние. Недопустимые события логируются или игнорируются осознанно.
- [ ] У состояний ожидания есть таймауты (сломанный датчик не вешает автомат навсегда).
- [ ] Начальное состояние при старте учтено: события парные (нет RELEASE/CLICK/LONG без PRESS, если кнопку держали при включении). Тест проверяет всю последовательность, а не только начало.

## 6. Память
- [ ] Нет `malloc/new/String` после инициализации (или это обосновано и контролируется).
- [ ] Нет больших локальных массивов и рекурсии. Стек оценён (high-water mark), запас ≥ 25 %.
- [ ] Буферы имеют явный размер, и все записи проверяют границы.
- [ ] Кольцевые буферы: размер — степень двойки (если используется маска), индексы атомарны, есть политика переполнения и счётчик потерь.
- [ ] Большие константы — `const` (во flash). ESP8266: `F()`/`PROGMEM` с `pgm_read_*`.
- [ ] Нет приведения байтового буфера к `uint32_t *` (выравнивание, aliasing). Многобайтовые поля собираются сдвигами.

## 7. Регистры и периферия
- [ ] Регистры доступны через `volatile`-указатели или заголовок производителя, без «магических адресов».
- [ ] Используются регистры SET/CLR, где они есть. RMW общих регистров защищён.
- [ ] Флаги W1C сбрасываются записью `=`, а не `|=`. Регистры clear-on-read не читаются «для лога».
- [ ] Начальный уровень выходов задан до включения выхода. Входы не висят в воздухе (есть подтяжки).
- [ ] Ножки, которые влияют на загрузку (ESP8266: GPIO0/2/15), используются с учётом ограничений.

## 8. Ошибки и надёжность
- [ ] Единые коды ошибок. Возвращаемые значения проверяются (или явно `(void)`).
- [ ] Для каждой подсистемы решено: деградация или остановка. Отказ безопасный.
- [ ] Watchdog включён в продукте, кормится **в одном месте** главного цикла, **не** в ISR таймера и не в `delay`.
- [ ] Причина сброса читается при старте и сохраняется или отправляется.
- [ ] Данные извне (UART, сеть, EEPROM) проверяются: длина, диапазон, CRC, версия формата.
- [ ] Энергонезависимые данные: есть версия, CRC, стратегия потери питания во время записи. Запись не в цикле (износ).

## 9. Числа
- [ ] Нет `float/double` в горячих местах на МК без FPU (или это обосновано). Единицы или масштаб задокументированы.
- [ ] Промежуточные произведения — в типе достаточной ширины. Нет знакового переполнения.
- [ ] Деление на ноль исключено. Порядок «сначала умножить, потом разделить» не переполняется.
- [ ] Индексы таблиц проверяются на диапазон.

## 10. Энергопотребление (если батарея)
- [ ] Неиспользуемые блоки и периферия выключены. Ножки в экономичном состоянии.
- [ ] Засыпание без гонки (проверка флагов и сон — атомарно). Частые пробуждения объединены.

## 11. Отладка и сопровождение
- [ ] Логирование отключаемо и не вызывается из ISR. Уровни и подсистемы настраиваются.
- [ ] Есть командный интерфейс или тестовый режим для проверки железа.
- [ ] Для релиза сохраняются ELF и map (расшифровка аварий).
- [ ] Комментарии объясняют «почему», у публичных функций описаны ограничения (из ISR можно? реентерабельна?).
