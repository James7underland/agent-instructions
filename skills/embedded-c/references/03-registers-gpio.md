# 03. Регистры, volatile, GPIO

## Регистры — это API железа
Регистры отображены в память: запись по адресу настраивает периферию. Имена и адреса берут из заголовка
производителя (CMSIS/SDK), а не пишут голыми числами.
```c
*((int *)0x0070C1) |= (1 << 2);        /* NO: magic address, wrong type, no volatile */

#define GPIO_BASE  0x40010800UL
typedef struct {
    volatile uint32_t MODE;    /* direction/config */
    volatile uint32_t IDR;     /* input data (read-only) */
    volatile uint32_t ODR;     /* output data */
    volatile uint32_t BSRR;    /* bit set/reset: write-only, atomic */
} gpio_regs_t;
#define GPIOA ((gpio_regs_t *)GPIO_BASE)
```
Регистры, сгруппированные в структуру, удобны: одинаковые порты обрабатываются одним кодом.

## volatile
`volatile` сообщает компилятору: значение может измениться вне видимого кода (железо, прерывание,
другой поток) или чтение/запись сами имеют побочный эффект. Поэтому каждое обращение в коде должно
стать реальным обращением к памяти: без кэширования в регистре, без выбрасывания «лишних» чтений и записей.

**Правило:** `volatile` обязателен для
1. регистров периферии (указатели `volatile uint32_t *`);
2. переменных, общих для ISR и основного кода;
3. переменных, которые меняет другая задача ОС, DMA или отладчик и которые читаются в цикле.

**Ловушка:** код «работает» с `-O0` и зависает с `-O2`:
```c
static bool s_flag;                 /* missing volatile */
void timer_isr(void) { s_flag = true; }
void wait(void) { while (!s_flag) { } }   /* compiler may turn this into while(1) */
```
**Ловушка:** `volatile` **не** делает операцию атомарной и **не** упорядочивает обычные (не-volatile)
обращения относительно volatile. `volatile uint32_t cnt; cnt++;` — это всё равно чтение-изменение-запись,
прерывание может вклиниться между шагами. Нужна критическая секция (см. `04-interrupts.md`).

**Ловушка:** `volatile` не заменяет барьеров памяти на многоядерных МК и с кэшем (DMA-буферы на
Cortex-M7). Для одноядерного ESP8266 и простых МК достаточно `volatile` и критических секций.

## Операции над битами регистра
```c
reg |=  BIT_U32(n);          /* set */
reg &= ~BIT_U32(n);          /* clear */
reg ^=  BIT_U32(n);          /* toggle */
if (reg & BIT_U32(n)) { }    /* test: result is 0 or BIT_U32(n), not 1 */
```
Все эти операции, кроме чтения, — **read-modify-write (RMW)**: прочитать → изменить → записать.
Прерывание между чтением и записью, которое меняет тот же регистр, потеряет своё изменение.

**Правило:** если у периферии есть регистры **SET/CLR** (BSRR на STM32, `GPOS`/`GPOC` на ESP8266) —
пиши в них: запись одной единицы атомарна и не трогает другие биты. Иначе — RMW в критической секции.

## Особые виды регистров (читай manual!)
- **SET/CLEAR-пара** управляет скрытым функциональным регистром: нули ничего не делают.
- **Write-only** регистр читать бессмысленно. Храни теневую копию (shadow variable) в RAM,
  меняй её и записывай целиком.
- **Clear-on-read:** чтение статуса сбрасывает флаги. Не читай «просто посмотреть» в отладчике и логе,
  ты сбросишь событие.
- **W1C (write-1-to-clear):** флаг сбрасывается записью 1. `REG |= FLAG` сбросит все флаги,
  пиши `REG = FLAG`.

## GPIO: чек-лист настройки выхода
1. Найти **имя** вывода (порт/номер), а не номер ножки корпуса.
2. Убедиться, что вывод работает как GPIO, а не как альтернативная функция (SPI, UART).
   Мультиплексор — в разделе «I/O configuration» или «Alternate functions».
3. Включить тактирование порта, если так устроен МК.
4. Направление — выход. Начальный уровень задать **до** переключения на выход, чтобы не было «иголки».
5. Проверить по схеме полярность: светодиод часто подключён к питанию, тогда он горит при 0.

Выход не работает? Проверь по порядку: питание, тот ли код залит (напечатай версию), правильная ли ножка
по схеме, не занята ли альтернативной функцией, не выключено ли тактирование, не сбрасывает ли watchdog,
инверсия, другая плата (брак пайки).

## GPIO: вход
- Нужна определённость: внешняя или внутренняя **подтяжка**. Кнопка на землю плюс pull-up
  дают активный низкий уровень: нажата = 0.
- Функция уровня `io_get()` возвращает уровень, а `button_pressed()` скрывает инверсию.
- Подтяжки потребляют ток. В батарейных устройствах лишние отключай, но не оставляй входы висеть.

## Распиновка — в одном заголовке
Все пины собраны в одном файле соответствия (`board.h` / `io_map.h`). Версия платы выбирается при сборке:
```c
/* io_map.h */
#if defined(BOARD_V1)
#  include "io_map_v1.h"
#elif defined(BOARD_V2)
#  include "io_map_v2.h"
#else
#  error "Board version is not selected"
#endif
```
Это единственное исключение из правила «модуль сам знает свои ресурсы»: таблицу пинов удобно видеть целиком
и сверять со схемой (её даже можно генерировать из CSV).

## ESP8266
- В Arduino: `pinMode(pin, OUTPUT | INPUT | INPUT_PULLUP)`, `digitalWrite`, `digitalRead`.
  `INPUT_PULLDOWN_16` есть только у GPIO16.
- Быстрые атомарные записи: `GPOS = 1 << gpio;` (set) и `GPOC = 1 << gpio;` (clear), чтение `GPI`.
  Только для GPIO0..15, у GPIO16 отдельные регистры. Прячь их за своим фасадом.
- Встроенный светодиод D4 = GPIO2 горит при `LOW`.
- Некоторые пины влияют на режим загрузки (GPIO0, GPIO2, GPIO15). Подробно — в
  `esp8266-pio/references/pinout-d1mini.md`.
