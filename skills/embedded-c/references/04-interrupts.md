# 04. Прерывания

## Что происходит при прерывании
1. Возникает **запрос (IRQ)**: внешняя ножка, периферия (таймер, UART, АЦП), программа или сбой.
2. Процессор **сохраняет контекст** (счётчик команд, часть регистров) на стек.
3. По номеру прерывания находит обработчик в **таблице векторов** (массив указателей на функции,
   его заполняет startup-код). Первые элементы таблицы — начальный указатель стека и вектор сброса.
4. Выполняется **ISR** (обработчик).
5. Специальная инструкция возврата из прерывания **восстанавливает контекст**, и основной код продолжается
   с того же места.

Прерывания-«задачи» (периферия) возвращаются в основной код. Прерывания-«исключения» (hard fault, деление
на 0, недопустимая инструкция, провал питания) обычно заканчиваются сбросом.

- **NMI** (немаскируемое) нельзя запретить. Оно срабатывает даже в критической секции.
- **Приоритеты:** при одновременных запросах первым обслуживается более важный.
- **Вложенные прерывания** (прерывание прерывания) — источник сложности. Не используй их без явной нужды.
- **Необработанное прерывание:** в отладке — вечный цикл, чтобы заметить. В продукте — возврат,
  лог и счётчик, чтобы не зависать у пользователя.

## Латентность
- **Латентность прерывания** — такты от IRQ до первой инструкции ISR (сохранение контекста).
- **Латентность системы** — худшее время от события до начала ISR. Это латентность прерывания **плюс самое
  долгое время, когда прерывания запрещены** (длинные ISR, критические секции).
- Пример расчёта: 30 МГц, звук 44,1 кГц, 10 тактов входа, 5 вызовов функций по 10 тактов и 275 тактов
  работы — 335 тактов (11 мкс) на каждое прерывание, а это почти 50 % процессора.

**Правило:** ISR короткий. Никаких вызовов «глубоких» функций, никакой печати, никаких ожиданий.

## Настройка прерывания (общий порядок)
1. **Запретить** это прерывание (даже если после сброса оно и так выключено).
2. Настроить периферию: условие срабатывания (фронт/уровень), режим.
3. Сбросить возможно висящий флаг.
4. Зарегистрировать обработчик (по имени функции через линкер или записью в таблицу).
5. Разрешить прерывание в периферии **и** в контроллере прерываний (NVIC). Это два разных места manual.

Обычно ISR должен **подтвердить (сбросить)** прерывание, записав или прочитав статус. Если не сбросить,
прерывание сразу сработает снова и повесит систему. Один вектор часто обслуживает несколько причин
(весь банк GPIO, все события SPI). Проверяй **все** биты причины, а не только первый.

## Реентерабельность
Функция **реентерабельна**, если её можно безопасно вызвать повторно, пока предыдущий вызов не закончился
(его прервали). Нереентерабельны функции, которые используют `static` или глобальные данные без защиты:
`malloc`, `printf` и весь stdio, `strtok`, большинство драйверов.

**Правило:** из ISR вызывай только реентерабельный код или код, который из основного цикла никогда
не вызывается одновременно.

## Общие данные и гонки
Если ISR и основной код обращаются к одной переменной, возникает **гонка (race condition)**: результат
зависит от момента прерывания.
```c
/* main loop: read-and-clear a flag set by ISR */
if (g_button_flag) {        /* ISR may fire right here and set flag again */
    g_button_flag = false;  /* ...and this line loses that second press   */
    handle_press();
}
```
Решения:
- ISR только **устанавливает**, основной код только **сбрасывает**, и это одно атомарное действие. Лучше
  ISR **увеличивает счётчик** (единственный писатель), а основной код сравнивает с последним прочитанным.
- Составное чтение или изменение — **в критической секции** (с запретом прерываний).
- Поток данных — **кольцевой буфер** с одним писателем и одним читателем (см. `11-circular-buffer.md`).

**Атомарность:** одно чтение или запись переменной разрядности процессора, выровненной по границе, обычно
атомарны: 8 бит на AVR, 32 бита на ESP8266 и Cortex-M. `uint16_t` на 8-битном МК, `uint64_t` на 32-битном,
`x++`, `x |= m`, пара «флаг + значение» — **не** атомарны.

## Критическая секция
Запрещай прерывания на минимальное время, только вокруг обращения к общим данным. Безопаснее
запрещать **все** прерывания, а не одно: частичный запрет ведёт к инверсии приоритетов (см. `06`).

**Ловушка — вложенные секции:**
```c
void helper(void)  { irq_disable(); /* ... */ irq_enable(); }
void critical(void){ irq_disable(); helper(); /* now UNPROTECTED */ irq_enable(); }
```
**Правило:** сохраняй и восстанавливай предыдущее состояние:
```c
irq_state_t st = irq_save_disable();   /* returns previous interrupt mask */
/* ... short critical code ... */
irq_restore(st);                        /* re-enables only if it was enabled */
```
Функции, которые запрещают прерывания, называй так, чтобы это было видно.

## Когда прерывание нужно, а когда нет
**Нужно:** жёсткий реальный срок, редкое событие, которое дорого опрашивать, короткая фоновая
работа с буфером (UART, SPI), выход из сна.
**Не нужно:** всё остальное. Прерывания делают систему недетерминированной, трудной для отладки
(гонки) и непереносимой. Альтернатива — **опрос** (обязательно с таймаутом) в главном цикле и
**системный тик** (см. `05`).

## ESP8266 (Arduino core)
- Обработчик GPIO: `attachInterrupt(digitalPinToInterrupt(pin), isr, FALLING /*RISING, CHANGE*/);`.
  GPIO16 (D0) прерываний не поддерживает.
- ISR **обязан** быть в IRAM: `void IRAM_ATTR on_button(void) { ... }`. Иначе при обращении ко flash
  (кэш выключен) будет сбой. Начиная с core 2.5 ядро прямо падает с сообщением «ISR not in IRAM!».
  Всё, что вызывается из ISR, тоже должно быть в IRAM.
- В ISR нельзя `delay()`, `Serial.print`, `yield()`, `new/malloc`, `String`, долгие циклы.
- Критическая секция: `noInterrupts(); ... interrupts();`. Для вложенного случая — сохранение уровня:
  `uint32_t ps = xt_rsil(15); ... xt_wsr_ps(ps);`. В ядре есть и RAII-класс `esp8266::InterruptLock`
  (`#include <interrupts.h>`) для C++.
- Wi-Fi-стек тоже работает на прерываниях. Длинные критические секции (десятки мкс и больше) ломают связь
  и тайминги `millis()`.
- 32-битные выровненные чтения и записи атомарны (одноядерный Xtensa LX106), `uint64_t` — нет.
