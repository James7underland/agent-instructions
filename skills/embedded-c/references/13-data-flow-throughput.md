# 13. Поток данных: data-driven системы, конвейер, расчёт пропускной способности

## Событийные и потоковые системы
- **Событийная** (event-driven): реагирует на события — автоматы и флаги (см. `06`, `07`).
- **Потоковая** (data-driven): непрерывно получает данные, обрабатывает, выдаёт (регистратор, аудио,
  датчик выстрела, телеметрия). Главные характеристики — скорость поступления и время обработки.
  Обработка должна быть **чуть быстрее** поступления.

Большинство систем сочетают оба вида. Раздели их и реализуй отдельно.
Для потока реши заранее, **как отставать**: пропускать данные и догонять, упрощать обработку или копить.

## Паттерны
- **Стратегия (strategy):** алгоритм обработки — указатель на функцию с фиксированной сигнатурой,
  меняется по команде без `switch` в горячем цикле. Даже если на лету менять не нужно, это удобно при
  разработке: сравнивать алгоритмы.
- **Шаблонный метод (template):** каркас «sample → process → output» фиксирован, шаги подменяются.
  В тестах `sample` читает из файла.
- **Конвейер и фильтры (pipeline):** цепочка стадий, выход одной — вход следующей (шумоподавление → ФНЧ
  → выбор каналов → запись → прореживание → график). Каждая буферизующая стадия добавляет
  **задержку данных**, и задержки складываются. Стадии, которые работают с окнами (min/max за интервал),
  отличаются от потоковых, окна часто перекрывают. Каждую стадию можно тестировать отдельно.

## Расчёт «speeds and feeds» (таблица обязательна)
Для каждого источника: частота отсчётов × каналы × размер отсчёта = байт/с.
```
АЦП 4 канала × 16 бит × 44,1 кГц = 352 800 Б/с  → SPI не ниже 2,8 МГц (+ запас, + другие устройства на шине)
запись события 4 с                  = 1,3 МБ      → влезет ли в RAM? нужна внешняя RAM или flash?
```
Для каждой шины просуммируй всех пользователей (номинал и худший случай). Для каждой стадии определи
нужный буфер. Для памяти учти объём (Мбит ≠ МБ!), время чтения, записи и стирания, ресурс.
Общая память (flash для ресурсов, журнала и KV) — общий ресурс: стирание KV может задержать запись
журнала, и возникает инверсия приоритетов.

## ESP8266
- Свободной RAM ≈ 40–50 КБ при работающем Wi-Fi: большие буферы звука или изображений не помещаются.
- `Serial` 115200 ≈ 11,5 КБ/с, Wi-Fi TCP — сотни КБ/с, но с непредсказуемыми паузами. Буферизуй.
- АЦП A0 один, 10 бит, медленный (порядка единиц–десятков тысяч отсчётов в секунду). Частое
  `analogRead()` мешает Wi-Fi, для быстрых измерений нужен внешний АЦП.
