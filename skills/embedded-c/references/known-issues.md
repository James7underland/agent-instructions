# Известные ловушки и найденные ошибки (embedded-c)

Пополняется после каждой задачи: симптом → причина → как правильно.

## Из книги (переложено на C99)
- Функция `TimePassed()` в гл. 5 обрабатывает переполнение отдельной веткой. Для беззнаковых счётчиков
  это не нужно: `now - since` уже даёт верный интервал. Ветка `now + (1 + MAX - since)` при
  `tTime = uint32_t` может сама переполниться в промежуточном выражении.
- Кольцевой буфер в гл. 7 считает длину как `(write - read) & (size - 1)` на `uint16_t`, операнды продвигаются
  в `int`. Результат верен только при дополнительном коде. Надёжнее индексы, которые растут без ограничений,
  в `uint32_t` и беззнаковое вычитание (`examples/ring_buffer.c`).
- «Фальшивая плавающая точка» из гл. 12 сдвигает знаковые числа (`tmp >> 1` для отрицательных — зависит
  от реализации, `<<` отрицательных — UB). В `examples/fixed_point.c` масштабирование сделано умножением и
  делением в `int64_t`.
- Пример `GetVariance` в гл. 12 умножает `int16_t * int16_t` и складывает в `uint64_t`: произведение считается
  в `int`, и для отрицательных отсчётов сумма квадратов ломается при смешении знаковых и беззнаковых. Приводи к
  `int64_t` до умножения.

## Проверено при создании примеров
- Обычная (не-volatile) запись данных в ячейку буфера может быть переставлена компилятором **после**
  volatile-записи индекса. Нужен `volatile` у массива или барьер компилятора (`PORT_COMPILER_BARRIER()` в `port.h`).
- Демонстрации со временем проверяй **с переходом через 2³²**: в первом варианте демо автомата стартовое время
  было слишком далеко от переполнения, и тест не проверял то, что обещал.
- Имя `pid_t` для PID-регулятора конфликтует с POSIX. Используй `pid_ctrl_t`.

## ESP8266 (перенесено в esp8266-pio/references/known-issues.md, продублировано кратко)
- ISR без `IRAM_ATTR` → падение при работе с flash («ISR not in IRAM!» в core ≥ 2.5).
- Долгий `loop()` без `yield()` → «Soft WDT reset» (≈ 3 с) или `rst cause: 4` (hardware WDT, ≈ 8 с).

## Найдено на пробной задаче (драйвер кнопки для D1 mini, 2026-09-27)
- **Нарушение парности событий при старте.** Кнопка, нажатая уже во время `init`: драйвер не выдавал
  PRESS (правильно), но через `long_ms` выдавал LONG, а при отпускании — RELEASE и CLICK, хотя в заголовке
  обещано «RELEASE всегда после PRESS». Первый тест держал кнопку только 200 мс и отпускание не проверял.
  **Правило:** события должны быть парными (флаг `press_seen`). Тест «зажато при старте» проверяет всё
  продолжение: удержание дольше `long_ms`, отпускание, следующее нажатие.
- **Порядок инициализации выхода:** сначала записать уровень, потом включить выход (см. esp8266-pio/known-issues).
- **`port.h` для ESP8266 сначала не собирался из .c-файлов:** не хватало `#include <c_types.h>` и
  `<core_esp8266_features.h>`. Код для реальной платформы проверяй сборкой под неё (`-DPORT_ESP8266`), а не
  только на ПК.
- **Время по тику, а не число отсчётов:** антидребезг по времени (`now - since >= debounce_ms`) не зависит от
  частоты вызова `poll`. Тест с опросом раз в 50 мс это подтверждает.
