# 05. Таймеры, ШИМ, системный тик

## Устройство аппаратного таймера
Счётчик, который считает тактовые импульсы независимо от программы. Регистры (названия зависят от МК):
- **counter** — текущее значение;
- **prescaler** — делитель входной частоты. Часто хранится как «делитель минус 1», проверь в manual;
- **compare/match** (их может быть несколько) — при совпадении выполняется действие;
- **action/auto-reload** — действие при совпадении: прерывание, остановка, перезагрузка счётчика,
  изменение ножки (установить, сбросить, переключить);
- **clock select**, **control** (старт/сброс), **interrupt enable/status**.

Источник тактов может быть неточным (внутренний RC-генератор дрейфует). Для точного времени нужен
кварц или подстройка по точному источнику (см. `17-power.md`).

## Расчёт
`f_irq = f_clk / (prescaler × compare)`, отсюда `prescaler × compare = f_clk / f_irq`.
1. Если `f_clk / f_irq` — целое, разложи его на множители, которые влезают в регистры
   (4 МГц / 20 Гц = 200 000 = 1000 × 200).
2. Иначе минимальный прескалер равен `f_clk / (compare_max × f_irq)`, округлённый вверх. Проверь погрешность
   `100 × |f_goal − f_real| / f_goal`.
3. Для лучшей точности переберите все допустимые прескалеры скриптом на ПК и возьми пару с минимальной ошибкой.
4. Не влезает — возьми таймер шире (16 или 32 бита) или считай прерывания программно (с потерей точности
   из-за латентности).

Для мигания нужна частота прерываний, **вдвое** большая частоты мигания: включить и выключить.

**Ловушка:** считать `f_clk / (prescaler * compare)` в 16-битном `int`. Пиши `uint32_t` и суффикс `UL`.
Константы задавай через `#define` с понятными именами и комментарием про формулу.

## ШИМ (PWM)
Период задаёт один регистр сравнения (сброс счётчика), скважность (duty cycle) — другой (переключение ножки).
Аппаратный ШИМ не тратит процессор. Программный ШИМ на прерываниях возможен, но при низкой частоте
светодиод мерцает, а при высокой прерываний слишком много. Яркость светодиода определяется средним
значением, для мотора нужен драйвер (см. `20`).

## Системный тик (system tick)
Одно периодическое прерывание (обычно 1 мс) увеличивает счётчик времени. Остальные временные задачи —
в главном цикле через сравнение времени, без отдельных прерываний и без блокировки.
```c
static volatile uint32_t s_ticks_ms;            /* written only by ISR */
void systick_isr(void) { s_ticks_ms++; }

uint32_t time_now_ms(void) { return s_ticks_ms; }   /* 32-bit aligned read: atomic on 32-bit MCU */

/* Unsigned subtraction is correct across rollover. */
uint32_t time_since_ms(uint32_t since) { return time_now_ms() - since; }
```
```c
static uint32_t s_last_blink;
void blink_poll(void)
{
    if (time_since_ms(s_last_blink) >= BLINK_PERIOD_MS) {
        s_last_blink += BLINK_PERIOD_MS;     /* no drift: schedule from previous deadline */
        led_toggle();
    }
}
```

**Ловушки переполнения:**
- 16-битный счётчик миллисекунд переполняется через 65,5 с, 32-битный — через 49,7 суток.
- `if (now >= start + period)` **ломается** при переполнении. Правильно `if (now - start >= period)`:
  беззнаковое вычитание по модулю 2^32 даёт верный интервал, если интервал меньше 2^31.
  Функция из книги с веткой «если now < since» при беззнаковом вычитании не нужна.
- На 8-битном МК 32-битный счётчик читается за несколько инструкций, это не атомарно. Читай его
  в критической секции или читай дважды, пока два значения не совпадут.
- Разные типы (`int` против `uint32_t`) в выражении времени дают знаковое/беззнаковое сравнение с ошибкой.

**Ограда и джиттер (fencepost/jitter):** задержка «на N тиков» начинается в случайный момент
внутри тика. Фактическая задержка — от N−1 до N тиков. Если нужно **не меньше** N мс, жди N+1 тик.
Для задержек порядка 1 мс тик в 1 мс слишком грубый.

## Мини-планировщик на тике
Задача — это структура: функция, время следующего запуска, период, флаг включения. В главном цикле
выполняются все задачи, у которых наступило время. Задачи не вытесняют друг друга и должны
быстро возвращать управление (кооперативная многозадачность). Это паттерн издатель/подписчик: тик
публикует время, задачи подписаны. Если планировщик разрастается, пора подумать о RTOS.
Код — в `06-main-loop-scheduling.md`.

## ESP8266 (Arduino)
- Системный тик уже есть: `millis()` (переполнение через ≈ 49,7 суток) и `micros()` (≈ 71,6 минуты).
  Правило `now - start >= period` обязательно.
- `delay()` в `loop()` блокирует всё, кроме Wi-Fi (внутри вызывается `yield`). Для неблокирующего
  кода — `millis()`.
- Программные таймеры: `Ticker` (callback-функции в системном контексте, короткие, без `delay`) и
  `os_timer`. Аппаратные: `timer1` (`timer1_attachInterrupt`, `timer1_write`, ISR в IRAM) — его же
  использует `analogWrite`/`tone`/Servo. `timer0` занят Wi-Fi, не трогай.
- ШИМ `analogWrite` на ESP8266 **программный** (генератор формы на timer1), по умолчанию 1 кГц.
  Диапазон 0..255 в core 3.x (в 2.x был 0..1023). Меняется через `analogWriteRange()` и `analogWriteFreq()`.
