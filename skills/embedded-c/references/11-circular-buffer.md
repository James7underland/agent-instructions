# 11. Кольцевой буфер (ring / circular buffer)

Очередь FIFO фиксированного размера в статическом массиве. Типичная связка: **производитель** — ISR
(принят байт UART, готов отсчёт АЦП), **потребитель** — главный цикл (разбирает команды, обрабатывает
блоками). Производитель кладёт понемногу, потребитель забирает пачками, или наоборот.

## Главные решения
1. **Как отличить «пусто» от «полно»,** если в обоих случаях `read == write`:
   - одна ячейка остаётся пустой (полно, когда `write + 1 == read`);
   - отдельный счётчик `count`, но тогда его меняют обе стороны, и нужна критическая секция;
   - **индексы, которые растут без ограничений (free-running)**, длина равна `write - read` (беззнаковое
     вычитание), позиция в массиве — `index & (SIZE - 1)`. Все ячейки используются, и у каждого индекса
     один писатель. **Рекомендуемый вариант.**
2. **Размер — степень двойки,** тогда перенос делается маской `& (SIZE-1)`, а не делением `%` (в ISR деление
   дорогое). Проверяй это при компиляции.
3. **Что делать при переполнении:** отбросить новое (вернуть ошибку и посчитать потерю) или затереть
   старое. Реши осознанно.

## Безопасность между ISR и main (один писатель, один читатель)
- `head` (запись) меняет **только** производитель, `tail` (чтение) — **только** потребитель.
- Оба индекса `volatile`, шириной не больше разрядности процессора, чтобы их запись была атомарной.
  На 8-битном AVR `uint16_t` не годится, нужен `uint8_t` и размер ≤ 256. На ESP8266 подходит `uint32_t`.
- **Порядок:** сначала записать данные в ячейку, **потом** сдвинуть `head`. Потребитель: сначала
  прочитать ячейку, потом сдвинуть `tail`. Чтобы компилятор не переставил обычную запись данных
  после volatile-записи индекса, сам массив тоже объявлен `volatile` (или стоит барьер компилятора).
- При таком устройстве блокировки не нужны: ISR видит устаревший `tail` и считает буфер чуть более
  полным, main видит устаревший `head` и считает его чуть более пустым. Оба ошибаются в безопасную сторону.
- Если писателей два (ISR и ещё одна функция main), нужна критическая секция.

```c
#define RB_SIZE 64u                                  /* power of two */
#define RB_MASK (RB_SIZE - 1u)
typedef char rb_size_is_power_of_two[(RB_SIZE & RB_MASK) == 0 ? 1 : -1];  /* C99 static assert */

static volatile uint8_t  s_buf[RB_SIZE];
static volatile uint32_t s_head;    /* written only by producer (ISR) */
static volatile uint32_t s_tail;    /* written only by consumer (main) */

/* Producer (ISR). Returns 0 if full (byte dropped). */
int rb_put(uint8_t b)
{
    uint32_t h = s_head;
    if ((uint32_t)(h - s_tail) >= RB_SIZE) { return 0; }
    s_buf[h & RB_MASK] = b;
    s_head = h + 1u;                 /* publish after data is stored */
    return 1;
}

/* Consumer (main). Returns 0 if empty. */
int rb_get(uint8_t *out)
{
    uint32_t t = s_tail;
    if (s_head == t) { return 0; }
    *out = s_buf[t & RB_MASK];
    s_tail = t + 1u;
    return 1;
}
```
Полная версия с несколькими экземплярами (структура плюс указатель), подсчётом потерь и тестами —
в `examples/ring_buffer.c` и `.h`.

## Когда копировать не хочется
Копирование тратит и такты, и RAM (две копии). Можно добавить третий указатель (`free`): данные читаются и
обрабатываются **на месте**, а ячейка освобождается позже. Можно добавить ещё указатели для стадий
конвейера (АЦП → обработка → ЦАП в одном буфере). Сначала нарисуй схему указателей на бумаге.

## Ловушки
- Размер не степень двойки, но стоит маска: индексы «прыгают», данные портятся.
- `%` в ISR на МК без аппаратного деления — медленно.
- Индексы `uint16_t` на 8-битном МК: неатомарная запись, гонка.
- Проверка «полон» через `count`, который меняют обе стороны без критической секции.
- Буфер без `volatile` при оптимизации: main «не видит» новые данные, или данные записаны уже после индекса.
- Переполнение молча портит данные. Нужен счётчик потерь и реакция на него.

## ESP8266
`Serial` уже содержит кольцевой буфер приёма, заполняемый в прерывании UART. Свой буфер нужен для своих
ISR (кнопки, датчики) и для передачи событий. Функции, которые вызывает ISR (`rb_put`), помечай `IRAM_ATTR`.
