# 16. Математика на МК: быстрые операции, среднее, fixed-point

## Точность против разрядности (accuracy vs precision)
Точность (accuracy) — насколько результат верен. Разрядность (precision) — сколько цифр в нём показано.
Лишние разряды — это шум, который тратит RAM и такты. Сначала определи **диапазон входных данных и допустимую
ошибку**, потом выбирай представление.

## Цена операций (МК без FPU и без аппаратного деления)
сложение, вычитание, сдвиг на константу — 1 такт; умножение — немного дороже (на DSP есть MAC);
**деление и `%`** — библиотечная функция, дорого; **float/double** — программная эмуляция, очень дорого
(плюс ≈ 0,5 КБ кода на одно только сложение float).

Приёмы:
- `i % 10 == 0` → период-степень двойки: `(i & 7) == 0`.
- Деление на 2^k → сдвиг. **Ловушка:** для отрицательных чисел `>>` округляет к −∞, а `/` — к нулю,
  и сдвиг отрицательного числа зависит от реализации. В знаковой арифметике сдвигай осознанно.
- Константы через `#define` или `enum` компилятор подставляет в инструкцию непосредственно.
- **Схема Горнера:** `A x³ + B x² + C x` = `((A x + B) x + C) x` — 3 умножения вместо 6.
- Вынеси общий множитель: `A x + B x + C x` = `(A + B + C) x`.

## Деление на константу через умножение и сдвиг
`x / 6 ≈ (x × 171) >> 10` (ошибка ≈ 0,2 %). Каждый лишний бит сдвига вдвое уменьшает ошибку.
Промежуточный результат — в типе вдвое шире. Способ годится только для **известного** делителя.
```c
/* x / 6 for 0 <= x <= 32767, error < 0.2 % */
static inline int32_t div6_approx(int32_t x) { return (x * 171) >> 10; }
```

## Усреднение
- **Скользящее по N точкам:** `sum += new - oldest`, нужен буфер из N отсчётов. Делить имеет смысл один раз
  (`sum / N`, N — степень двойки → сдвиг), а не делить каждый отсчёт.
- **Блочное:** накопить N, выдать `sum / N`, обнулить. RAM почти не нужна. Хватает, если новое значение
  нужно раз в N отсчётов.
- **Экспоненциальное (IIR):** `avg += (x - avg) >> k`. Буфер не нужен, одна строка. Храни `avg` в увеличенном
  масштабе (`avg_q = avg << k`), иначе при малых изменениях усечение «замораживает» результат.
- **Медиана** 3 или 5 точек — против одиночных выбросов (помехи на АЦП).

**Ловушка усечения:** `avg += (new - old) / N` при близких значениях всегда даёт 0: среднее не меняется.
Правило: большое число делят на много меньшее, а не на сопоставимое. Масштабируй (умножай) заранее,
но следи, чтобы не было переполнения.

## Дисперсия и СКО
`σ` часто не нужна: для оценки разброса хватает **дисперсии** (без корня). Однопроходная формула
`Σx² − (Σx)²/N` требует очень широкого `sumSquares` (для 16-битных отсчётов — 64 бита). Алгоритм **Уэлфорда**
держит промежуточные значения маленькими, но делит на каждом шаге. Выбирай по ресурсам и помни об
усечении. **Правило:** ищи готовый, проверенный алгоритм, его анализ ошибок уже сделан.

## Таблицы поиска и интерполяция
- **Неявный вход** (индекс = вход): шаг — степень двойки, тогда индекс считается сдвигом:
  `idx = (x - X_MIN) >> SHIFT`. Центрируй ступени: к `x` добавь полшага. **Проверяй диапазон** индекса:
  выход за таблицу — UB.
- **Линейная интерполяция** между соседними точками: меньше таблица, больше вычислений. Промежуточное
  произведение — в 32 битах. При шаге-степени двойки деление становится сдвигом.
```c
/* y = y0 + (x - x0) * (y1 - y0) / (x1 - x0), overflow-safe for int16 inputs */
static int16_t lerp_i16(int16_t x0, int16_t y0, int16_t x1, int16_t y1, int16_t x)
{
    int32_t t = (int32_t)(x - x0) * (int32_t)(y1 - y0);
    return (int16_t)(y0 + t / (int32_t)(x1 - x0));
}
```
- **Явный вход** (пары x,y с переменным шагом): точнее там, где кривая изгибается, но нужен поиск
  (двоичный по отсортированной таблице). Типично для калибровки датчиков по температуре.
- **Ряд Тейлора** (для sin и т. п.) плюс Горнер: точность регулируется числом членов, но годится только в своём
  диапазоне.

## Fixed-point (Q-формат)
Число хранится как целое с подразумеваемым масштабом 2^n: `real = raw / 2^n`. Формат **Qm.n** —
m бит целой части (со знаком), n бит дробной. Пример: **Q15.16** в `int32_t` (шаг ≈ 1,5·10⁻⁵,
диапазон ±32768), **Q1.15** в `int16_t` (−1…+1).

| Операция | Как |
|---|---|
| из целого | `a << n` |
| из вещественной константы | `(int32_t)(c * (1 << n) + 0.5)` — при компиляции |
| сложение и вычитание | как у целых, если **одинаковый** n; иначе сначала выровнять сдвигом |
| умножение | `(int32_t)(((int64_t)a * b) >> n)` — произведение в двойной ширине, округление `+ (1 << (n-1))` |
| деление | `(int32_t)(((int64_t)a << n) / b)` |
| в целое | `a >> n` (к −∞) или `(a + (1 << (n-1))) >> n` (округление) |

**Правила:**
1. Для каждой величины задокументируй формат (в имени или комментарии: `temp_q8` — Q23.8).
2. Считай диапазоны: где возможно переполнение, промежуточный результат держи в 64 битах или делай насыщение.
3. Сдвиг вправо отрицательных — зависит от реализации (на GCC арифметический). Для переносимости
   делай беззнаковое или явное деление.
4. Не пиши универсальную «фальшивую плавающую точку» (мантисса + порядок на лету): это заново изобретённый float
   со всеми его затратами. Бери фиксированный формат под задачу или готовую библиотеку (CMSIS-DSP, libfixmath).

**Альтернатива без дробей:** храни в **мелких единицах** — температуру в 0,01 °C (`int16_t`), напряжение в мВ,
время в мкс. Это тоже fixed-point, только масштаб десятичный. Такие числа проще печатать.

## Машинное обучение на МК
Обычно на устройстве только инференс. Обязателен тест: вывод оптимизированной версии против эталона после
каждого переобучения. Классические алгоритмы часто проще, и отлаживать их легче.

## ESP8266
FPU нет: `float` эмулируется (медленно), `double` ещё медленнее, `%f` в `printf` тянет много кода.
Для датчиков используй целые в мелких единицах или Q-формат, вывод — `"%ld.%02ld"`. Пример Q16.16 —
`examples/fixed_point.c`.
