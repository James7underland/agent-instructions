# 17. Энергопотребление

## Физика в одну строку
`P = U × I`, `E = P × t`. Энергию снижают четыре рычага: напряжение (выбор компонентов, ядро 1,8 В), сопротивление
(компоненты), **ток** и **время во включённом состоянии**. Последние два во многом зависят от программы.
Ёмкость батареи задаётся в мА·ч: AA ≈ 3000 мА·ч при 30 мА хватит примерно на 100 часов. При токах,
близких к пределу батареи, правило перестаёт работать, смотри даташит батареи.

## Бюджет (таблица обязательна)
Строки — компоненты, столбцы — режимы устройства (работа, сон, передача по радио...). В ячейках токи
из даташитов, дальше доля времени в каждом режиме, средний ток и срок службы. Токи складываются.
Режимы здесь — это режимы продукта, а не состояния программы.

## Измерение
- Всё лишнее отключено: отладчик, UART от ПК. Одна линия питания и одна земля.
- Мультиметр в режиме тока (правильные гнёзда и предел, иначе сгорит предохранитель) или **шунт + вольтметр**
  (`I = U / R`). Шунт сам «ест» напряжение (burden voltage): для микроампер во сне нужен большой R, а для
  рабочего режима — маленький. Отсюда проблема перепада на порядки. Для сна используй специальные профилировщики
  питания.
- Мультиметр показывает среднее. Короткие пробуждения видны только на осциллографе или профилировщике.

## «Выключай свет, уходя»
- Выключай **внешние устройства** (питание через ключ или удержание в reset). Учитывай время их запуска.
- **Неиспользуемые ножки:** вход с pull-down → выход в 0 → вход с pull-up (в порядке предпочтения).
  Не ставь внутреннюю подтяжку против внешней. **Не подавай 1** на ножки обесточенного чипа: он запитается через
  защитные диоды и может повредиться.
- Отключай тактирование и питание **неиспользуемых блоков МК**.
- **Снижай частоту:** мощность примерно пропорциональна частоте. Но иногда выгоднее быстро сделать работу
  и уснуть («заяц»), чем долго работать медленно («черепаха»).
- Уточняй медленный 32 кГц генератор по точному (кварц или GPS PPS): посчитай, сколько тиков медленного
  укладывается в эталонную секунду. Учитывай температуру.

## Сон
Уровни (названия у каждого МК свои): замедление → idle (ядро спит, периферия работает, будит любое прерывание)
→ deep sleep (часть периферии выключена) → power down (почти всё выключено, будит пин или RTC) → выключение
(старт с нуля). Чем глубже сон, тем дольше просыпаться (латентность).

**Модель «прерывание → флаг → обработка → сон»:** ISR ставит флаг, main обрабатывает все флаги и засыпает,
только если новых нет. **Ловушка:** прерывание, пришедшее между проверкой «флагов нет» и командой сна,
«проспит» до следующего события. Проверку и засыпание делай с запрещёнными прерываниями, если МК это
поддерживает (на Cortex-M WFI будит даже при запрещённых прерываниях):
```c
for (;;) {
    uint32_t ev = events_take();          /* atomic read-and-clear */
    handle_events(ev);
    watchdog_feed();
    irq_disable();
    if (s_events == 0) {
        cpu_sleep_irq_disabled();          /* e.g. __WFI(): wakes on pending IRQ even with PRIMASK set */
    }
    irq_enable();
}
```
- **Не просыпайся часто:** объединяй низкоприоритетные задачи с другими пробуждениями.
- **Модуль управления питанием:** подсистемы регистрируют callback-функцию «можно ли сейчас глубокий сон?»
  (например, идёт передача по UART → нельзя).
- **Watchdog во сне:** либо спит вместе с МК, либо требует периодических пробуждений (см. `08`).
- **Цепочка процессоров:** маленький экономичный МК дежурит и будит большой только по делу.

## ESP8266
Самый прожорливый потребитель — Wi-Fi (≈ 70–80 мА в среднем, пики до 300+ мА). Уровни:
- **Modem sleep** (по умолчанию при подключении): радио засыпает между маяками.
- **Light sleep:** `WiFi.setSleepMode(WIFI_LIGHT_SLEEP)`, CPU приостанавливается при простое.
- **Deep sleep:** `ESP.deepSleep(us)` — ≈ 20 мкА у самого чипа (на плате D1 mini больше из-за LDO и CH340).
  Выход из сна — **через сброс**: GPIO16 (D0) должен быть соединён с RST, программа стартует заново.
  Состояние сохраняй в `ESP.rtcUserMemoryWrite` или во flash. Максимум ≈ 3,5 ч (`ESP.deepSleepMax()`).
- `WiFi.mode(WIFI_OFF)` и `WiFi.forceSleepBegin()`, если сеть не нужна.
- Токи в сотни мА означают, что питание должно выдерживать пики. Просадки дают brownout-сбросы.
