# 02. Работа с железом: даташиты, тесты, командный интерфейс, ошибки

## Как читать даташит (для программиста)
1. Возьми **последнюю** ревизию и **errata** (ошибки в документе и в самом чипе). Ошибки есть почти у всех чипов.
2. Обзор и функциональную схему на первой странице пропусти, пока не знаешь класс устройств.
3. **Описание** (Description) читай целиком, медленно, вслух.
4. Разделы «Application information» / «Theory of operation» — главное для драйвера:
   как инициализировать, как общаться, какие ограничения по времени.
5. **Временные диаграммы** сверяй с кодом, а потом с осциллографом.
6. Раздел Absolute maximum и электрические характеристики понадобятся, если «общается, но работает не так»
   (температура, питание).
7. Для процессора читай **Reference/User manual** своего семейства, а не общий manual ядра ARM.
   Главы по используемой периферии читай целиком, даже если есть пример кода от производителя.

Названия сигналов с чертой сверху, `nNAME`, `NAME#`, `/NAME` — **активный низкий уровень**.

## Схема
Ищи самые «многоногие» блоки (U1 = процессор), разъёмы (J), светодиоды и кнопки, **подтяжки** (pull-up/pull-down).
Вход без подтяжки «висит» (hi-Z), и его значение случайно. Пересечение линий без точки — не соединение.

## Три вида тестов
| Тест | Когда | Особенности |
|---|---|---|
| **POST** (power-on self-test) | каждый старт, и в продакшене | быстрый, неразрушающий; результат доступен и потом (лог/команда) |
| **Юнит-тест** | перед релизом, по команде в поле | может быть долгим или разрушающим; хорошо оставить в прошивке «по секретной комбинации» |
| **Bring-up-тест** | при оживлении платы | временный, самый маленький шаг: «помигать ножкой» |

**Правило оживления:** начинай с самого нижнего уровня и с самого маленького шага (светодиод →
SPI-байт → чтение ID чипа → функция). Каждый компонент должен тестироваться отдельно, запускать тест
может не только автор.

**Шаблон теста памяти (flash/EEPROM):** прочитать исходные данные → записать меняющийся узнаваемый
шаблон (адрес + 0x55) → проверить → вернуть исходные данные → проверить. POST не должен изнашивать
flash: достаточно проверить заголовок (ключ, версия, контрольная сумма).

## Командный интерфейс (command pattern)
Таблица «имя → функция → справка», интерпретатор строк из UART. Тесты и отладочные действия запускаются
без перепрошивки. Таблица легко расширяется, команда `help` печатает её же.
```c
typedef void (*cmd_fn_t)(const char *args);
typedef struct { const char *name; cmd_fn_t fn; const char *help; } cmd_t;

static const cmd_t s_cmds[] = {
    { "ver",   cmd_version, "print firmware version" },
    { "led",   cmd_led,     "led <on|off|blink>" },
    { "help",  cmd_help,    "list commands" },
};
```
Разделение ролей: клиент (таблица), вызывающий (парсер, одинаково обращается со всеми командами),
команда (запись таблицы), получатель (функция, которая делает работу).

## Обработка ошибок
- Для каждой подсистемы реши заранее: **мягкая деградация** (датчик в поле работает как может)
  или **громкий отказ** (медицина). В любом случае отказ должен быть **безопасным**.
- **Единый набор кодов ошибок** на весь проект (`error_codes.h`), 0 — «нет ошибки». Коды общие:
  «неверный параметр», «неверный индекс/NULL», «не инициализировано», «таймаут», «катастрофа».
  Длинные частные коды не нужны.
- Ошибку, которую никто не проверяет, незачем возвращать. Вернул — проверь.
- Цепочка вызовов без вложенных `if`:
```c
err_t err = sensor_power_on();
if (err == ERR_OK) { err = sensor_configure(); }
if (err == ERR_OK) { err = sensor_start(); }
if (err != ERR_OK) { log_msg_num(LOG_SENSOR, LOG_ERROR, "sensor init", err); }
return err;
```
- `ASSERT` на МК свой: запись в лог или RAM, точка останова (`BKPT` при подключённом отладчике),
  светодиод или ножка, потом сброс через watchdog. `printf` в `ASSERT` меняет тайминги.
- **Отладка таймингов:** не печатай, а пиши 1–2-байтовые коды событий в маленький кольцевой буфер в RAM
  и выгружай его после критического участка. Ещё лучше — свободные ножки МК (тестовые точки) и логический анализатор.

## ESP8266
- Даташит ESP8266EX + «ESP8266 Technical Reference» + errata/FAQ Espressif. Схема D1 mini: светодиод
  на GPIO2 (D4) — **инверсная логика**, горит при LOW. Кнопки нет. На A0 делитель, вход 0–3,2 В.
- POST: печатать версию, `ESP.getResetReason()`, `ESP.getFreeHeap()`, `ESP.getChipId()` при старте.
- Командный интерфейс удобно вешать на `Serial` (115200 8N1), см. пример в скилле `esp8266-pio`.
