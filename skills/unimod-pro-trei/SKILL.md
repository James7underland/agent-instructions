# Unimod PRO 2 (ТРЭИ) — работа с проектами

Формат проекта нигде публично не описан, но **разобран экспериментально** и записан
в `references/`. Проект — это каталог с текстовыми файлами (JSON / CSV / XML / INI),
плюс два бинарных словаря `*.var`. Всё, кроме `*.var`, редактируется скриптами.

## Порядок действий в начале КАЖДОЙ задачи

1. `references/file-format-notes.md` — карта формата: какой файл за что отвечает,
   что является источником истины, а что зеркалом.
2. `references/known-issues.md` — грабли. Там есть вещи, которые ломают проект молча.
3. `references/recipes.md` — готовые пошаговые рецепты (создать проект с нуля,
   добавить программу/функцию/ФБ/структуру, словари, править код, собрать).
   Нужен алгоритм (регулятор, фильтр, таймер, работа с массивом или строкой) —
   сначала `references/fb-library.md`: возможно, готовый блок уже есть.
4. Последние 2-3 записи в `references/session-log.md`.

## Три правила, которые важнее остальных

1. **`tags/global.var` — источник истины глобального словаря.** `tags/global.csv`
   только зеркало: IDE его НИКОГДА не читает, а перезаписывает при сохранении.
   Удалили/испортили `global.var` → все глобальные переменные потеряны безвозвратно.
2. **Текст программ живёт в JSON (base64), а не в `.st`.** `prog.st`, `types/*.st`,
   `*.csv` — генерируемые зеркала, правки в них затираются при следующем сохранении.
3. **Перед любой правкой — резервная копия каталога проекта.**
   ```bash
   cp -r <project_dir> <project_dir>.bak-$(date +%Y%m%d-%H%M%S)
   ```

## Что можно делать скриптами, а что нет

| Задача | Скриптом? | Как |
|---|---|---|
| Создать проект с нуля | да | скелет `assets/skeleton/` + `import.prj` |
| Создать программу / функцию / структуру / ФБ | да | `import.prj` в корне проекта |
| Локальный словарь программы или дочерней программы | да | `<имя>.import.csv` в корне — **заменяет словарь целиком**, класть полный список (recipes.md, Рецепт 10) |
| Дочерняя программа | да | `import.prj` → `<CHILD_PROGRAM>` строка `имя,ST,R,родитель,` (третье поле — тип выхода) |
| Массив | локальный — да, глобальный — GUI | строка CSV `Type=A`, `Library` = тип элемента, `Length` = `[N]` / `[N,M]` |
| Архивация переменной | да | поля CSV `Is_Ar;Ar_count;Ar_period;Ar_filter` |
| Текст программы без base64 | да | `prog.import.st` при закрытом проекте — только программы верхнего уровня |
| Словарь структуры | да | напрямую в `types/structs.json` |
| Словарь функции | да | напрямую в `functions/functions.json` |
| Экземпляр системного ФБ (`SIN_GEN`, `BLINK`, …) | да | строка в CSV словаря как у экземпляра структуры: `gen1;U;;SIN_GEN;4;…` + поля; вызов `gen1.SIN_GEN(...)` |
| Код ST любого POU | да | поле `text.st` (base64) в соответствующем JSON |
| Порядок вызова программ, период задачи | да | `tasks/main/task.json` |
| Конфигурация контроллера, Modbus, OPC | да | `configuration.json` |
| Параметры подключения к ПЛК (IP, порт) | да | **`settings.ini` → `[connectionPLC]`**, не `configuration.json` |
| **Глобальный словарь** | **нет** | только через GUI (импорт в редакторе словаря) |
| **Модуль ввода-вывода** | **нет** | переменная модульного типа в глобальном словаре → модуль сам появляется в дереве конфигурации и в `modilesIO` |

Формат `umvar` (`*.var`) разобран лишь частично — генерировать его вручную нельзя.
Именно поэтому глобальный словарь остаётся ручной операцией, а локальные словари
делаются через `*.import.csv`, чтобы `.var` сгенерировала сама IDE.

## Запуск IDE из командной строки

```bash
"C:/Program Files/UnimodPRO2/Unimod.exe" -open "<путь>/project.uprj"
```

**Путь не должен содержать пробелов.** Unimod режет аргумент `-open` по первому
пробелу и выдаёт «Не найден файл проекта», кавычки не помогают. Для каталогов с
пробелами подставлять короткое имя 8.3 (`C:\CLAUDE~1\...`) — `unimod_open.ps1`
делает это сам.

При открытии IDE показывает модальные диалоги подтверждения импорта — их надо
прожать. Готовые скрипты в `scripts/` (UTF-8 **с BOM**, иначе PowerShell 5.1
их не прочитает):

| Скрипт | Что делает |
|---|---|
| `unimod_open.ps1 -Project <...\project.uprj>` | запускает IDE и подтверждает диалоги импорта |
| `unimod_focus.ps1` | выводит окно IDE вперёд (нужно перед горячими клавишами) |
| `unimod_save.ps1` | Ctrl+Shift+S — сохраняет **весь проект**; `-EditorOnly` = Ctrl+S, только активный редактор |
| `unimod_build.ps1 -ProjectDir <...>` | F9 и проверка результата |
| `unimod_close.ps1` | штатное закрытие |
| `unimod_open_secure.ps1 -Project <...> -Login <...> -Password <...> -Fill` | открытие проекта, **защищённого паролем**, без авто-Enter; ввод через буфер обмена |

**Защищённый паролем проект** (в `usr.cfg` непустая секция `[user]`) нельзя
открывать `unimod_open.ps1`: он жмёт Enter в окне входа, это неудачная
попытка, после 3 (по умолчанию) проект блокируется, а пароль не
восстанавливается. Эксперименты с безопасностью — только на копии.

**Осторожно с Enter.** После НЕуспешной сборки первый диалог — «Упаковать проект
и отправить разработчику по электронной почте?», и кнопка по умолчанию «Да».
На пост-сборочных диалогах жать только ESC.

**Осторожно с контроллером.** Во всех окнах подключения (диагностика, чтение с
контроллера) адрес по умолчанию `192.168.1.1`, а кнопка по умолчанию —
действие («Прочитать», «Продолжить»): Enter отправит запрос реальному
устройству в сети. Для проверок без железа — только `127.0.0.1`. «Загрузка»
(F7), «Broadcast», обновление прошивок и «Внесение ошибок» — только по явной
просьбе пользователя. Карта этих функций — `gui-guide.md`, раздел «Работа с
контроллером».

## Когда нужен GUI

Часть возможностей файлами не решается вообще: **глобальный словарь**
(бинарный `global.var`), **модули ввода-вывода** (добавляются переменной
модульного типа в глобальном словаре),
**эмуляция и отладка** (это исполнение, а не файлы), библиотеки и
права доступа. Для них — `references/gui-guide.md`: карта меню, панелей и правила
автоматизации. Скрипты управления интерфейсом через UI Automation —
в `scripts/ui/` (элементы адресуются по имени, а не по координатам).

**Библиотека готовых блоков — 204 системных ФБ.** Прежде чем писать логику
руками, посмотреть, нет ли готового: регуляторы, `PWM`, фильтры, `HYSTER`,
`LIMITR`, `LRATE`, `DZONE`, `AVRGD`, `INTEG`, `DELAY`, `LATCH`, мультиплексоры,
массивы (`AR_COPY`, `GETAR`, `SETAR`), битовые поля (`GETFIELD`, `SETFIELD`),
строки (`MID`, `FIND`, `I_TO_S`), время (`TIME_GET`, `TIME_TO_TEXT`), Modbus,
HART, файлы, расчёты по ГОСТ. Поиск и сведения — `fb_find()` / `fb_info()` из
`fbd_gen.py` (данные в `assets/fb_library.json`), раздел руководства —
`scripts/manual.py ИМЯ`, каталог целиком — `references/fb-library.md`.
Собираются все 204; 33 сверены с руководством в эмуляции (`ui/um_emul.ps1`).

**Схемы FBD пишутся файлами.** `prog.json` с `Blocks`/`Links` редактор
принимает как есть, в том числе на 400+ блоков. Генератор и разборщик схем:
`scripts/fbd_gen.py` — `expr()`/`fb_call()` сами раскладывают выражения
по клеткам и проверяют типы, порядок выполнения ставится по правилу IDE, правка
чужой схемы — `Scheme.load`, `delete`, `insert`, `move`, `rename`;
`fbd_dump.py` (`--check-st` — сверка с выводом IDE), смысловой дифф версий —
`fbd_diff.py` (Рецепты 11, 13, 14). Для точечных правок мышью —
`scripts/ui/fbd_lib.ps1` и `fbd_do.ps1`: координаты вычисляются по полосам
прокрутки при любом масштабе и размере поля. Любой из 204 системных ФБ генератор
ставит сам, как и функцию проекта, метод структуры, дочернюю программу и элемент
массива (`func_call`, `struct_call`, `child_call`). Программы обмениваются через `программа.переменная` (чтение и запись) или
глобальные переменные. Элементы LD (шина, контакт, виток), метка и прыжок,
массивы (в том числе трёхмерные и с индексом-переменной) — тоже файлом. Рабочий путь, стандарт расположения, каталог операторов и таблица
«симптом → причина → лечение» — `references/fbd-guide.md`.
Главные ловушки: непонятое IDE выбрасывает **молча** (после генерации сверять
код ST `fbd_dump.py --check-st`); связь, проведённая мышью, не попадает в модель
до следующей правки блока (`Submit-FbdLinks` / `fbd_do.ps1 save`, потом сверять
файл); правка мышью перенумеровывает порядок выполнения по расположению
результатов; два блока одного экземпляра ФБ и оператор на 3+ входа без `args`
теряют связи при сохранении; цикл по связям и неизвестная буква типа в импорте
словаря роняют саму IDE; неявных преобразований типов нет, REAL-константы только
с точкой.

Всё остальное быстрее и надёжнее делать правкой файлов по `references/recipes.md`.

## Обязательный цикл проверки

Любая правка файлов вступает в силу только после цикла
**открыть в IDE → сохранить (Ctrl+Shift+S)**. Пока это не сделано, изменения не
подтверждены. После правки всегда:

1. Открыть проект в Unimod PRO 2.
2. Сохранить (**Ctrl+Shift+S**, а не Ctrl+S — тот сохраняет только активный
   редактор) — IDE перезапишет зеркала и словари.
3. Собрать (F9). Признак успеха: появился каталог `app/` с `project.app`,
   и кнопки «Загрузка / Отладка / Эмуляция» стали активными.

## Фиксация знаний (обязательно в конце задачи)

Запись в `references/session-log.md`, устоявшиеся факты — в
`file-format-notes.md` (структура) или `known-issues.md` (грабли).
Не оставляй находки только в чате.

## Структура каталога skill

```
unimod-pro-trei/
├── SKILL.md
├── references/
│   ├── file-format-notes.md   # карта формата проекта
│   ├── known-issues.md        # грабли и ограничения
│   ├── recipes.md             # пошаговые рецепты
│   ├── gui-guide.md           # карта интерфейса и рецепты работы в GUI
│   ├── fbd-guide.md           # схемы FBD: файлами, расположение, ловушки
│   ├── fb-library.md          # 204 системных ФБ: назначение, проверки, вызов
├── scripts/               # скрипты управления IDE и генерации FBD
│   ├── fbd_gen.py         # сборка схемы FBD записью prog.json
│   ├── fbd_dump.py        # чтение схемы FBD: выражения, блоки, замечания
│   ├── fbd_diff.py        # смысловой дифф двух версий схемы
│   ├── manual.py          # раздел руководства ТРЭИ по имени ФБ или функции
│   └── ui/                # управление интерфейсом через UI Automation
│       ├── fbd_lib.ps1    # мышь в редакторе FBD: геометрия, связи, размещение
│       ├── fbd_do.ps1     # то же одиночными командами
│       └── um_emul.ps1    # эмуляция: словарь, вход и выход, чтение и запись значений
└── assets/
    ├── fb_library.json    # свод по системным ФБ (назначение, страница, вердикты)
    └── skeleton/          # эталонный пустой проект (11 файлов)
```
