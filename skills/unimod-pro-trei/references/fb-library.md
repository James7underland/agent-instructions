# Системная библиотека: 204 функциональных блока

Библиотека ТРЭИ — это не «набор таймеров», а готовая автоматика: регуляторы,
ШИМ, фильтры, гистерезис, ограничение скорости, работа с массивами, строками,
временем, Modbus, файлами, HART, расчёты по ГОСТ. Прежде чем писать логику
руками, стоит посмотреть, нет ли готового блока: `fb_find('гистерезис')`.

## Откуда сведения

| Источник | Что даёт |
|---|---|
| `%APPDATA%\TREI\UnimodPRO2\library\types\types.json` | выводы, их типы и комментарии — читает `fb_catalog()` |
| `doc/Unimod_PRO_2_Programming_Manual.pdf`, главы 6–7 | назначение, алгоритм, примеры на ST — читает `manual.py ИМЯ` |
| `assets/fb_library.json` | свод: назначение, семейство, нужен ли контроллер, страница руководства, вердикт сборки и проверки в эмуляции |

```python
from fbd_gen import fb_info, fb_find
fb_info('PWM')['purpose']      # назначение из руководства
fb_info('PWM')['inputs']       # [('AUTO','B'), ('X','R'), ...]
fb_info('PWM')['emul']         # что показал опыт в эмуляции
fb_find('усреднение')          # поиск по назначению
```

```bash
python manual.py PWM             # раздел руководства целиком
python manual.py --example TON   # только пример вызова на ST
python manual.py --list 6        # все 164 блока главы 6 со страницами
```

## Как вызвать блок

В словаре программы — строка экземпляра (`instance_csv_rows('lat1','LATCH')`),
в коде — вызов метода с аргументами **в порядке входов** и чтение выходов
по именам:

```
lat1.LATCH(n = 5, rn);      (* аргументы позиционные, выражения допустимы *)
y := lat1.Y;
q := lat1.Q;
```

На схеме FBD то же самое делает `Scheme.fb_call()` — порядок входов тот же.
Аргументом может быть литерал (`25.0`, `b#7`, `d#1711021435000.0`, `'текст'`),
переменная, элемент массива, целый массив (для выводов «ссылка на массив»)
или выражение (`n >= 3`, `(n >= 12) AND (n <= 14)`).

## Проверено сборкой и эмуляцией

- **Собираются все 204 блока** (проба: экземпляр в словаре, присвоение каждому
  входу, вызов метода, чтение каждого выхода). Ни один блок компилятор не
  отверг — в том числе аппаратные семейства (`MB_*`, `HART_*`, `FL_*`,
  `SOCK_*`): без железа они собираются, но работать будут только на контроллере.
- **33 блока проверены в эмуляции** на соответствие руководству — колонка
  «эмуляция» в таблице ниже. Совпало всё, кроме двух мест: единица `PWM.GUprd`
  и час в примере `TIME_TO_TEXT` (см. `known-issues.md`).

## Чем «не описанные» отличаются от остальных

У 40 блоков из 204 нет раздела в руководстве: 26 прикладных `*_GA`
(газоанализатор и родственная автоматика), `CRC`, `HART`, `LPQ`/`LPR`/`LPRM`,
`GET_PLC_INFO_*`, `GET_CRC_FB`, `SOE_TO_ARRAY`, `SOE_ARR_POS`, `drv_gettime`,
`settime`, `AI_VALID`, `PORT_GATE`, `MB_R_C`/`MB_W_C` (описаны, но под именем с
кириллической «С»). Про них известны только выводы и комментарии из библиотеки
IDE — поведение придётся выяснять опытом.

## Регуляторы: точные формулы (формулы в PDF — картинки, текстовая выгрузка их теряет)

Сняты рендером страниц 513/521 PDF (`pymupdf`, индекс страницы = номер в колонтитуле − 1).

**RAN** (аналоговый ПИД, позиционная форма):
`W(p) = KP + KP/(TI·p) + KD·TD·p/(TD·p + 1)`
- производная **не** умножается на KP; её фильтр 1-го порядка с постоянной **TD**.
  Перевод из стандартной формы Kc·(1 + 1/(Ti·s) + Td·s/(Td/N·s + 1)):
  `KP=Kc, TI=Ti, TD=Td/N, KD=Kc·N`;
- цепочка: X2 → FILTER(TF) → `Xe = X1 − KM·X2f` → зона DB → ПИД → ограничение Ymin/Ymax;
- D и P считаются от **ошибки** (бросок по уставке), весов уставки b, c нет;
- антинасыщение: на Ymax/Ymin интегратор не растёт/не убывает; Zup/Zdown — запрет изменения;
- ручной режим: Y = X0 (так удобно делать ступеньку для снятия переходной);
  при переходе в AUTO интегратор = X0 − KP·Xz (безударно), производная обнуляется;
- параметры KP…TD документ советует менять в ручном режиме; все они — входы, т.е. могут меняться каждый цикл.

**RIM** (импульсный, для ИМ постоянной скорости + PWM), скоростная форма ПДД²:
`W(p) = TM·(KP·p + KP/TI + KD·TD·p²/(TD·p + 1)²)`, вместе с ИМ 1/(TM·p) даёт
`KP + KP/(TI·p) + KD·TD·p/(TD·p + 1)²`. TI ≤ 0 воспринимается как 1.

**DELAY / AVRGM**: N ≤ 128 циклов (больше — как 128), N фиксируется при RUN=TRUE.
Задержка N·Cycle — длиннее либо крупным Cycle, либо цепочкой блоков.

**Не проверено в эмуляции:** единицы TI/TD (скорее всего секунды, как у INTEG), схема дискретизации RAN.

## Как проверять блок опытом

Рецепт 18 в `recipes.md`: словарь + сценарий на ST → сборка → эмуляция →
чтение словаря. Два правила, без которых опыт врёт:

1. **Читать словарь постранично.** Таблица отдаёт «Значение» только у строк,
   которые сейчас на экране; дальние переменные читаются пустыми и выглядят
   как нули — легко решить, что программа не работает. `um_emul.ps1` листает
   таблицу сам.
2. **Ставить метки стадий** (`z_stage := N;` между группами) — сразу видно,
   докуда дошёл цикл программы, если блок всё-таки прерывает выполнение.
