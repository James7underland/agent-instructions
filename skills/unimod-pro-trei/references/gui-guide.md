## Инструмент

Qt отдаёт дерево **UI Automation** (в `platforms/qwindows.dll` есть
`QWindowsUiaMainProvider`), поэтому элементы адресуются по имени, а не по
координатам. Скрипты — в `assets/scripts/ui/`.

| Скрипт | Что делает |
|---|---|
| `ui_lib.ps1` | общая библиотека, подключается точкой из остальных |
| `ui_tree.ps1` | дамп дерева UIA: `-MaxDepth`, `-Filter`, `-Type` |
| `ui_read.ps1` | обзор: вкладки, деревья, кнопки, поля (`-What tree|table|buttons|edit|tabs|all`) |
| `ui_do.ps1` | действие над элементом по имени: `-Action auto|click|invoke|value|expand|select|focus` |
| `ui_menu.ps1` | проход по пути в главном меню за один вызов |
| `ui_shot.ps1` | снимок окна целиком или прямоугольной области |
| `ui_errors.ps1` | вкладка «Список ошибок» текстом |
| `um_emul.ps1` | эмуляция: открыть словарь программы, войти/выйти, прочитать все значения, записать значение |

```powershell
# посмотреть, что вообще есть на экране
.\ui_read.ps1 -What overview

# пройти по меню и нажать пункт
.\ui_menu.ps1 -Path "Файл","Архив проекта","Упаковать проект в файл"

# нажать кнопку диалога по имени
.\ui_do.ps1 -Name "Отмена" -Type Button

# найти, но не нажимать (когда совпадений может быть несколько)
.\ui_do.ps1 -Name "Сохранить" -List
```

## Деревья и таблицы — это Grid (проверено 2026-09-19)

Дерево «Программы и данные» и таблица словаря в UIA поддерживают
`GridPattern`: `GetItem(строка, колонка)` отдаёт ячейку **любой** строки, даже
не отрисованной, а `Current.RowCount` — сколько их всего. Это надёжнее, чем
собирать видимые `TreeItem` по координатам.

```powershell
$t = @(Get-UmAllElements -MaxDepth 12 | Where-Object { $_.Type -eq 'Tree' -and $_.X -gt 600 })[0]
$g = $t.Element.GetCurrentPattern([System.Windows.Automation.GridPattern]::Pattern)
$g.Current.RowCount                      # все строки словаря
$g.GetItem(5, 0).Current.Name            # имя переменной в 6-й строке
$g.GetItem(5, 2).Current.Name            # её значение (колонка 2)
```

Две оговорки:

1. **`Name` есть у всех строк, а «Значение» — только у отрисованных.** Дальние
   строки приходят пустыми; читать словарь целиком надо постранично
   (`{PGDN}` + склейка), это делает `um_emul.ps1 -Action read`.
2. **Прямоугольник (`BoundingRectangle`) верен только у видимых строк**, у
   остальных он в виртуальных координатах (встречались Y в десятки тысяч), а
   `ScrollItemPattern.ScrollIntoView()` на них не сработал. Поэтому узлы дерева
   раскрываются по одному: выделили кликом по видимой строке → `{RIGHT}`.

Дерево проекта с несколькими сотнями переменных раскрывать целиком (`{MULTIPLY}`)
не стоит: 2591 строка, и навигация клавишами становится бесполезной.

## Пять правил, без которых GUI не поддаётся

1. **Окно всегда развёрнуто на весь экран.** `Show-UmWindow` делает
   `ShowWindow(SW_MAXIMIZE)`. При фиксированном размере (раньше было 1600×940)
   нижние панели «Список ошибок» и «Вывод» и правая панель «Добавить/Изменить»
   не попадают в снимок, и разбор ошибок сборки превращается в раскопки.

2. **Одна операция — один вызов PowerShell.** Всплывающее меню Qt закрывается,
   как только окно теряет фокус, а между вызовами фокус забирает окно Claude.
   Поэтому «открыть меню» и «выбрать пункт» разными вызовами не работают —
   для этого и сделан `ui_menu.ps1`. Модальные диалоги, наоборот, переживают
   смену фокуса, с ними можно работать отдельными вызовами.

3. **Меню открывается кликом, а не `Invoke`.** У пункта меню есть
   `InvokePattern`, но на пункте верхнего уровня он не раскрывает выпадающий
   список. У кнопок диалогов `Invoke` работает штатно.

4. **Перед проходом по меню — два `{ESC}`.** Если меню осталось открытым от
   прошлой операции, первый же клик по пункту верхнего уровня его закроет,
   а не откроет. `ui_menu.ps1` шлёт `{ESC}` сам.

5. **Масштаб координат измеряется, а не угадывается.** `Get-UmScale` ставит
   курсор и сравнивает `GetCursorPos` с `GetPhysicalCursorPos`. На проверенной
   машине коэффициент вышел **1** — координаты UIA совпадают с координатами
   `SetCursorPos`, поэтому прямоугольник любого элемента можно подставлять в
   `ui_shot.ps1 -Region` без пересчёта. Единица получается потому, что
   `ui_lib.ps1` при загрузке объявляет процесс DPI-aware
   (`SetProcessDPIAware()`); без этого до первого UIA-вызова координаты
   логические, и снимок выходит обрезанным (1721×927 вместо 2582×1390). Сравнивать ширину окна из
   `GetWindowRect` с шириной из UIA бесполезно: у развёрнутого окна рамка
   выходит за экран и коэффициент получается мусорный (0.99 вместо реального).

**Заголовок окна не всегда содержит имя проекта.** Обычно это
`Unimod PRO 2: <имя>`, но после «Сохранить проект как» заголовок остаётся
`Unimod PRO 2`, хотя проект открыт и виден в дереве. Определять «проект открыт»
по наличию двоеточия в заголовке нельзя — `unimod_open.ps1` из-за этого уходил
в TIMEOUT на корректно открытом проекте. Надёжный признак: сплэш-окно называется
`Unimod`, а главное — `Unimod PRO 2` с именем или без, поэтому маска
`'Unimod PRO 2*'` их различает.

Ещё две мелочи, на которых легко потерять время:

- У скрытых элементов Qt отдаёт `BoundingRectangle` = бесконечность. Приведение
  к `int` падает — в библиотеке для этого есть `ConvertTo-UmInt`, а у элементов
  выставляется флаг `OffScreen`.
- Выпадающие меню и диалоги — **отдельные окна верхнего уровня** процесса.
  Обходить надо все окна процесса (`Get-UmRoots`), а не только главное.
- Не называть вспомогательные функции `MI`, `SI`, `NI` и т. п. — это встроенные
  алиасы PowerShell (`Move-Item`, `Set-Item`, `New-Item`), и вызов молча уходит
  не туда.

## Дерево проекта («Программы и данные»)

Разделы верхнего уровня. «Массивы» появляются только если массивы в проекте есть.

```
<имя проекта>
├── Глобальный словарь
├── Задачи
│   └── main
│       └── <программа>
│           └── Локальный словарь → переменные
├── Структуры
│   └── <структура>
│       ├── Функциональные блоки → <ФБ>
│       └── Данные → поля структуры
├── Функции
│   └── <функция>
│       └── Локальный словарь → возвращаемое значение и параметры
└── Списки слежения
```

Особенности работы с деревом:

- **Двойной клик по узлу открывает его редактор** (`ui_do.ps1 -Action dblclick`).
- Узлы **не поддерживают `ExpandCollapsePattern`**. Раскрывать надо выделением
  и стрелкой: `ui_do.ps1 -Action expand` уже делает это через `{RIGHT}`.
  `{MULTIPLY}` (звёздочка на цифровом блоке) раскрывает всю ветку целиком.
- В UIA каждая строка дерева даёт **два** `TreeItem` с одинаковым `Y`: колонка
  «Имя» и колонка «Комментарий». Фильтруй по `X`, иначе получишь дубли.

создаётся.

## Редактирование ячеек словаря: `{RIGHT}` + `{F2}`

Это главный приём работы с таблицей словаря. Мышью ячейки открыть **не
получается**: клик по ячейке только выделяет строку, а редактор не запускается —
ни одиночным кликом, ни двойным, ни кликом по уже выделенной строке.

Работает клавиатура:

- **`{RIGHT}`** перемещает текущую ячейку на колонку вправо. В этом дереве у
  строк нет потомков, поэтому стрелка вправо не раскрывает узел, а идёт по
  колонкам: Имя → Тип → Значение → Адрес modbus → Архивация → Хранить/резерв →
  Комментарий.
- **`{F2}`** открывает редактор текущей ячейки. Для «Тип» это выпадающий список,
  который сразу раскрыт; для остальных — поле ввода.
- Выбор в списке — стрелками `{DOWN}` и `{ENTER}`; в поле ввода — `^a`, текст,
  `{ENTER}`.

Полный рецепт создания глобальной переменной нужного типа, целиком скриптом:

```powershell
# кнопку жмём через InvokePattern — она надёжнее клика
$add = @(Get-UmAllElements -MaxDepth 14 |
         Where-Object { $_.Type -eq 'Button' -and $_.Name -eq 'Добавить переменную' })[0]
$inv = $add.Element.GetCurrentPattern([System.Windows.Automation.InvokePattern]::Pattern)

$inv.Invoke(); Start-Sleep -Milliseconds 800
Send-UmKeys "^a" 150
Send-UmKeys "g_pressure_out" 300       # имя
Send-UmKeys "{ENTER}" 600
Send-UmKeys "{RIGHT}" 350              # -> колонка "Тип"
Send-UmKeys "{F2}" 700                 # раскрыть список типов
Send-UmKeys "{DOWN}{DOWN}{DOWN}" 500   # булевский -> байт -> целый -> вещественный
Send-UmKeys "{ENTER}" 700
Send-UmKeys "{RIGHT}" 350              # -> "Значение"
Send-UmKeys "{F2}" 600
Send-UmKeys "^a" 150; Send-UmKeys "12.5" 300; Send-UmKeys "{ENTER}" 700
Send-UmKeys "{RIGHT}{RIGHT}{RIGHT}{RIGHT}" 500   # -> "Комментарий"
Send-UmKeys "{F2}" 600
Send-UmKeys "Давление на выходе НПС" 400; Send-UmKeys "{ENTER}" 700
```

Всё это — в **одном** вызове PowerShell: между вызовами теряется фокус и
сбрасывается текущая ячейка.

Смещения в списке типов от «булевский»: байт `{DOWN}`, целый ×2,
вещественный ×3, дв.вещественный ×4, таймер ×5, строка ×6. Дальше в том же
списке идут структуры системной библиотеки и структуры проекта — то есть
переменную библиотечного типа (например `BLINK` или `SIN_GEN`) объявляют
отсюда же.

## Дочерние программы, массивы, архивация, экспорт тегов (гл. 5)

Проверено 2026-09-12 на `s2_lab`; файловые пути — `recipes.md`, Рецепт 10.

### Дочерняя программа

- **Контекстное меню программы** (выделить узел, `+{F10}`): Добавить
  дочернюю программу · Удалить (Del) · Открыть · Копировать (Ctrl+C) ·
  Вставить (Ctrl+V) · Переименовать (F2) · Открыть словарь · Переместить
  вверх (Ctrl+Вверх) · Переместить вниз (Ctrl+Вниз). Первый пункт —
  `{DOWN}{ENTER}`.
- Окно называется **«Добавить программу»**: «Имя:» (`Edit`, по умолчанию
  `program_0001`, `SetValue` работает), «Язык:» (`ComboBox`, ST), «OK» —
  `Invoke` внутри `Start-Job`.
- Узел появляется под родителем, после его «Локального словаря». В длинном
  дереве он оказывается вне UIA — свернуть «Глобальный словарь» и «Локальный
  словарь» родителя (клик по узлу + `{LEFT}`).
- **Меню дочерней программы** — то же плюс «Параметры» 4-м пунктом. Окно
  «Параметры функционального блока: <имя>» (так и называется) — таблицы
  «Входы» и «Выходы» (Имя, Тип, Комментарий), только просмотр, OK / Отмена.
- **Словарь дочерней программы** — «Открыть словарь», 8-й пункт. В нём есть
  колонка **«Атрибут»** (Вход / Выход), которой нет у обычной программы.
  Выход `<имя>` создаётся сам, по умолчанию «булевский», переименовать нельзя.
  Тип меняется обычным рецептом: `{HOME}{RIGHT}{F2}{DOWN}×3{ENTER}{ESC}`.

### Массивы

- Массив создаётся **именем**: `g_arr[5]`, `g_mat[2,3]` (до трёх измерений).
  Строка становится раскрываемой: элементы `g_arr[0]…g_arr[4]`, у двумерного —
  промежуточные узлы `g_mat[0]`, `g_mat[1]` и листья `g_mat[i,j]`. Раскрыть —
  `{RIGHT}` на строке, как у структуры.
- **Тип задать ДО скобок** (known-issues): создать `g_real`, выставить тип,
  затем переименовать в `g_real[5]`.

### Архивация

- Флажок «Архивация» виден по умолчанию, параметры спрятаны в скрытых
  колонках. **Правый клик по заголовку таблицы** открывает меню видимости
  колонок (пункты видны в UIA как `MenuItem`, состояние — `TogglePattern`):
  Без сортировки · Имя · Тип · Значение · Адрес modbus · Архивация ·
  **Настройки архивации ▸** (Количество записей · Фильтр по времени (сек) ·
  Фильтр по значению) · Хранить/резерв · Комментарий · offset · Имя в
  Alpha.Server · Доступ · Alpha.DataCategory. Каждый клик переключает одну
  колонку и закрывает меню.
- Видимость хранится в реестре, `varColumns` — ширины колонок через запятую,
  0 = колонка скрыта.
- Значения параметров: `{RIGHT}` до колонки, `{F2}`, текст из буфера,
  `{ENTER}`. Флажок — **только клик мышью** по центру ячейки.
- После сохранения — поля `Is_Ar;Ar_count;Ar_period;Ar_filter` в CSV словаря,
  после сборки — в `base.csv`.

## Редактор ST

Открывается двойным кликом по узлу программы, функции или ФБ. Панель кнопок:

| Группа | Кнопки |
|---|---|
| правка | отменить изменения · повторить изменения · удалить · вырезать · копировать · вставить |
| вставка операторов | for · while · repeat · if then · if then else · if then elif · case · goto · return |
| контроль | **Проверка** |

**Текст через UIA не читается** — область кода это QScintilla, `ValuePattern`
возвращает пустую строку. Читать и писать надо через буфер обмена:

```powershell
Invoke-UmClick -X 1200 -Y 400 -SleepMs 500   # клик в область текста
Send-UmKeys "^a" 300
Send-UmKeys "^c" 600
$code = Get-Clipboard -Raw                    # весь текст программы
```

Проверено: вернулись ровно те же 412 символов, что лежат в `prog.json`.
Обратная запись — `Set-Clipboard` + `^a`, `^v`. Но для правки кода надёжнее
файлы (`text.st` в JSON), GUI нужен только когда файл править нельзя.

**Кнопка «Проверка»** компилирует один POU без полной сборки и заполняет вкладку
«Список ошибок» с точным номером строки и столбца. Быстрее, чем F9, когда
правишь один блок:

```
Ошибка 19: Неизвестное выражение или идентификатор | sim_main | строка 20 | столбец 1
```

Список ошибок читается скриптом — `ui_errors.ps1` (ячейки таблицы приходят как
`DataItem`). Учти: список **может содержать результат прошлой «Проверки»**,
а не текущей сборки — сверяй столбец «Источник» и время.

## Добавление программы через GUI

Правый клик по узлу задачи «main» → контекстное меню: «Добавить программу» ·
«Свойства» · «Вставить». Открывается диалог с именованными полями:

| Поле | Тип | Значения |
|---|---|---|
| Имя: | Edit | задаётся через `ValuePattern.SetValue` |
| Язык: | ComboBox | **ST** или **FBD/LD** |
| OK / Отмена | Button | `InvokePattern` |

Контекстные меню дерева — см. отдельный раздел ниже: их надо вызывать
клавишами и клавишами же выбирать пункт, потому что UIA их не видит.

## Контекстные меню: `Shift+F10` и стрелки

Через контекстное меню делается многое, чего больше нигде нет: добавление
программы, списка слежения, добавление переменной в список слежения,
переименование и удаление узлов.

Два правила:

1. **Вызывать `+{F10}` (Shift+F10), а не правый клик.** Синтетический правый
   клик через `mouse_event` меню открывает не всегда; `Shift+F10` — стабильно.
   Узел перед этим должен быть выделен обычным левым кликом.
2. **Выбирать пункт клавишами, а не мышью.** Всплывающее меню Qt **открывается,
   но в дереве UI Automation не появляется вовсе** — `Get-UmAllElements` его не
   находит, хотя на скриншоте меню видно. Поэтому координат пункта взять неоткуда;
   идти надо `{DOWN}` нужное число раз и `{ENTER}`.

```powershell
# выделить узел, открыть его контекстное меню и выбрать первый пункт
Invoke-UmClick -X $pn.X -Y $pn.Y -SleepMs 900
Send-UmKeys "+{F10}" 1300
Send-UmKeys "{DOWN}" 500
Send-UmKeys "{ENTER}" 2000
```

Состав меню смотреть скриншотом (`ui_shot.ps1`) — это единственный способ
узнать, сколько раз жать `{DOWN}`. Известные меню:

| Узел | Пункты |
|---|---|
| Задача `main` | Добавить программу · Свойства · Вставить |
| Программа | Добавить дочернюю программу · Удалить · Открыть · Копировать · Вставить · Переименовать · Открыть словарь · Переместить вверх · Переместить вниз |
| Дочерняя программа | как у программы + «Параметры» (4-й пункт); «Открыть словарь» — 8-й |
| Списки слежения | Добавить список слежения |
| строка словаря | Добавить переменную · Вставить · Переместить сюда · Просмотр · Сформировать бинарный описатель... |

## Управление проектами

**«Файл → Сохранить проект как»** — обычный диалог с полями «Имя:» и «Путь:»
(теми же, что у «Создать проект»), кнопки OK / Отмена. Поля задаются через
`ValuePattern`, OK — через `InvokePattern`. Что именно попадает в копию —
в `file-format-notes.md`.

**«Файл → Переименовать проект» диалога НЕ открывает.** Пункт меню переводит
корневой узел дерева в режим правки имени — это inline-редактирование, как по
`F2`. Поэтому искать поля диалога в UIA бесполезно, их нет. Дальше:

```powershell
Send-UmKeys "^a" 300          # текст в узле уже выделен, но на всякий случай
Send-UmKeys "proj_ren" 500    # новое имя: латиница, цифры, подчёркивание
Send-UmKeys "{ENTER}" 3000
```

То же самое доступно по `F2` на корневом узле и через его контекстное меню.

**Одного `{ENTER}` мало.** После ввода имени IDE показывает подтверждение
(руководство, §6.8: предлагает сохранить проект и перезагружает его). Пока
это окно не обработано, переименование **не доходит до файловой системы** —
в дереве новое имя уже видно, а каталог и `name` в `project.uprj` остаются
прежними. Если в этот момент закрыть IDE принудительно, операция откатывается целиком.

Окон подтверждения **два, подряд**:

1. «Переименование проекта — **Сохранить изменения проекта?**», кнопки «Да» /
   «Нет», по умолчанию сфокусирована «Да».
2. «Переименование проекта — **Для завершения переименования проект будет
   перезагружен**», кнопка OK.

Оба ловятся через `EnumWindows` по процессу (в UIA их искать не надо) и
закрываются `SetForegroundWindow` + `{ENTER}`. После второго окна проект
перезагружается — сверять каталог на диске имеет смысл только после этого.

Результат после обоих подтверждений (проверено): **каталог на диске
переименован**, `name` в `project.uprj` обновлён, заголовок окна стал
`Unimod PRO 2: <новое имя>`. То есть переименование действительно меняет имя
каталога, как обещает руководство, — просто доводится до конца лишь после
второго диалога.

**«Файл → Удалить проект» — необратимо, с защитой от случайного нажатия.**
Открывается диалог «Удаление» с текстом «Для подтверждения удаления проекта
нужно ввести его название:», под ним показано имя проекта, поле ввода и кнопки
«Подтвердить» / «Отмена». Диалог целиком читается через UIA:

```powershell
$ed = @(Get-UmAllElements -MaxDepth 18 |
        Where-Object { $_.Type -eq 'Edit' -and $_.Y -gt 690 -and $_.Y -lt 710 })[0]
$ed.Element.GetCurrentPattern([System.Windows.Automation.ValuePattern]::Pattern).SetValue("proj_ren")
$btn = @(Get-UmAllElements -MaxDepth 18 |
         Where-Object { $_.Type -eq 'Button' -and $_.Name -eq 'Подтвердить' })[0]
$btn.Element.GetCurrentPattern([System.Windows.Automation.InvokePattern]::Pattern).Invoke()
```

Имя надо ввести точно — иначе «Подтвердить» не сработает. Удаляется каталог
проекта целиком, с диска. Применять только к своим песочницам.

**«Инструменты → Экспорт/импорт → Экспорт файла структуры проекта» не даёт
ничего нового.** Сохранённый файл **байт в байт совпадает** с
`proj_structure.prj`, который и так лежит в корне проекта (проверено: оба по
201 байту, одинаковое содержимое). Пользоваться экспортом из GUI смысла нет —
проще взять готовый `proj_structure.prj`. Обратная операция, импорт структуры,
делается файлом `import.prj` без всякого GUI (см. `recipes.md`).

**«Инструменты → Сравнение проектов» требует контроллера.** Вопреки названию,
это не сравнение двух каталогов на диске: пункт сразу отвечает окном
«У проекта не указаны параметры подключения» с кнопкой OK. То есть сравнивается
текущий проект с приложением, залитым в ПЛК. Без железа функция недоступна;
сравнивать две версии проекта на диске надо своими средствами (diff по файлам).

## Списки слежения

Список слежения — это именованная группа переменных для просмотра значений при
отладке. Редактировать переменные в нём нельзя, только смотреть.

**Создаётся только через контекстное меню** узла «Списки слежения» — ни в
главном меню, ни на панели такой команды нет:

```powershell
# выделить узел "Списки слежения", открыть меню, взять единственный пункт
Invoke-UmClick -X $pn.X -Y $pn.Y -SleepMs 900
Send-UmKeys "+{F10}" 1300
Send-UmKeys "{DOWN}" 500
Send-UmKeys "{ENTER}" 2000
```

Появляется узел с именем по умолчанию `follow_list_0001`. Двойной клик по нему
открывает вкладку «Списки слежения: <имя>».

**Панель редактора списка:**

Добавить переменную · Удалить переменную · Режим отображения: (hex/dec) ·
Передвинуть переменную вверх · Передвинуть переменную вниз · **Экспорт** ·
Поиск + Найти.

Колонки: Имя · Тип · Значение · Комментарий.

**Формат на диске** — `varLists/varLists.json`, простой JSON:

```json
{
    "name": "Списки слежения",
    "varLists": [
        { "name": "follow_list_0001" }
    ]
}
```

Пустой список — это один объект с полем `name`. Правила имени те же, что у
проекта: латиница, цифры, подчёркивание, начинается с буквы, до 128 символов.

**Добавление переменной в список** (проверено кнопкой на панели списка):

Кнопка «Добавить переменную» открывает **модальное** окно «Добавление
переменной» с единственным полем «Название переменной». Нажимать её надо
обычным кликом, а не `InvokePattern` — `Invoke` на кнопке, за которой стоит
модальный диалог, зависает по таймауту и вешает весь обход UIA.

Дальше диалог ведётся клавиатурой:

```powershell
# фокус на диалог берём по его handle через Win32 (UIA сейчас заблокирован)
[W32]::SetForegroundWindow([IntPtr]$dlgHandle)
Send-UmKeys "g_pressure_out" 500   # имя переменной
Send-UmKeys "{TAB}" 400            # с поля на кнопку "Добавить"
Send-UmKeys "{ENTER}" 2000
```

`{ENTER}` прямо из поля ввода **не срабатывает** — поле забирает клавишу себе,
диалог остаётся открытым. Нужен именно `{TAB}` на кнопку.

В таблице списка появляется строка, где имя, тип, значение и комментарий
подтягиваются из словаря: `g_pressure_out · вещественный · 12.5000000 ·
Давление на выходе НПС`.

Второй путь, по руководству, — контекстное меню переменной в редакторе словаря,
пункт «Добавить в список слежения» с подменю списков (не проверялся).

### Состав списка не сохраняется в проекте

Проверено: добавили переменную, сохранили, закрыли и открыли проект заново —
**список остался, а переменная в нём исчезла**. Сходится тремя независимыми
способами:

- диф каталога проекта после сохранения — изменений нет;
- `grep follow_list` по всему каталогу находит только `varLists/varLists.json`,
  а там лежит одно лишь имя списка;
- в GUI после перезакрытия вкладка `follow_list_0001` открывается с пустой
  таблицей.

То есть хранится только **перечень списков**, а наполнение живёт в сессии.
Проверен и реестр: рекурсивный поиск по `HKCU\Software\TREI` не находит ни имён
переменных списка, ни `follow_list` — там лежат только ширины колонок
(`varListColumns`). Значит состав не сохраняется **нигде**, и планировать
«собрать список слежения скриптом и передать вместе с проектом» нельзя.

## Редактор FBD/LD

Открывается двойным кликом по программе, у которой `lang: fbd`. Создать такую
программу можно **файлами**, не трогая GUI, — см. `recipes.md`.

> **Схему тоже можно не рисовать.** `prog.json` со схемой принимается
> редактором как есть (проверено 2026-09-12). Рабочий путь, генератор
> `fbd_gen.py`, стандарт расположения и таблица симптомов — в `fbd-guide.md`.
> Ниже — рисование мышью: оно нужно для точечных правок и когда хочется
> посмотреть глазами.

**Панель редактора** (все кнопки именованы в UIA):

| Группа | Элементы |
|---|---|
| вид | показать нумерацию · показать координаты · увеличить шрифт · уменьшить шрифт |
| правка | отменить изменения · повторить изменения · удалить · вырезать · копировать · вставить |
| режим резинки (CheckBox) | Выделить · Раздвинуть · Сдвинуть |
| режим работы (CheckBox) | режим редактирования · режим соединения |
| контроль | проверить · очистить неиспользуемое из словаря |

**Палитра элементов** — вертикальная панель у правого края, каждый элемент
это `CheckBox` с именем:

Переменная · Константа · Структура · Структура с полями · Функция ·
Функциональный Блок · Дочерняя программа · Оператор · Метка · Прыжок · Шина ·
Соединение · Виток · Контакт

Ниже, отдельной группой, переключатели источника переменных:
Глобальный словарь · Локальный словарь.

**Панель «Добавить/Изменить» — это форма параметров элемента FBD.** Вот зачем

При выбранном инструменте «Константа» показывает три поля (тип элемента,

### Как рисовать схему (проверено 2026-09-12, пересмотрено 2026-09-13)

Всё, что ниже, автоматизировано в `assets/scripts/ui/fbd_lib.ps1`
(`Invoke-FbdPlace`, `Invoke-FbdLink`, `Set-FbdMode`, `Save-FbdProject`) и
`fbd_do.ps1`. Геометрия, механика кликов и таблица симптомов — в
`fbd-guide.md` → «Мышь: `fbd_lib.ps1`». Здесь — что происходит в редакторе.

**Обязательное условие: окно IDE закреплено поверх остальных окон**
(`Set-UmTopmost`) — иначе клики уходят в чужое окно.

**Сетка поля не зашита, а читается из полос прокрутки** схемы:
шаг клетки `sx = (Maximum + ширина поля) / column_max`, `sy` — так же по
вертикали через `line_max` (размер поля из `Define` схемы, обычно 500; IDE
принимает и 1000, и 5000 — клетка та же, полоса длиннее);
левый край блока `поле.X + sx·column − прокрутка`, строка k-го вывода
`поле.Y + sy·(line + k) − прокрутка`. При `Scale=2` клетка 16 × 24 px, при
`Scale=1` — 12 × 18, при `Scale=3` — 22 × 30. Прежняя формула
`663 + 15.96·column`, `218 + 23.5·line` была приближением и снята.

**0. Элементы без списка** (константа, метка, прыжок, шина, соединение) ставятся
перетаскиванием **значка-руки** «Применить в программе» из панели на клетку поля;
клик по значку ничего не делает. Тип берётся вторым комбобоксом («целая»,
«Левая  силовая шина», «Return», …), значение или имя набирается в поле ввода с
клавиатуры — `SetValue` туда не проходит. Автоматизировано в
`fbd_lib.ps1` → `Invoke-FbdPlaceHand` (проверено 2026-09-18).

**Типы констант в палитре:** булевская, целая, вещественная, таймерная,
строковая, байтовая, дв.точности. Байтовая даёт литерал `b#0`, дв.точности —
`d#0.0`.

**1. Добавить блок — перетаскиванием** из списка панели «Добавить/Изменить».
Клик по списку и клик по полю не работают. Точка отпускания — левый верхний
угол блока: `x = поле.X + sx·column + sx/4`,
`y = поле.Y + sy·(line − строк_заголовка) − sy/4` (у переменной заголовка нет,
у оператора и ФБ одна строка). Так блок встаёт ровно в заданную клетку.
- **Оператор** — палитра «Оператор», категория раскрывается стрелкой, пункт
  называется полностью: `Сложение (+)`.
- **ФБ из словаря** — палитра «Функциональный Блок», источник «из Словаря»,
  раскрыть экземпляр (`_TON_1`) и тащить **дочерний узел метода** `TON`.
  Сам экземпляр не перетаскивается.
- Комбобоксы панели переключаются только кликом по пункту раскрытого списка
  (`Select-FbdCombo`).

**2. Переместить блок** — та же протяжка, начиная с тела блока. Смещение
точки захвата сохраняется: взяли на 3 клетки правее левого края — блок встанет
на 3 клетки левее цели.

**3. Удалить блок** — в режиме редактирования клик по заголовку блока (кнопки
«удалить» и «вырезать» становятся активными), затем `Invoke` на «удалить».
Кнопка отмены называется «отменить  изменения» (два пробела) и откатывает
последнее действие, в том числе связь.

**4. Провести связь.** Включить «режим соединения» **кликом мыши** — режимы
взаимоисключающие, «режим редактирования» выключится сам. Дальше два клика по
выводам **в любом порядке**; клик — внутри блока, в 0,6 клетки от края, на
строке вывода. Выбранный вывод помечается пурпурной точкой, клик по пустому
месту выбор снимает. Условия: типы данных совпадают, на вход — одна связь
(выход можно ветвить), переменная может питать другую переменную. Трасса
прокладывается сама, в том числе на большие расстояния; между двумя кликами
поле можно прокрутить — выбор сохраняется. **Проведённая связь не попадает в
модель IDE**, пока после неё не будет правки блока: у вкладки нет « *»,
сохранение пишет схему без связи, код ST её не видит (проверено 2026-09-14).
После серии связей — перенос любого блока туда и обратно (`Submit-FbdLinks`).

**5. Удалить связь** — в режиме **редактирования** кликнуть по линии (кнопка
«удалить» станет активной) и нажать «удалить».

**6. Проверить схему.** «Сборка → Редактор → Проверить программу» (**Ctrl+F9**)
или кнопка «проверить» панели редактора — ошибки с координатами блоков в
клетках схемы; «Сборка → Редактор → Вывести код на ST» — схема текстом на
вкладке «Вывод». Пока есть неподключённые блоки, код не выводится. Подменю
«Редактор» доступно только при активной вкладке схемы. Если `ui_menu.ps1` не
видит подменю, кликать по координатам развёрнутого окна 2560×1334:
«Сборка» (218,49) → «Редактор» (289,146) → «Вывести код на ST» (570,176).

**7. Сохранить** кнопкой «Сохранить проект» (`Save-FbdProject`) — сохранение
синхронное, к возврату из `Invoke` файл уже записан. Перед этим зафиксировать
связи (`Submit-FbdLinks`; `fbd_do.ps1 save` делает всё сразу). **После
сохранения сверить файл** (`Assert-FbdFile` или `fbd_dump.py`): при двух блоках
одного экземпляра ФБ IDE сохраняет схему без единой связи и не сообщает об этом.
Правка мышью (перенос, удаление, новый блок) перенумеровывает порядок
выполнения по расположению — правило в `fbd-guide.md` → «Порядок выполнения».

### Палитра: чем ставится и что получается в файле (проверено 2026-09-12)

| Элемент палитры | Как ставить | Что в `Blocks[]` |
|---|---|---|
| Переменная | тащить из списка словаря | `type 0`, `dict 0`, `mode 4` |
| Константа | задать тип данных и значение, тащить **значок-руку** | `type 1`, `subtype 0`, `name` = значение |
| Структура | источник → тащить из списка | `type 12`, один вход и один выход |
| Структура с полями | источник → тащить из списка | `type 2`, выводов по числу полей |
| Функция | источник → тащить из списка | `type 15` |
| Функциональный Блок | источник → узел метода под экземпляром | `type 3`, имя `<экземпляр>.<ФБ>` |
| Дочерняя программа | тащить из списка | `type 16` |
| Оператор | категория → пункт; на 3+ входа — спиннер «Входы» стрелками и значок-рука | `type 4`, `subtype` 0/1, `args` при 3+ входах |
| Метка | значок-рука | `type 9`, имя пустое, выводов нет |
| Прыжок | выбрать цель (Return или метку), значок-рука | `type 10`, `name` — цель |
| Шина | выбрать левую или правую, значок-рука | `type 5`, `subtype` 0 левая (3 выхода) / 1 правая (3 входа) |
| Виток | выбрать вид, тащить **булеву** переменную из списка | `type 7`, `subtype` 0..5 |
| Контакт | то же | `type 8`, `subtype` 0..3 |

**Источник** для функции, ФБ и структур — второй комбобокс панели: «из
Библиотеки Проекта», «из Библиотеки Системы», «из Словаря». Третий комбобокс —
куда положить переменную экземпляра («Локальный»/«Глобальный Словарь»).

**Категории операторов** и все токены — в `fbd-guide.md` → «Каталог операторов».

**Контекстное меню схемы** (правый клик; в UIA не видно, окно `Unimod`, 14
пунктов одинаковой высоты): Изменить · Добавить комментарий · Добавить eni-eno ·
Удалить eni-eno · Удалить · Вырезать · Копировать · Вставить · Вставить аналог ·
Инвертировать · Раскомментировать · Закомментировать · Автоматически · Изменить
цвет. Действует на выделенное: «Инвертировать» — на выделенную связь,
«Добавить eni-eno» — на ФБ, «Закомментировать» — на блок или связь,
«Добавить комментарий» — на пустое место. Панель «Свойства» для элементов
схемы пустая. Автоматизация — `Invoke-FbdContextMenu` в `fbd_lib.ps1`.

**Оператор на 3+ входа.** В панели «Добавить/Изменить» у выбранного оператора
есть спиннер «Входы: 2». `SetValue` через UIA значение показывает, но не
фиксирует; стрелки спиннера меняют по-настоящему, но перетаскивание пункта
списка сбрасывает спиннер на 2. Работает так: кликнуть пункт, стрелками
выставить число входов, тащить **значок-руку** «Применить в программе».
Файлом проще: `Scheme.op('AND', 4, …)` пишет `args: 4`.

**В эмуляции схема показывает живые значения** прямо на выводах блоков — для
проверки глазами словарь открывать не обязательно.

**Виды витка:** прямой · инвертированный · (N) · (P) · (R) · (S).
**Виды контакта:** прямой · инвертированный · (N) · (P).

Правила, на которых теряется время:

1. **Элементы без списка** (константа, метка, прыжок, шина) тащат за
   **значок-руку** рядом с надписью «Применить в программе» — элемент, чьё
   `Name` содержит «Применить в программе», точка захвата — левый край + 14 px.
   Тащить сам значок палитры бесполезно.
2. **Виток и контакт принимают только BOOL.** С вещественной переменной
   перетаскивание молча ничего не делает.
3. **ФБ и структуры из системной библиотеки заводят экземпляр сами**:
   перетащили `BLINK` — в локальном словаре появились `_BLINK_1` и все его поля.
4. **Один экземпляр ФБ — один блок.** Узел экземпляра второй раз не
   перетаскивается, а узел метода — перетаскивается, и это ловушка: при
   сохранении пропадают все связи программы (см. known-issues). Для второго
   блока нужен новый экземпляр.
5. **Точку отпускания держать внутри видимого поля.** Бросок, при котором
   точка вне поля или блок не помещается, молча игнорируется.

Проверено целиком: цепочка `переменная → := → переменная` дала
`local_var_0001 := ( local_var_0001 ) ;` и собралась в `app/project.app`.
Формат хранения схемы — в `file-format-notes.md`.

Пустая FBD-программа сборке не мешает: проект с такими программами собирается
без ошибок.

## Дерево конфигурации: контроллер, сеть, модули (гл. 7.1–7.2)

Живёт в нижней левой панели **«Контроллеры и коммуникации»** (вкладка внизу с
тем же именем). Верхняя панель — «Программы и данные» — это другое дерево, в
обеих корень называется именем проекта, поэтому `ui_do.ps1 -Name "<проект>"`
даёт **два** совпадения: `-Index 0` — дерево программ, `-Index 1` —
конфигурация.

Состав дерева (тип мастер-модуля M501E):

```
<проект>
├── Загрузка/отладка проекта
│   └── Подключение к PLC_1            — гл. 7.1
├── Контроллеры
│   └── PLC_1                          — гл. 7.2
│       ├── Параметры резервирования   — 7.2.2
│       ├── Сетевые настройки          — 7.2.3
│       ├── Параметры режима выполнения— 7.2.4
│       ├── Аппаратная конфигурация    — 7.2.5
│       └── Модули ввода/вывода        — 7.2.6
│           ├── Линия связи (порт ST-BUS 1)
│           └── Линии связи M101SN
├── Внешние коммуникации               — гл. 7.3
└── OPC-сервера                        — гл. 7.4
```

**Раскрыть всё поддерево одним движением:** **двойной** клик по корню и затем
`{MULTIPLY}` (звёздочка на numpad). Одиночного клика мало — проверено: после
него `{MULTIPLY}` не срабатывает, фокус клавиатуры не доходит до дерева. Это стандартное сокращение Qt-дерева, оно
раскрывает всю ветку разом — иначе узлы приходится разворачивать по одному, а
UIA не показывает детей нераскрытого узла вообще.

```powershell
& "$ui\ui_do.ps1" -Name "<проект>" -Type TreeItem -Index 1 -Action dblclick
[System.Windows.Forms.SendKeys]::SendWait("{MULTIPLY}")
Start-Sleep -Milliseconds 2000
& "$ui\ui_read.ps1" -What tree -NoFocus
```

Форма настройки открывается **одиночным кликом** по узлу и занимает центральную
область. Снимать её удобно регионом `660,150,1420,900`.

### Куда какая форма пишет

| Раздел дерева | Файл | Ключи |
|---|---|---|
| Подключение к PLC_1 | **`settings.ini`**, секция `[connectionPLC]` | `1\IpAddress`, `1\port`, `1\typeSocket` (0=TCP, 1=SSL), `1\mtu`, `1\repeatCount`, `1\ansverTimeout`, `1\privateKey`, `1\privateCertificate`, `1\publicCertificatesPath` |

| Сетевые настройки | там же | `net_mode`, `net_eth1..4` и `_res`/`_1`, `net_netMask1..4`, `net_gateway`, `net_mrpWakeup`, `remoteAccess_web`, `remoteAccess_webProtocol`, `remoteAccess_ftp`, `remoteAccess_telnet`, `ethComponents[]` (порт, протокол, фрейм) |
| Параметры режима выполнения | там же | `watchdogTime`, `runModeParam_saveRes`, `runModeParam_maxSystemEvents`, `runModeParam_ftt`, `runModeParam_maxTimeoutRequest`, `runModeParam_isEnergySaving` |

Проверено: ввод IP на форме и `Ctrl+Shift+S` меняют ровно строку
`1\IpAddress=` в `settings.ini`.

### Что видно на формах

- **Подключение к PLC_1:** IP-адрес, Транспорт (TCP/SSL), Номер порта. Кнопка
  **«Расширенные опции»** (обычный `Invoke`) доразворачивает Размер фрейма,
  Количество повторов, Время ожидания ответа.
- **PLC_1:** Название ПЛК, **Тип мастер-модуля**, Комментарий и справочная
  панель «Основная информация» со сводкой LAN1–LAN4 и IP-портов; ссылки
  «настроить» ведут в соответствующие разделы дерева.
- **Параметры резервирования:** при `Без резервирования` все поля ниже
  неактивны. Таблица «Файлы зеркализации» с кнопками «Добавить» / «Удалить
  выделенные»; имя файла задаётся как `/unimod/usr/<имя>.<расш>`.
- **Сетевые настройки:** по группе на каждый LAN, в каждой кнопки `+` / `-`
  для добавления IP-адресов и поле маски.
- **Параметры режима выполнения:** Watchdog (мс), Энергонезависимое хранение
  (жёстко «С меткой "хранить"»), Максимальное число системных событий. Красная
  подпись предупреждает, что Watchdog влияет на задачи МКО по ST-NET(S).
- **Аппаратная конфигурация:** режим порта ST-BUS 1, режим порта RS-485/422/232
  (COM1) и четыре юнита с типом (Не используется / UCOM2 / USTB) и режимом.
- **Линия связи:** интерфейс и протокол недоступны для правки (всегда «Порт
  ST-BUS» и «ST-BUS(N)»), настраиваются время ожидания, число обращений,
  пауза, смещение адресов и скорость. Внизу сворачиваемый «Список подключённых
  модулей ввода/вывода».

Выпадающий список на форме PLC_1 (значение пишется в `typeMaster`):

### Модули ввода-вывода добавляются НЕ в дереве конфигурации

Дерево конфигурации здесь только показывает результат. Форма раздела «Линии
связи …» прямо пишет: «Для добавления элементов используйте контекстное меню в
окне "Контроллеры и коммуникации"», а руководство (7.2.6.2) описывает
единственный рабочий путь: **добавить в глобальный словарь переменную с типом
модульной структуры** — после этого модуль появляется в дереве конфигурации
как вложенный элемент линии связи. Адрес модуля и период опроса правятся на
панели «Свойства» при выделенной переменной в глобальном словаре, а удаление
модуля = смена типа переменной на немодульный или удаление переменной.

Список доступных модульных структур: **«Библиотека → Модули ввода-вывода»** или
кнопка на панели быстрого доступа — открывается вкладкой «Библиотека модулей»
(имя, версия, описание). Постфикс `_vX` — версия аппаратной конфигурации
(прошивки) модуля, а `_x2` — сдвоенный вариант. Состав структуры: блоки `in` /
`out` (рабочие данные, обмен каждый цикл), `statistic` / `param` (служебные,
пишутся однократно при старте), `control` (управление обменом, одинакова у всех
модулей: `not_valid`, `err_cfg`, `block_poll` и т. д.).

### Рецепт: добавить модуль ввода-вывода (проверено полностью)

Модуль добавляется **только через глобальный словарь**. Проверено на `M558O_v2`
(32-канальный дискретный вывод): после сохранения модуль появился в дереве
конфигурации как `1. M558O_v2 (mod1)` под линией связи, а проект собрался —
`BUILD OK`.

```powershell
$ui = "…\assets\scripts\ui"
. "$ui\ui_lib.ps1"

# 1. открыть глобальный словарь
& "$ui\ui_do.ps1" -Name "Глобальный словарь" -Type TreeItem -Action dblclick

# 2. создать переменную
& "$ui\ui_do.ps1" -Name "Добавить переменную" -Type Button -Action invoke
Send-UmKeys "^a" 150; Send-UmKeys "mod1" 300; Send-UmKeys "{ENTER}" 900

# 3. открыть список типов В ЯЧЕЙКЕ «Тип» (координаты ячейки первой строки)
Show-UmWindow | Out-Null
Invoke-UmClick -X 937 -Y 265 -SleepMs 700
Send-UmKeys "{F2}" 1300

# 4. допрыгнуть до нужной структуры набором префикса и кликнуть по ней
Send-UmKeys "M558O" 1000
$scale = Get-UmScale
$t = @(Get-UmAllElements -MaxDepth 12 |
       Where-Object { $_.Type -eq 'ListItem' -and $_.X -gt 0 -and $_.Name -eq 'M558O_v2' })[0]
$p = Get-UmClickPoint -Element $t.Element -Scale $scale
Invoke-UmClick -X $p.X -Y $p.Y -SleepMs 1200

# 5. ЗАКРЫТЬ редактор ячейки и только потом сохранять
Send-UmKeys "{ESC}" 800
& "…\assets\scripts\unimod_save.ps1"
```

Три вещи, на которых это ломается:

1. **`{ENTER}` после выбора типа снова открывает редактор ячейки.** Закрывать
   надо `{ESC}`. Если сохранить с открытым редактором, строка не зафиксируется:
   в первый раз `tags/global.csv` остался пустым (один заголовок), хотя тип на
   экране уже был выбран и строка подсветилась зелёным.
2. **Список типов в ячейке виртуализирован** — UIA отдаёт ровно 20 видимых
   пунктов, а модульных структур в списке сотни. Набор префикса (`Send-UmKeys
   "M558O"`) прокручивает список к нужному месту, после чего искомый пункт
   попадает в число видимых и по нему можно кликнуть. Набор длинной строки
   целиком (`"M1231TR_v1"`) тоже работает — Qt накапливает символы и выделяет
   точное совпадение, но UIA при этом продолжает показывать верхние видимые
   элементы, так что по дампу кажется, будто поиск промахнулся. Ориентироваться
   надо на снимок, а не на список имён.
3. **Промах мимо элемента может открыть модальный диалог.** Клик по фиктивным
   координатам `(0, …)` попал в панель «Выбор режима» и вызвал окно «Для
   выполнения данного действия необходимо закрыть текущий проект». Пока оно
   висит, весь ввод глотается, `{F2}` не открывает список, а UIA возвращает
   пустоту. Симптом «список не открылся» — повод сделать снимок и поискать
   диалог, а не менять координаты.

Что появляется после добавления модуля:

| Файл | Что происходит |
|---|---|
| `tags/global.csv` | одна модульная переменная разворачивается в **дерево из ~110 строк**: `mod1`, `mod1.control.*`, `mod1.statistic.*`, `mod1.param.*`, `mod1.in.*`, `mod1.out.*` (167 байт → 12 284) |
| `tags/global.var` | 26 байт → 13 672: словарь перестаёт быть пустым |
| `tags/base.csv` | 1 659 → 9 040: все каналы модуля получают смещения |
| `configuration.json` | в `communicationLines[0].modilesIO` добавляется запись модуля |
| `types/io/module1.lib`, `types/io/module1.xml` | описание модульной структуры копируется в проект |

Строка корневой переменной в `global.csv`:

```
mod1;U;1;M558O_v2;5;;0;;false;0;;;;;;false;;;;;32-канальный дискретный вывод
```

то есть `Type=U` (структура), `ADDR_MOD=1` — **адрес модуля на линии связи**,
`Library=M558O_v2` — имя модульной структуры, `Length=5` — число блоков-детей.
Адрес и период опроса правятся на панели «Свойства» при выделенной переменной.
Проверено, что показывает панель «Свойства» (справа) для выделенной модульной
переменной: Имя · Тип · кнопка **«Изменить тип»** · Адрес модуля
(логический) · Адрес модуля (физический, недоступен) · Контроллер · Линия
связи. Строки модульной переменной в словаре подсвечены **зелёным**,
переменные МКО — **жёлтым**; в колонке «Значение» у модуля пишется
`Адрес (логич.): 1 | …`, у переменных МКО — `МКО: 1`.

Осторожно: `{RIGHT}` в колонке «Имя» у структурной строки **раскрывает**
строку, а не сдвигает текущую ячейку вправо. Рецепт `{RIGHT}`+`{F2}` для
смены типа работает только у простой (нераскрываемой) переменной.

### Флажок в заголовке группы: только `TogglePattern`

Формы «NTP» и «OPC-сервер контроллера» включаются флажком в заголовке рамки
(checkable QGroupBox). В UIA такой флажок — `CheckBox` размером **со всю
рамку** (у NTP 728×296), поэтому клик по центру попадает в поле внутри рамки
и ничего не переключает. Переключать через паттерн:

```powershell
$cb = @(Get-UmAllElements -MaxDepth 14 | Where-Object { $_.Type -eq 'CheckBox' -and $_.Name -eq 'NTP' })[0]
$tp = $cb.Element.GetCurrentPattern([System.Windows.Automation.TogglePattern]::Pattern)
$tp.Toggle()                    # Off -> On
$tp.Current.ToggleState         # проверка
```

Все дочерние элементы такой рамки UIA называет **именем рамки** и отдаёт как
`Group`: кнопка «Добавить IP адрес NTP» видна как `[Group] 'NTP'` размером
~182×34. Искать её приходится по размеру и положению, а не по имени.

### Комбобоксы формы: пункты не кликаются по координатам UIA

У выпадающих списков **на формах конфигурации** UIA отдаёт `ListItem` с
координатами вида `(0, 19·N)` и шириной 640 — это не экранные координаты, а
раскладка ещё не показанного popup'а. Клик по ним попадает в левый край экрана
и молча не делает ничего (проверено дважды на «Типы данных в редакторе»).
Отличать так: у настоящего раскрытого списка `X > 0` и окно в дампе
называется `Unimod`, а не `Unimod PRO 2: <проект>`.

Рабочий способ — клавиатура: кликнуть по самому комбобоксу (его UIA отдаёт с
верными координатами), затем `{DOWN}`×N и `{ENTER}`. Список типов **в ячейке
словаря** ведёт себя иначе — там координаты настоящие (см. раздел про
редактирование ячеек).

## Внешние коммуникации и OPC (гл. 7.3–7.4)

Ветка «Внешние коммуникации» в том же дереве конфигурации:

```
Внешние коммуникации          форма: «используйте контекстное меню»
├── Межконтроллерный обмен    форма: размер фрейма TREINET (8000)
│   └── 1 (Ethernet-res)      связь Treinet
├── Modbus
│   ├── Modbus-RTU Master
│   ├── Modbus-RTU Slave
│   ├── Modbus-TCP Master
│   │   └── 1 Modbus          связь
│   │       └── Modbus-запросы   таблица запросов, кнопки + / -
│   ├── Modbus-TCP Slave      форма: макс. соединений на порт, время удержания
│   └── Modbus-UDP Master     в руководстве не описан
├── MЭК-104 (Slave)           форма: «Добавить задачу» / «Удалить»
│   └── Группы переменных     общий адрес ASDU, таблица групп, кнопки + / -
│       └── Группа 1          переменные группы
├── NTP                       флажок NTP, таймауты, режим, «Добавить IP адрес NTP»
└── OPC-сервер контроллера    флажок и семь опций
OPC-сервера
└── Новый OPC-сервер 1        имя, IP, порт, три пути к ключам
```

Внимание: в имени узла `MЭК-104 (Slave)` первая буква **латинская `M`**, а
не кириллическая `М`. Поиск по `"МЭК-104 (Slave)"` с кириллицей ничего не
найдёт.

**Как добавлять** (везде `Shift+F10` на узле раздела, пункт выбирать стрелками):

| Что | Где | Пункты меню |
|---|---|---|
| Связь Modbus | узел любого из пяти разделов Modbus | «Добавить связь Modbus» — единственный |
| Связь Treinet | «Межконтроллерный обмен» | «Добавить связь Treinet» · «Экспорт…» · «Импорт…» |
| Задача МЭК-104 | форма узла «MЭК-104 (Slave)» | кнопка «Добавить задачу» (кликом) |
| Группа МЭК-104 | форма «Группы переменных» | кнопка `+` |
| Запрос Modbus | форма «Modbus-запросы» | кнопка `+` |

Кнопки `+` / `-` на формах имеют имена `'+'` и `'-'` — их находит
`ui_do.ps1 -Name "+" -Type Button`.

**Связь МКО: переменные создаются с формы.** Рядом с полями «Структура данных
МКО» и «Диагностическая структура» — кнопки «Выбрать из словаря» и «Добавить в
словарь». Вторая сама заводит переменную в **глобальном словаре** и сразу
привязывает её к связи — это быстрее, чем создавать переменную в словаре
вручную. Обе открывают **модальный диалог**, поэтому нажимать кликом мыши (не
`Invoke` — он зависнет), а в диалоге работать только клавиатурой:

```powershell
# кнопки идут сверху вниз: [0] — данные, [1] — диагностика
$btns = @(Get-UmAllElements -MaxDepth 16 |
          Where-Object { $_.Type -eq 'Button' -and $_.Name -eq 'Добавить в словарь' } | Sort-Object Y)

# диагностика: диалог с одним полем, по умолчанию «var_MKO_DIAG_» (выделено)
$b = Get-UmClickPoint -Element $btns[1].Element -Scale $scale
Invoke-UmClick -X $b.X -Y $b.Y -SleepMs 1800
Send-UmKeys "^a" 200; Send-UmKeys "mko1_diag" 400; Send-UmKeys "{ENTER}" 2000

# данные: диалог «Тип переменной» (комбобокс, по умолчанию первая структура
# проекта) + «Имя переменной»; фокус на типе, в имя — через Tab
$b = Get-UmClickPoint -Element $btns[0].Element -Scale $scale
Invoke-UmClick -X $b.X -Y $b.Y -SleepMs 1800
Send-UmKeys "{TAB}" 400; Send-UmKeys "mko1_data" 400; Send-UmKeys "{ENTER}" 2000
```

Имя переменной — не длиннее 22 символов, латиница, цифры, `_`. Пока открыт
такой диалог, `Get-UmRoots` его **не показывает** отдельным окном — проверять
его наличие только снимком.

**Отключить связь без удаления:** контекстное меню связи Modbus содержит
«Отключить/Задействовать» (галочка = включена) и «Удалить связь Modbus`  Del`».
Отключённая связь не проверяется при сборке — так можно оставить в проекте
недозаполненную связь.

Новая связь Modbus появляется сразу с одним запросом по умолчанию и названием
`Modbus`; связь Treinet — с портом 8001 и нулевыми адресами. **Собрать проект
с незаполненной связью нельзя** — что именно нужно заполнить, см.
`known-issues.md`, «Пустая коммуникационная задача ломает сборку».

Что куда пишется в `configuration.json` — `file-format-notes.md`, разделы про
Modbus, МКО/МЭК-104 и OPC-сервер контроллера.

**Меню «Инструменты»** (снято `ui_menu.ps1 -ListOnly`): Поиск · Карта адресов
modbus · CRC функциональных блоков · Сравнение проектов · Безопасность ·
Экспорт/импорт · Настройки. Подменю «Экспорт/импорт»: Экспорт базы тегов ·
Экспорт карты modbus регистров модулей ввода-вывода · Импорт проекта Unimod PRO
1.xxx · Импорт файла структуры проекта · Экспорт файла структуры проекта ·
Импорт структуры BACnet устройства · Импорт ST программ с диска · Сформировать
бинарный описатель…

**Карта адресов modbus** (проверено): открывается вкладкой в центральной
области. Сверху комбобокс типа регистра (Coil / Discrete input / Input register
/ Holding register) и кнопка «Обновить», под ним 8 кнопок-страниц `0..1fff`,
`2000..3fff`, … `e000..ffff` (по 8192 адреса), ниже таблица «Адрес ·
Переменная · Тип · Комментарий» на 65 536 строк с адресами в hex (`0x0001`…).
Двойной щелчок по занятой строке переводит к переменной в словаре. Карта только
показывает — адреса назначаются в словаре (колонка «Адрес modbus»).

**Экспорт карты modbus регистров модулей** (проверено): создаёт в каталоге
проекта `export/moduleN_modbus.csv` — по файлу на модуль, `N` = адрес модуля.
Файл в **CP1251**, CRLF, заголовок
`Имя;Тип;Тип регистра modbus;Адрес modbus (dec);Комментарий`. Если модулю не
назначены modbus-адреса, в файле **только заголовок** (60 байт) — ошибки нет.
После экспорта всплывает информационный диалог «Файлы сохранены в каталог
C:/CLAUDE~1/…» с единственной кнопкой OK — закрывать `{ENTER}`. Путь в нём
короткий (8.3), потому что так проект был открыт.

**Недоступно без внешних программ:** «Отладка → Чтение конфигурации
OPC-сервера» и «Загрузка конфигурации OPC-сервера» требуют запущенной службы
«Trei Opc Configuration server»; раздел «База абонентов» появляется в дереве
только после успешного чтения. Не проверялось.

## Эмуляция и отладка (гл. 8)

Эмуляция — виртуальный контроллер внутри IDE, железо не нужно. Условие —
**успешная сборка** (без неё кнопка «Эмуляция» неактивна).

**Включение.** Надёжный способ — кнопка **«Эмуляция» на левой панели выбора
режима**: в UIA это `CheckBox` с именем `'   Эмуляция  '` (с пробелами),
состояние читается `TogglePattern`:

```powershell
$cb = @(Get-UmAllElements -MaxDepth 12 | Where-Object { $_.Type -eq 'CheckBox' -and $_.Name -match 'Эмуляция' })[0]
$p  = Get-UmClickPoint -Element $cb.Element -Scale $scale
Invoke-UmClick -X $p.X -Y $p.Y -SleepMs 4000
$cb.Element.GetCurrentPattern([System.Windows.Automation.TogglePattern]::Pattern).Current.ToggleState   # On
```

Повторный клик — выход из эмуляции. Пункт меню «Отладка → Эмуляция» тоже
работает, но при втором заходе в той же сессии `ui_menu.ps1` его не нашёл
(прошёл только «Отладка») — кнопка панели надёжнее. Признаки запуска: в
«Выводе» строка `[чч:мм:сс.ммм] Эмулятор запущен.`, при выходе — `Эмулятор
остановлен.`; кнопка «Эмуляция» подсвечена, кнопки «Сборка» и «Загрузка»
гаснут.

**Редакторы открывать ДО входа в эмуляцию.** В режиме эмуляции дерево
«Программы и данные» заблокировано (серое): узлы не раскрываются ни двойным
кликом, ни `{RIGHT}`/`{MULTIPLY}`, UIA видит только корень. Открытые заранее
вкладки (словарь, ST-редактор) продолжают работать и показывают живые значения.

**Что видно в словаре в эмуляции.** Колонка «Значение» — текущие значения
**красным**, обновляются сами (снимки с интервалом 5 с показывают разные
числа). Имена и типы серые, кнопки `-`, «вверх», «вниз», «отмена» неактивны —
менять можно только значения. Структурная строка раскрывается кликом по имени
и `{RIGHT}`.

**Навигация по словарю в эмуляции — только клавиатура.** Клик мышью по строке
текущую строку не меняет (так же, как в режиме проекта). Рабочая цепочка:
клик в таблицу, чтобы отдать ей фокус, → `{HOME}` (первая строка) →
`{DOWN}`×N → на структурной строке `{RIGHT}` раскрывает её:

```powershell
Invoke-UmClick -X 760 -Y 265 -SleepMs 600      # любая строка таблицы — только ради фокуса
Send-UmKeys "{HOME}" 300
for ($k = 0; $k -lt 14; $k++) { Send-UmKeys "{DOWN}" 120 }   # t1 — 15-я строка
Send-UmKeys "{RIGHT}" 1200                      # раскрыть t1
```

В раскрытой структуре у полей стрелки направления: зелёная `→` — вход
(атрибут 1), красная `←` — выход (атрибут 2). Булевы значения выводятся
**синим** (`false`/`true`), числа — красным, у вещественных 7 знаков после
запятой.

`{RIGHT}{RIGHT}` + `{F2}` на поле структуры редактор значения **не открыл**, а
набранный следом текст ушёл в поиск по строкам (текущая строка перескочила) —
значение не изменилось. Так значения в эмуляции не пишутся. Двойной клик
мышью по ячейке (как в руководстве) — тоже нет: синтетические клики эта
таблица не принимает.

**Рабочий способ записи значения — `ValuePattern.SetValue` на ячейке.**
Каждая ячейка словаря в UIA — отдельный `TreeItem` с паттернами
`Invoke, Value, GridItem, TableItem`; у ячейки колонки «Значение» `Name` —
это текущее значение (`'1.5000000'`), `IsReadOnly = False`. Ни фокус, ни
текущая строка для этого не нужны:

```powershell
# ячейка «Значение» нужной строки: колонка x≈1013 (900..1300), строка — по Y
$cell = @(Get-UmAllElements -MaxDepth 20 | Where-Object {
          $_.Type -eq 'TreeItem' -and $_.X -gt 900 -and $_.X -lt 1300 -and [math]::Abs($_.Y - 337) -lt 6 })[0]
$cell.Element.GetCurrentPattern([System.Windows.Automation.ValuePattern]::Pattern).SetValue("2.5")
# проверка: через ~1 с Name ячейки = '2.5000000'
```

Проверено: `AMP_M` 1.5 → 2.5 дошло до виртуального контроллера — амплитуда
уровня выросла, сработали обе аварии. **Читать** значения тем же способом
удобнее, чем снимками: `Name` ячейки «Значение» — готовое число. Нужную
ячейку проще всего искать по Y строки (ячейки одной строки имеют одинаковый
Y, колонка «Имя» — X≈693, «Тип» — X≈863, «Значение» — X≈1013).

`SetValue` работает **только для колонки «Значение»**. На ячейке «Тип» (в
режиме проекта) вызов проходит без ошибки, но тип не меняется — у колонки
редактор-список. Тип менять через список ячейки (см. раздел про ячейки
словаря и рецепт добавления модуля).

**Результаты проверки на `tank_sim`** (значения читались из ячеек UIA):

- «Выполнение по циклам» — `n_cycle` замер (9033 держался 3 с);
- **F8** («Выполнить один цикл») — ровно один цикл: `t_s` 3.2948 → 3.3948 →
  3.4948. В основном режиме F8 неактивна;
- «Основной режим выполнения» — счёт возобновился;
- «Останов приложения» — `n_cycle` замер (9175 держался 3 с), эмулятор при этом
  не выключается;
- «Переинициализация приложения» — **видимого эффекта на переменные нет**:
  ни `n_cycle`, ни `init_done`, ни изменённый вручную `AMP_M` не сбросились, в
  «Выводе» записи нет. Что она делает — не выяснено;
- «Установить время цикла» и «Сброс времени цикла» — не проверялись.

Команды управления циклом в «Вывод» ничего не пишут — судить об их действии
можно только по значениям.

**Скорость эмулятора не привязана к реальному времени:** при периоде задачи
100 мс набегало от ~9 до ~20 циклов в секунду в разные моменты. Время модели
(`t_s += CYCLE_S`) считается по циклам, поэтому в эмуляции оно течёт не с
реальной скоростью — на правильность логики это не влияет, но секундомером её
не проверить.

**Значения в редакторе ST — подсказкой при наведении** (проверено): над именем
переменной всплывает `имя=значение`, например `n_cycle=755`. Подсказки
**нет в UIA** (элементов `ToolTip` не находится) — только снимок. Нужен
настоящий сдвиг курсора: первое наведение `SetCursorPos` сразу после
переключения окна подсказку не вызвало, второе (курсор переехал с одного
слова на другое) — вызвало. Надёжнее ставить курсор рядом, а затем на слово.
Редактировать текст ST в эмуляции нельзя.

**Повторный вход в эмуляцию — холодный старт.** Выход и новый вход
перезапускают приложение с начальных значений словаря: `n_cycle` пошёл заново,
записанный вручную `AMP_M = 2.5` вернулся к `1.5`. Значения, записанные в
эмуляции, в проект не попадают (файлы не меняются) и переживают только
текущий сеанс эмуляции. Чтобы открыть ещё один редактор, приходится выходить
из эмуляции — и терять накопленное состояние.

**Что эмуляция пишет в проект:** в `settings.ini` добавляется секция
`[Emulate]` с `Watchdog=3000`. Больше ничего.

## Библиотеки (гл. 10)

**Системная библиотека** — «Библиотека → Системная библиотека» или кнопка
`'Системная библиотека'` на панели быстрого доступа. Открывается вкладкой в
центральной области: поле «Поиск:» (`Edit` без имени, ~(744,173)) и кнопка
«Найти», ниже дерево с колонками «Имя · Тип · Атрибут · Комментарий». Узлы
верхнего уровня — ФБ и функции (ADDM, AGA8_92, AI_GA, …, BLINK, CTU, …,
SIN_GEN, …), раскрываются в список входов/выходов.

- Список длинный и **виртуализирован**: UIA отдаёт только видимые строки
  (при открытии — 27 блоков). Нужный блок искать не прокруткой, а поиском:
  ввести имя в поле и нажать «Найти» — дерево прокрутится к блоку и сделает его
  текущим (он окажется у нижнего края).
- Двойной клик по имени блока открывает **редактор имени ячейки** — сразу
  `{ESC}`. Раскрывать блок — `{RIGHT}` (после поиска он текущий), затем
  `{DOWN}`×N, чтобы прокрутить его поля в видимую область.
- Сама библиотека лежит **вне каталога IDE**, в профиле пользователя:
  `%APPDATA%\TREI\UnimodPRO2\library\types\types.json` — обычный JSON на
  ~132 МБ (`version` 118, ключи `last_uid`, `sys_arrays`, `sys_struct_defs`).
  Рядом `types.u2lib` — тот же `types.json` в зашифрованном ZIP. В каталоге IDE
  имена блоков встречаются только внутри `ucc.dll` и `Unimod.exe` — поиск по
  каталогу IDE библиотеку не находит, это ловушка. Подробности формата — в
  `file-format-notes.md`. Описание блоков — в «Руководстве по программированию»
  (`doc/Unimod_PRO_2_Programming_Manual.pdf`, «Системные функциональные блоки»)
  и частично в `library/docs/sys/*.html`.

**Как использовать системный ФБ (проверено на `SIN_GEN`):**

1. В словаре программы добавить переменную и выбрать ей тип блока через список
   ячейки «Тип» (клик по ячейке + `{F2}`, набрать префикс `SIN_GEN`, кликнуть
   пункт) — как модульную структуру. `SetValue` на ячейке «Тип» не работает.
   Можно и файлом: экземпляр пишется в CSV словаря как экземпляр структуры
   (`file-format-notes.md`, «Экземпляр системного ФБ в словаре»).
2. Вызвать из ST как метод: `gen1.SIN_GEN(true, PERIOD_S, 0.0);` — входы
   позиционно в порядке полей (`RUN, T, F`), выход — `gen1.Y`. «Проверка» и
   сборка проходят.
3. Состав входов/выходов смотреть на вкладке системной библиотеки (раскрыть
   блок) или в `library/types/types.json` (`lib_struct_<ИМЯ>`).

В эмуляции `gen1.Y` совпал с `SIN(2π·t/60)` той же программы (разница ~10⁻³,
отставание на один цикл). При пошаговой отладке — ловушка с временем цикла
3000 мс, см. `known-issues.md`.

**Пользовательская библиотека** — вкладка «Пользовательская библиотека» внизу
левой панели: кнопки «Сохранить», «Экспорт», «Импорт» и дерево «Имя ·
Комментарий».

- **Добавление:** контекстное меню структуры в дереве «Программы и данные»
  (`Shift+F10` на узле структуры) — пункты: Удалить · Копировать · Вставить ·
  Найти использование · Свойства · **Добавить в пользовательскую библиотеку**
  (6-й, `{DOWN}`×6 + `{ENTER}`) · Переименовать. Структура сразу появляется в
  дереве панели, заголовок панели получает `*`.
- **«Сохранить»** (кнопка панели, X<640, не путать с кнопкой панели
  инструментов) пишет библиотеку в
  **`Documents\UnimodPRO2\_userlib\structs.json`** (каталог создаётся при
  первом сохранении) — и **одновременно кладёт побайтную копию в каталог
  открытого проекта под именем `av`**. Этот `av` — мусор в проекте, его
  стоит удалять перед архивацией.

  (*.json)», кнопка «Открыть»). Диалог — отдельное окно: `Show-UmWindow` его не

- Функции в пользовательскую библиотеку этим путём не добавляются (в меню
  функции такого пункта нет в видимой части).

## Безопасность проекта (гл. 11)

**Всё — только на одноразовой копии проекта.** Пароль однопользовательского
режима не восстанавливается, после 3 неверных вводов проект блокируется.

Меню «Инструменты → Безопасность»: Выбор режима проекта (подменю: Открытый ·
Однопользовательский · Защищенный) · Настройка политик безопасности ·
Настройка учетных записей · Настройка журналирования · Смена пароля.
Подменю видно в UIA, но закрывается между вызовами — проходить путь целиком
одним `ui_menu.ps1`:

```powershell
& "$ui\ui_menu.ps1" -Path "Инструменты","Безопасность","Выбор режима проекта","Однопользовательский"
```

**Диалог «Редактирование учетной записи»** (модальный): логин (предзаполнен
`user`), «Пароль», «Повторите пароль», неактивный список роли «Единственный
пользователь», кнопки «Применить» (по умолчанию) / «Отмена». Это отдельное
окно верхнего уровня — активировать по заголовку через Win32
`EnumWindows` + `SetForegroundWindow`, `Show-UmWindow` его не активирует.
Текст — **только через буфер обмена** (раскладка может быть русской, тогда
`SendKeys "lab"` напечатает кириллицу):

```powershell
function Paste($t) { Set-Clipboard -Value $t; Send-UmKeys "^a" 150; Send-UmKeys "^v" 350 }
Paste "lab"; Send-UmKeys "{TAB}" 300; Paste "Lab12345"; Send-UmKeys "{TAB}" 300; Paste "Lab12345"
Set-Clipboard -Value " "          # не оставлять пароль в буфере
# проверить снимком, затем {ENTER} = «Применить»
```

После «Применить» IDE ничего не показывает; изменения ложатся в `usr.cfg` при
сохранении (`file-format-notes.md`, раздел про `usr.cfg`).

**После любой смены режима следующая смена заблокирована до переоткрытия
проекта.** Переход «однопользовательский → открытый» пароля не спрашивает,
показывает окно «Изменен режим проекта» («…необходимо закрыть и заново
открыть проект», кнопка OK), и после этого в подменю «Выбор режима проекта»
активен только «Открытый» — «Однопользовательский» и «Защищенный» серые, клик
по ним ничего не делает. Порядок: сменить режим → сохранить → закрыть IDE →
открыть проект заново → следующий шаг.

**Что видит администратор защищённого проекта** (вход `admin`, проверено):
корень дерева «Программы и данные» серый и не раскрывается в редакторы,
кнопки «Сохранить» и «Сохранить проект» на панели инструментов неактивны,
«Сборка», «Загрузка», «Отладка», «Эмуляция» на панели режимов неактивны —
доступна «Диагностика». То есть администратор настраивает безопасность, но
проект не правит и не собирает, как и сказано в руководстве.

**Диалог «Настройка политик паролей»** («Инструменты → Безопасность →
Настройка политик безопасности», только в защищённом режиме, модальный):
«Минимальная длина пароля» (счётчик, 8), группа «Состав обязательных

op1 / Функции:»), кнопки «Добавить», «Удалить», «Редактировать»,
«Блокировка». «Добавить» (UIA `Invoke`, не зависает) открывает тот же диалог
«Редактирование учетной записи»: «Имя пользователя», «Пароль», «Повторите
пароль», список ролей (активен, в нём роли из вкладки «Роли»), «Применить».
Заполнение — как в однопользовательском режиме, через буфер обмена.
Сам диалог «Настройка пользователей» закрывать `WM_CLOSE` по его окну.

**Диалог «Журналирование событий безопасности»** («Инструменты →
Безопасность → Настройка журналирования»): флажки «Записывать события
безопасности в файл» и «Записывать события безопасности в Syslog», группа
«Параметры Syslog» — IP-адрес, Транспорт (TCP/…), Номер порта; «Применить» /
«Отмена». Флажки — `TogglePattern` (найти `CheckBox` по `*в файл*`), затем
Win32-активация окна и `{ENTER}`. Ключи в `usr.cfg`: `siemIsLinuxFile`,
`siemIsSyslog`, `siemSyslogIp`, `siemSyslogTypeSocket`, `siemSyslogPort`.

**Где на самом деле журнал.** Руководство обещает файл `unimod_siem` в
каталоге проекта — его там нет. IDE пишет события в
**`%USERPROFILE%\Documents\UnimodPRO2\data\log_siem\unimod_siem.log`** — один
файл на все проекты этого пользователя Windows. Записи появлялись в
защищённом режиме **и до включения флага** «Записывать… в файл»; судя по
имени ключа (`siemIsLinuxFile`), флаг относится к файлу на стороне
контроллера/Linux, а не к этому журналу. Формат — в `file-format-notes.md`.

**Открытие защищённого проекта** — окно **«Введите учетные данные»** поверх
заставки: «Имя пользователя», «Пароль», «Вход» (по умолчанию) / «Отмена».
Открывать только `assets/scripts/unimod_open_secure.ps1`:

```powershell
.\unimod_open_secure.ps1 -Project <каталог> -Exe <Unimod.exe>                      # только дойти до окна входа
.\unimod_open_secure.ps1 -Project <каталог> -Exe <Unimod.exe> -Login lab -Password Lab12345 -Fill
```

Обычный `unimod_open.ps1` для такого проекта **нельзя**: он жмёт Enter в
любом окне и потратит попытку входа.

## Работа с контроллером (гл. 6.3, 6.5, 8.1, 9)

Контроллера не было, поэтому всё ниже проверено **только до ошибки
подключения**: вместо ПЛК — `127.0.0.1` (порт 6000 свободен, отказ приходит
меньше чем за 1,5 с). Всё, что происходит после успешного подключения,
описано по руководству и помечено **(не проверено на железе)**.

**Правило для этого раздела.** В любое поле адреса — `127.0.0.1`, пока
пользователь сам не назвал адрес своего контроллера. Во всех окнах адрес по
умолчанию `192.168.1.1` (часто это роутер), а кнопка по умолчанию — действие,
а не «Отмена». Порт проверять перед запросом:
`Get-NetTCPConnection -LocalPort 6000 -State Listen` должен быть пуст.

### Режим диагностики

Вход — CheckBox «Диагностика». Дерево проекта и кнопки «Сборка», «Загрузка»,
«Отладка», «Эмуляция» с панели исчезают, остаются «Проект» и «Диагностика».
Выход — CheckBox «Проект». Проект при этом остаётся открытым.

Вкладка **«Диагностика: опрос модулей»**:

| Элемент | UIA | Примечание |
|---|---|---|
| «Абонент (IP-адрес мастер-модуля):» | `ComboBox` + вложенный `Edit` (y≈164) | редактируемый, по умолчанию `192.168.1.1`; `SetValue` на `Edit` работает; история — реестр `recentDiagIPList` |
| «Порт:» | `Spinner` | 6000 |
| «Опросить» | `Button` | запускает опрос |
| **«Broadcast»** | `Button` | широковещательный поиск по локальной сети, в руководстве не описан — **не нажимать** |
| «Опрошено адресов: N/255» | `Text` + прогресс-бар | |
| Таблица | колонки Адрес, Тип модуля, Комментарий, Состояние, Версия ПО, Серийный номер, Аппаратная версия платы, Дата изготовления, Контрольная сумма ПО | до опроса все 256 строк «Неизвестный / Не опрошен» |

Опрос `127.0.0.1` → окно **«Подключение»**: «Не удалось подключиться к
мастер-модулю. Проверьте кабель и настройки» [OK]. Этого окна **нет** в
`Get-UmRoots` — закрывать через Win32 (`EnumWindows` по заголовку
`Подключение` → `PostMessage(WM_CLOSE)`). Счётчик после этого 1/255, файлы
проекта не меняются.

Контекстное меню строки таблицы (правый клик; пункты видны в UIA как
`MenuItem`): **«Диагностика»**, **«Внесение ошибок»**. Второго пункта в
руководстве нет; по названию — внесение неисправностей в модуль. **Не
нажимать** без пользователя. У опрошенного модуля, по руководству, там же
«Конфигурация» и «Обновление прошивки». Двойной клик по неопрошенной строке
ничего не открывает.

**Дальше — по руководству (не проверено на железе).**

Мастер-модуль: двойной клик по строке → вкладка с индикаторами режима,
ошибок мастер-модуля, динамических ошибок, кодами запуска и сброса; вкладки
«Периферия» (MODE-переключатели, Ethernet, DI/DO, питание, температура,
SD-карта), «Статистика» (время, часовой пояс, время цикла, наработка),
«Версия ПО»; журнал системных событий по 100 записей на страницу с фильтром
по группам. Кнопки: «Установить время» (+ «Синхронизация времени с
компьютером»), «Сброс времени цикла» (обнуляет максимальное время цикла),
«Запуск», «Останов приложения», «Сброс приложения» (останов + перезапуск),
«Экспорт» (всё в текстовый файл), «Обновить ОС» (`*.osfirmware`),
«Обновить ИС» (`*.firmware`), «Обновить КК» (`*.stmfirmware`,
коммуникационный контроллер ST-BUS).

Код режима работы мастер-модуля: 0 — инициализация, 1 — исполнение,
2 — конфигурирование (приложения нет или ошибка), 3 — отладка по циклам,
4 — обновление проекта, 5 — пробный запуск (резервирование), 6 — передача
проекта на резервный, 7 — откат изменений, 8 — запуск на резервном,
9 — синхронизация рабочих данных, 10 — режим загрузчика.

| MODE | Положение «On» |
|---|---|
| 1 | холодный старт: без восстановления сохранённой базы, модули сбрасываются |
| 2 | не запускать исполнительную систему — только ОС и сеть |
| 3 | признак резервного: старт с задержкой до 10 с |
| 4 | игнорировать сетевые настройки пользователя, адреса по умолчанию |
| 5 | резервированный режим |
| 6 | STOP / технологический режим: приложение остановлено |

Загрузку можно запретить из приложения: `system(52, 1)` — индикатор
«Установлен запрет загрузки приложения» красный; снять — `system(52, 0)` или
запуск в технологическом режиме (MODE:6).

Модуль ввода-вывода: двойной клик или «Диагностика» → вкладка с модульной
структурой (каналы, параметры, состояние); «Конфигурация» — параметры модуля;
правый клик по каналу → «Метрология» → «Калибровка тока» / «Калибровка
напряжения» (только чтение); «Обновление прошивки» (`*.firmware`). Любое
обновление перезагружает модуль, питание отключать нельзя — **только
пользователь**. Не более 255 модулей за опрос, до конца опроса диагностика
отдельных модулей недоступна, кнопка «Прервать» останавливает опрос.

### Чтение с контроллера

- **«Прочитать проект»** при открытом проекте → окно «Для выполнения данного
  действия необходимо закрыть текущий проект» [OK] (видно в UIA). Сначала
  «Файл → Закрыть проект» (Alt+X). Дальше, по руководству (не проверено на
  железе): IP и порт → «Прочитать» → имя и каталог нового проекта → «OK».
  В ресурсах есть строки «Загрузка исходников приложения» и «Архив проекта не
  был загружен на контроллер»: читается архив исходников, который
  загружается в ПЛК вместе с приложением. Нет архива — нечего читать.
- **«Прочитать конфигурацию»** → окно **«Параметры»**: «IP-адрес ПЛК:»

  умолчанию**) / «Отмена». Оба поля — `Edit` с рабочим `SetValue`.
  `127.0.0.1` → то же окно «Подключение», файлы проекта не изменились.

### Отладка на контроллере и загрузка

Адрес берётся с формы «Загрузка/отладка проекта → Подключение к PLC_1»
(`settings.ini [connectionPLC]`).

- Пустой IP → окно «Подключение»: «Параметры подключения некорректны!
  Проверьте настройки на вкладке "Контроллеры и коммуникации" ->
  "Загрузка/отладка проекта"» [OK].
- С адресом → окно **«Подтвердите параметры подключения»**: Название ПЛК, IP,
  Тип транспорта, Номер порта; флажок «Не спрашивать до закрытия проекта»;
  «Продолжить» (по умолчанию) / «Отменить». Рамка главного окна в этот
  момент **жёлтая** — так IDE показывает режим отладки. «Продолжить» на
  `127.0.0.1` → «Не удалось подключиться к мастер-модулю…», режим
  возвращается в «Проект».
- Поля для ввода имени ПЛК в этом окне нет. Оно появится, если включить
  «Настройки IDE → Отладчик → Запрашивать подтверждение имени абонента…»
  (по умолчанию выключено). Эта защита от загрузки не в тот контроллер
  стоит того, чтобы предложить её пользователю.
- **Ввод адреса на форме — только настоящим вводом.** `SetValue` меняет
  текст, но форма его не принимает. Рабочая цепочка: клик в поле → `^a` →
  `^v` из буфера → `{TAB}`. И адрес с формы **молча** пишется в
  `settings.ini` при закрытии IDE — «закрыть без сохранения» здесь нет.

По руководству и строкам ресурсов `tracergui.dll` (не проверено на железе):
окно загрузки сравнивает «Приложение #1/#2 в контроллере» с «Загружаемым
приложением» — имя, номер и дата сборки, MD5 проекта, конфигурации ПЛК,
программ и словарей, тегов OPC; зелёный — совпадает, жёлтый — несущественные
отличия, красный — ошибка. Кнопка «Загрузить приложение»; при
резервировании — «Пошаговая загрузка», «Поменять режимы
(основной/резервный)», «Синхронизировать резервный мастер-модуль». Если имя
проекта в ПЛК другое — «Прервать загрузку?», и **продолжение — это «Нет»**.
Для отладки имя проекта обязано совпадать; если отличается только версия —
«Продолжить отладку?», и отлаживается приложение, уже лежащее в ПЛК.

## Опасные места

- В меню «Файл» пункт **«Удалить проект»** стоит сразу после «Закрыть проект»,
  а стрелки в меню останавливаются и на неактивных пунктах. Вслепую по меню
  не ходить — только по имени пункта.
- После **неуспешной сборки** первый диалог предлагает упаковать проект и
  отправить его разработчику по электронной почте, кнопка по умолчанию — «Да».
  Отвечать только `{ESC}`.
- **«Загрузка»** пишет приложение в контроллер. Без явного разрешения
  пользователя не нажимать.
- **Окна подключения к контроллеру** — «Параметры» чтения конфигурации,
  поле «Абонент» диагностики: адрес по умолчанию `192.168.1.1`, кнопка по
  умолчанию — «Прочитать» / «Продолжить». Enter = запрос к реальному
  устройству в сети. Для проверок — только `127.0.0.1`.
- **«Broadcast»** в режиме диагностики — широковещательный опрос локальной
  сети. Не нажимать.
- **В режиме диагностики на живом ПЛК** «Внесение ошибок», «Обновить
  ОС/ИС/КК», «Обновление прошивки», «Установить время», «Останов приложения»,
  «Сброс приложения» действуют на работающее оборудование — только по явной

- **Окно загрузки при другом имени проекта в ПЛК:** «Прервать загрузку?» —
  здесь продолжение загрузки — это «Нет». Не отвечать на автомате.
