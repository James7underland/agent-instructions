# Разбор модели «Олимпиадная схема.vsym» (Symmetry 2023.2)

Файл: `01.01. symmetry_model\Олимпиадная схема.vsym` (сохранён 21.11.2025, внутри кейс «20251117»), рядом —
`OPC_DA.XML` (теги OPC-сервера Symmetry) и `MB TCP tags.xlsx` (карта регистров Modbus для ПЛК ТРЭИ).
Оригинал не изменялся; разбор выполнен на копии (`Symmetry Claude\Работа\olymp\olymp.vsym`).
Картинки и данные — в папке `Разбор\` рядом: схема целиком и по частям (экспорт PFD из модели через Visio),
снимок Symmetry, графики и CSV динамики, окно сбоя интегратора.

## 1. Что это за объект
**Магистральный нефтепровод с двумя нефтеперекачивающими станциями и приёмным пунктом**, модель в
**динамическом режиме** (ActiveEngine = 2), предназначенная для связи с ПЛК через OPC DA → Modbus TCP.

```
вход (340 кПа) → 01LV-01 → 01Tank-01 (резервуар НПС-1)
  → ПНС-1: 3 подпорных насоса 01PNA-01…03 параллельно (задвижки 01GV-01…06)
  → узел 01LV-03…06 → МНС-1: 4 магистральных насоса 01MNA-01…04 ПОСЛЕДОВАТЕЛЬНО,
      у каждого: задвижки на входе/выходе (01GV-07…14) + обводная линия с обратным клапаном (01LV-08…11)
  → узел регулирования давления: 2 параллельные нитки 01LV-12/01PCV-01/01LV-13 и 01LV-14/01PCV-02/01LV-15
  → 01LV-16 → Pipe1 (186,5 км, Ø740×10, подъём +155,7 м)
→ НПС-2: фильтры 02F-01/02 (2 нитки) → 3 МНА 02MNA-01…03 последовательно (02GV-01…06, байпасы 02LV-05…07)
  → узел регулирования 02PCV-01/02 → 02LV-11 → Pipe2 (63,5 км, Ø550×10, подъём +111,4 м)
→ РП (приёмный пункт): 3 нитки (03LV-01 байпас, 03PCV-01, 03PCV-02) → фильтр 03F-01
  → резервуары 03Tank-01 и 03Tank-02 → отгрузка (M14 → output_stream-05, 101,3 кПа)
```
Состав модели: 73 клапана/задвижки (Valve), 10 насосов (PumpWithCurve), 16 делителей и 14 смесителей (узлы
трубной обвязки), 3 ёмкости (MultifeedSep2), 2 трубы (PipeSegment, 27 и 25 участков), 18 «регуляторов»
(на деле датчики), 10 энергопотоков, 4 калькулятора (Process Calculator).

## 2. Среда
Пакет свойств **Advanced Peng-Robinson**; 16 компонентов: 3 гипотетических (Hypo20000–20002, ≈91 % мольн. —
нефтяные фракции) + C1…nC9, вода, **сероводород** (~1,2 % мольн. на входе). Плотность ≈ 860 кг/м³ при 16 °C
(жидкость); на входе есть немного газа (доля пара 0,4 %).

## 4. КИП и управление
- **Все 18 «регуляторов» (01PT-01…11, 02PT-01/02, 03PT-01/02, 01LT-01, 03LT-01/02) — датчики**: режим Indicator/Off,
  выход OP ни к чему не подключён. Значения уставок (SP) и Kp/Ti заполнены (напр. 01PT-01 SP 636 кПа, 01PT-11
  SP 2500 кПа, 02PT SP 4000 кПа, 03PT SP 600 кПа, Kp 0,2–2, Ti 300–600 с), но в модели не работают.
  **Регулирование давления/уровня должен выполнять ПЛК** (двигая PCV, задвижки, включая насосы).
- Привязка датчиков: 01PT-01 — вход МНС-1; 01PT-02/03 — вход/выход 01МНА-01; 04/05 — 02; 06/07 — 03; 08/09 — 04;
  01PT-10 — выход МНС-1; 01PT-11 — выход НПС-1; 01LT-01/03LT-01/03LT-02 — уровни резервуаров. Совпадает с
  описаниями в таблице Modbus.
- **Калькуляторы** (4 шт., **работают**: `dir` показывает `Ignored = 1`, но фактическое значение `InternalVal = 0`;
  проверено 2026-09-27 — запись 37 в `VLV_Opening_Percent…B12.Val_Num` сразу даёт `01GV-07.%Opening = 37`):
  - `VLV_Opening_Percent` — столбец B связан с %Opening 18 арматур НПС-1 (01LV-03…06, 01LV-12…15, 01PCV-01/02,
    01GV-07…14) — сюда ПЛК **пишет** степень открытия;
  - `VLV_Condition` — B = % открытия тех же арматур, C = 1 при 100 % («открыто»), E = 1 при 0 % («закрыто») —
    ПЛК **читает** состояния;
  - `MNA_Parameters` — D = команда вкл/выкл МНА (1/0/1/0), B → `Switch` насоса, C → `PumpSpeed`;
  - `Liquid_Level` — «логика поддержания уровня»: если уровень входного/выходного резервуара < 40 % или > 60 %,
    вернуть 50 % (искусственное удержание уровня).

## 5. Связь с ПЛК
`OPC_DA.XML`: 104 тега (89 на запись) группы «aitec» → `MB TCP tags.xlsx`: адреса Modbus 0…204 (float = 2
регистра), чтение — функция 3 (массивы ТРЭИ `Symm_valve_read`, `Symm_pump_read`, `Symm_sensor_read`), запись —
функция 16 (`Symm_valve_write`, `Symm_pump_write`). **Охвачена только НПС-1** (арматура МНС и узла PCV,
4 МНА, датчики 01PT-01…11). НПС-2, РП и датчики уровня в обмен не входят.

## 6. Замечания / возможные ошибки в модели
1. ~~Калькуляторы выключены~~ — **ошибка первого разбора, исправлено 2026-09-27**: `Ignored = 1` в выводе движка —
   отображение по умолчанию у любого объекта (`InternalVal = 0` = работает). Запись в ячейку сразу передаётся в
   модель. Но **ячейка при чтении остаётся прежней (100)** — ПЛК должен читать фактическое положение
   (`01GV-07.%_Opening` или `VLV_Condition`), а не свою же ячейку записи.
2. `VLV_Condition.C2` (состояние 01LV-03): формула `=IF(B2=100;1;0))` — **лишняя скобка**; остальные строки
   записаны как `=IF(Bn=100,0;1,0;0,0)`. `E15` записана иначе (`=IF(B15=0;1;0)`) — по смыслу то же.
3. **01MNA-04 выключен (`Switch = Off`), но его задвижки 01GV-13/14 открыты** — через стоящий насос идёт
   ≈154 м³/ч параллельно обводному обратному клапану 01LV-11. То же у **02MNA-03** (≈103 м³/ч). На реальной НПС
   остановленный агрегат отсекается задвижками — стоит закрыть их (или это часть задания).
4. В `MNA_Parameters` частота задана только для 01MNA-04 (C6 = 3000), C3–C5 пустые.
5. Дубликат тега OPC `VLV_Opening_Percent.PCalcMgr.Sh1.B3.Value`.
6. Материальный баланс НПС-1 не сведён: поступает 908 т/ч, откачивается ≈1058 т/ч → уровень 01Tank-01 падает
   ≈1,1 %/ч (≈174 м³/ч).
7. Давление на входе РП 431 кПа ниже уставки 03PT (600 кПа) — при включённом регулировании PCV РП начнут
   прикрываться (подпор).
8. Обводные линии МНА (01LV-08…11, 02LV-05…07) — клапаны с `CheckValve = 1` (обратные клапаны): у работающих
   насосов перепад отрицательный, расход 0 — так и должно быть.
9. У всей арматуры привод `ActuatorType = Instantaneous` — задвижки/клапаны перемещаются мгновенно, без времени
   хода (для отработки алгоритмов ПЛК реалистичнее задать `Linear_Speed`/`Time_Constant`).

## 7. Поведение в динамике без управления
**Как сохранена, модель в динамике не считается дальше 25–50 с.** Интегратор останавливается с сообщением
`Composition Calculations Failed For /.Pipe2` (в GUI окно Integrator: «Composition Calcs Failed - See Log For Details»;
см. `Разбор\Сбой интегратора Pipe2.png`). Это воспроизводится и в GUI, и через движок; уменьшение шага (1 → 0,25 с)
не помогает. Причина: сохранённое внутреннее состояние Pipe2 не согласовано с потоками. Уже за первые 5 с расход
на выходе трубы подскакивает с 1058 до 1500–1700 т/ч при ≈1060–1180 т/ч на входе: труба «выливается» в РП, и
композиционный расчёт участков разваливается.

**Что помогает (проверено):** переинициализация динамики из стационара (`init / / SteadyState`; в GUI —
инициализация динамики из стационара) **плюс неявный метод интегрирования BDF2** (Integrator → Settings →
Integration Method = BDF2). Только переинициализация (Euler) — сбой на 88 с. Только BDF2 — сбой на 39 с.
Вместе — устойчиво 300+ с (≈15 мин расчёта; модель тяжёлая, 3–5 с реального времени на 1 с модели).

Результат 300 с без управления (`Разбор\Динамика 300 с без управления.png/.csv`):
| Величина | t = 0 | t = 300 с |
|---|---|---|
| P выхода НПС-1, кПа | 4572 | 4474 |
| P входа НПС-2, кПа | 2201 | 1615 (продолжает падать) |
| P выхода НПС-2, кПа | 4314 | 3679 |
| P входа РП, кПа | 431 | 464–475 (всплеск до 708 на 140 с) |
| G через Pipe1, т/ч | 1058 | 1191 (растёт) |
| G через Pipe2, т/ч | 1058 | ≈1240 |
| Уровень 01Tank-01 / 03Tank-01, % | 42,28 / 50,41 | 42,28 / 50,45 (ёмкости огромные) |

Вывод: без регуляторов схема за 5 мин не приходит к равновесию — участок НПС-1 → Pipe1 разгоняется,
давление на входе НПС-2 падает (к 300 с ≈1,6 МПа, тенденция сохраняется). Для работы стенда с ПЛК нужно:
замкнуть регулирование давления (PCV по 01PT-11/02PT/03PT) и держать BDF2.

## 8. Что сделать перед использованием (рекомендации)
1. Integrator → Integration Method = **BDF2**; при старте — переинициализировать динамику из стационара.
2. Калькуляторы включены (проверено) — отдельно ничего делать не нужно.
3. Исправить `VLV_Condition.C2` (лишняя скобка); удалить дубликат тега B3 в `OPC_DA.XML`.
4. Закрыть задвижки остановленных агрегатов (01GV-13/14 у 01MNA-04, 02GV-05/06 у 02MNA-03) или учесть перетоки.
5. При желании — время хода арматуры (`ActuatorType`/`Linear_Speed`) для реалистичной отработки ПЛК.
