# 09. Структуры, объединения, битовые поля

## Структуры
```c
struct point { int16_t x; int16_t y; };
struct rect  { struct point min; struct point max; };   /* nesting is fine */
```
- Со структурой как с целым можно: присваивать и копировать, передавать в функцию и возвращать из неё (по значению),
  брать адрес, обращаться к полям. **Сравнивать через `==` нельзя.**
- `p->x` — то же, что `(*p).x`. Скобки нужны, потому что `.` старше `*`.
- `++p->len` увеличивает `len`, а не `p`: `->` старше `++`.
- Большие структуры передавай через `const struct cfg *`, чтобы не копировать их на маленький стек.
- Самоссылка допустима только через указатель: `struct node { int v; struct node *next; };`.

**Правило:** сравнивать структуры — поле за полем. `memcmp` не годится: в структуре есть байты выравнивания
(padding) с мусором.

## Размер и выравнивание
Размер структуры **не равен** сумме размеров полей. Компилятор вставляет пропуски, чтобы каждое поле было
выровнено, и добивает конец так, чтобы массив таких структур тоже был выровнен. Точный размер даёт только `sizeof`.

```c
struct bad  { uint8_t a; uint32_t b; uint8_t c; };  /* typically 12 bytes */
struct good { uint32_t b; uint8_t a; uint8_t c; };  /* typically 8 bytes  */
```
**Правило (МК):** в экономичных структурах располагай поля от больших к маленьким. Так экономится RAM.

**Ловушка (МК):** отправлять структуру «как есть» в UART, по сети или писать во flash. Раскладка, padding
и порядок байт зависят от компилятора и платформы, другая сторона прочитает не то.
`__attribute__((packed))` — расширение GCC. Оно приводит к невыровненному доступу: на ESP8266 это
медленно или вообще исключение, если взять адрес поля. **Правило:** для обмена данными сериализуй поля
вручную, байт за байтом (см. `read_le32` в `06-pointers-arrays.md`).

## Инициализация
```c
struct uart_cfg { uint32_t baud; uint8_t data_bits; uint8_t stop_bits; };
static const struct uart_cfg cfg = { .baud = 115200, .data_bits = 8, .stop_bits = 1 };  /* (C99) */
struct uart_cfg tmp = { 0 };   /* all members zero */
```
Поля без инициализатора равны 0. **(C99)** Назначенные инициализаторы `.поле = значение` — лучший выбор:
они не зависят от порядка полей.

## Массивы структур
Параллельные массивы (`char *name[N]; int count[N];`) лучше заменить одним массивом структур.
Число элементов даёт `sizeof tab / sizeof tab[0]`, считать вручную не нужно.

## Объединения (union)
Все члены начинаются с одного адреса. Размер равен размеру наибольшего члена с учётом выравнивания.
Читать можно тот член, который последним записывали. Чтение другого члена — это type punning:
в C99 TC3 и C11 он допустим, но результат зависит от представления (порядок байт, формат `float`).
В C++ это UB.

**Правило:** рядом с `union` храни метку, какой член сейчас действителен (tagged union):
```c
typedef enum { VAL_INT, VAL_FLOAT, VAL_STR } val_kind_t;
typedef struct {
    val_kind_t kind;
    union { int32_t i; float f; const char *s; } u;
} value_t;
```
Инициализировать `union` без назначенного инициализатора можно только значением **первого** члена.

**Гарантия общей начальной последовательности:** если несколько структур в `union` начинаются
одинаковыми полями (например, `type`), это общее начало можно читать через любую из них.

## Битовые поля
```c
struct flags {
    unsigned int ready  : 1;
    unsigned int error  : 1;
    unsigned int mode   : 3;
};
```
Удобны для **внутренних** флагов: экономят память, а код получается понятным (`f.ready = 1;`).

**Почти всё в битовых полях определяет реализация:** порядок полей в слове, пересечение границы слова,
знаковость `int`-поля, размер «слова». Взять адрес поля (`&f.ready`) нельзя.

**Ловушка (МК):** описывать **регистры периферии** битовыми полями. Раскладка непереносима, а запись одного поля —
это чтение-модификация-запись всего слова. Для регистров с битами «запись 1 сбрасывает флаг» (W1C) это
случайно сбросит соседние флаги. Кроме того, такая операция не атомарна относительно прерываний.
**Правило:** регистры — только через `volatile`-указатель и маски (см. `10-bit-operations.md` и скилл `embedded-c`).

**Ловушка:** `int flag : 1;` может хранить только 0 и -1, если `int`-поле знаковое. Пиши `unsigned int`
или **(C99)** `_Bool`/`bool`.
