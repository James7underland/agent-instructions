# 08. Массивы указателей, указатели на функции, сложные объявления, typedef

## Массивы указателей
`char *lines[N]` — N указателей на строки. Чтобы переставить строки, переставляют указатели, а не текст:
это быстро и не требует копирования. Так же устроены таблицы имён и `argv`.

`argc`/`argv`: `argv[0]` — имя программы, `argv[argc] == NULL`. На МК аргументов командной строки нет,
но разбор команд по UART устроен так же: строка режется на токены, и получается массив указателей.

## Указатели на функции
Имя функции в выражении превращается в указатель на неё, так же как имя массива. `&` писать не обязательно.
Вызов: `fp(x)` или `(*fp)(x)`, это одно и то же.

```c
typedef void (*event_handler_t)(uint8_t event);   /* name the type once */

static void on_press(uint8_t e)   { (void)e; /* ... */ }
static void on_release(uint8_t e) { (void)e; /* ... */ }

static event_handler_t handlers[] = { on_press, on_release };

void dispatch(uint8_t event)
{
    if (event < ARRAY_LEN(handlers) && handlers[event] != NULL) {
        handlers[event](event);
    }
}
```
**Применение на МК:** таблицы обработчиков команд, callback-функции драйверов, конечные автоматы
на таблице переходов, «интерфейсы» модулей через структуру из указателей на функции.

**Ловушка (UB):** вызывать функцию через указатель **несовместимого** типа. В K&R `strcmp` приводят к
`int (*)(void *, void *)` и так передают в свой `qsort` — формально это UB. **Правило:** сигнатура
callback-функции должна точно совпадать с типом указателя. Для стандартного `qsort` пиши обёртку с
`const void *`-параметрами и приводи типы внутри неё:
```c
static int cmp_u16(const void *a, const void *b)
{
    uint16_t x = *(const uint16_t *)a;
    uint16_t y = *(const uint16_t *)b;
    return (x > y) - (x < y);          /* no overflow, unlike x - y */
}
```
**Ловушка:** `return x - y;` в функции сравнения переполняется для больших `int`, поэтому сравнивай явно.

**Ловушка:** вызов по нулевому или неинициализированному указателю на функцию на МК — это прыжок по адресу 0
и сброс. Перед вызовом проверяй на `NULL`.

## Как читать сложные объявления
Правило «по спирали» или «справа налево от имени»: начни с имени, сначала читай то, что справа
(`[]` — массив, `()` — функция), потом то, что слева (`*` — указатель), учитывая скобки.

| Объявление | Читается как |
|---|---|
| `int *p[10]` | `p` — массив из 10 указателей на `int` |
| `int (*p)[10]` | `p` — указатель на массив из 10 `int` |
| `int *f(void)` | `f` — функция, возвращающая указатель на `int` |
| `int (*pf)(void)` | `pf` — указатель на функцию, возвращающую `int` |
| `void (*tbl[4])(int)` | `tbl` — массив из 4 указателей на функции `void(int)` |
| `const char *s` | указатель на **константные** символы: `s` менять можно, `*s` нельзя |
| `char *const s` | **константный указатель**: `s` менять нельзя, `*s` можно |
| `volatile uint32_t *const REG` | константный указатель на volatile-регистр (МК) |

**Правило:** сложное объявление собирай по шагам через `typedef`. Спецификатор `const` пиши рядом с тем,
к чему он относится.

## typedef
`typedef` не создаёт нового типа, он даёт новое имя существующему. Зачем он нужен:
1. переносимость: заменил одну строку `typedef` — и тип сменился во всей программе (`size_t`, `uint32_t`);
2. читаемость сложных типов, особенно указателей на функции.

Синтаксис такой же, как у объявления переменной, только впереди `typedef`: `typedef unsigned long ticks_t;`.

**Правило:** не прячь указатель за `typedef` у обычных данных (`typedef struct node *NodePtr;`).
Так пропадает `*`, и неясно, где нужен `const` и `->`. Исключение — указатели на функции.
Суффикс `_t` зарезервирован POSIX. В прошивках его используют повсеместно, это допустимо,
но будь готов к коллизиям имён.
