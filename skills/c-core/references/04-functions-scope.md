# 04. Функции, области видимости, классы памяти, заголовки

## Функции и прототипы
- Программа на C — это набор определений функций и переменных. Функции нельзя вкладывать друг в друга.
- **Прототип** объявляет тип результата и типы параметров: `int power(int base, int n);`.
  Имена параметров в прототипе не обязательны, но служат документацией.
- С прототипом компилятор проверяет число и типы аргументов и сам приводит их к нужному типу
  (`sqrt(2)` передаст `2.0`).
- Без прототипа функция считается возвращающей `int`, а аргументы проходят «продвижение по умолчанию»:
  `char` и `short` становятся `int`, `float` становится `double`. **(C99)** Неявное объявление запрещено, но многие
  компиляторы выдают только предупреждение. Считай его ошибкой.

**Правило:** у каждой функции должен быть прототип до первого вызова. Для публичных функций он лежит в `.h`,
для внутренних это `static` в начале `.c` или определение выше места использования.

**Ловушка:** `int f();` в C (до C23) значит «аргументы **неизвестны**», а не «без аргументов».
Проверка аргументов при этом отключена. Для функции без параметров пиши `int f(void);`.

**Ловушка:** функция определена в одном файле как `double atof(char *)`, а вызывается в другом без прототипа.
Вызывающий код считает, что результат `int`, и берёт мусор. Прототип в общем `.h`, который подключён
**и** в файле с определением, ловит такое расхождение при компиляции.

## Возврат значения
`return выражение;` приводит значение к типу функции. Функция, объявленная с результатом, но «упавшая» с конца
без `return`, возвращает мусор. Если вызывающий использует это значение, это UB. Флаг `-Wreturn-type` входит в `-Wall`.

**Правило:** возвращай код ошибки или статус, а результат отдавай через указатель. Так делает `scanf`.
Сигнал ошибки не должен совпадать с допустимым результатом.

```c
/* Returns 0 on success, negative error code otherwise; result via out-pointer. */
int adc_read_mv(uint8_t channel, uint16_t *out_mv);
```

## Передача аргументов
В C всё передаётся **по значению**: функция получает копию. Чтобы изменить переменную вызывающего,
передают её адрес. Массив передаётся как указатель на первый элемент, копирования нет.
Структура передаётся копией, поэтому большие структуры передавай через `const T *`.

## Внешние переменные, `extern` и `static`
- **Определение** выделяет память (`int count;` вне функций). **Объявление** только сообщает тип (`extern int count;`).
- Определение у внешнего объекта должно быть **ровно одно** на всю программу. Объявлений может быть сколько угодно.
- `static` на уровне файла означает внутреннюю связь (internal linkage): имя видно только в этом `.c`.
  Так скрывают данные и вспомогательные функции модуля.
- `static` внутри функции делает переменную постоянной: она живёт всю программу, инициализируется один раз
  и видна только внутри функции.
- `register` — устаревшая подсказка. Она ничего не даёт, но запрещает брать адрес `&`. Не используй.

**Правило (модульность):** всё, что не нужно другим модулям, объявляй `static`.
Глобальные переменные, видимые из нескольких файлов, — крайняя мера. Нужна связь между модулями —
делай функции доступа.

**Ловушка:** `int buf[64];` в заголовке, который подключают два `.c`, — это два определения.
Результат — ошибка компоновки «multiple definition» или, хуже, тихая склейка common-символов в старых GCC.
В `.h` пиши `extern`, определение — в одном `.c`.

**Ловушка (МК):** локальная переменная функции-обработчика, которую ты хочешь сохранять между вызовами,
должна быть `static`. Иначе она будет мусором при каждом входе.

## Заголовочные файлы
Заголовок — это контракт модуля: прототипы, типы, константы, `extern`-объявления.
Каждый `.c` подключает **свой** `.h` первым, чтобы проверить, что определения совпадают с объявлениями.
Заголовок сам подключает всё, что ему нужно, и защищён include guard (см. `05-preprocessor.md`).

```c
/* counter.h */
#ifndef COUNTER_H
#define COUNTER_H
#include <stdint.h>
void     counter_reset(void);
void     counter_tick(void);
uint32_t counter_get(void);
#endif

/* counter.c */
#include "counter.h"
static uint32_t s_count;          /* hidden state, zero-initialized */
void counter_reset(void) { s_count = 0; }
void counter_tick(void)  { s_count++; }
uint32_t counter_get(void) { return s_count; }
```

## Блочная структура и затенение
Переменная, объявленная в блоке, скрывает одноимённые внешние переменные до конца блока.
**Правило:** не называй локальные переменные так же, как внешние. Флаг `-Wshadow` предупреждает об этом.

## Инициализация
- `static` и внешние объекты: инициализатор должен быть константным выражением. Выполняется один раз,
  до старта программы. Без инициализатора объект равен 0.
- Автоматические объекты: инициализатор может быть любым выражением и выполняется при каждом входе в блок.
  Без инициализатора там мусор.
- Массив: `int d[] = {31, 28, 31};` — размер считается сам. Если инициализаторов меньше, чем элементов,
  остальные элементы равны 0. Больше — ошибка.
- `char s[] = "abc";` — массив из 4 байт (с `'\0'`).
- **(C99)** Назначенные инициализаторы: `struct cfg c = { .baud = 115200, .parity = 0 };`,
  `int t[8] = { [3] = 1 };`. Они понятнее и не ломаются, если поменять порядок полей.

## Рекурсия
Каждый вызов получает свой набор автоматических переменных на стеке.
**Ловушка (МК):** стек маленький (у `loop()` на ESP8266 около 4 КБ, на AVR — сотни байт).
Рекурсия неограниченной глубины и большие локальные массивы приводят к переполнению стека,
а это «случайные» перезагрузки. **Правило:** на МК избегай рекурсии или строго ограничивай её глубину.
Большие буферы делай `static` или глобальными.
