# 02. Операторы, неявные преобразования, приоритеты, порядок вычисления

## Арифметика
`+ - * / %`. Целочисленное деление отбрасывает дробную часть. `%` работает только с целыми.
**(C99)** Деление округляется к нулю: `-7/2 == -3`, `-7%2 == -1`. В C89 и в K&R это зависело от реализации.

**Правило:** в формулах вида «сначала умножить, потом разделить» умножай первым и следи,
чтобы произведение не переполнилось.
**Ловушка:** `c = 5/9 * (f - 32)` всегда 0, потому что `5/9 == 0`. Правильно `5 * (f - 32) / 9` или `5.0f/9.0f`.
**Ловушка:** деление на 0, `INT_MIN / -1` и `INT_MIN % -1` — это UB. На МК часто нет даже исключения,
просто получается мусор.

## Неявные преобразования (самое важное для МК)
1. **Целочисленное продвижение (integer promotion):** `char`, `short`, `uint8_t`, `uint16_t`, битовые поля и `enum`
   в любом выражении сначала превращаются в `int`, если `int` вмещает все их значения, иначе в `unsigned int`.
2. **Обычные арифметические преобразования:** операнды разных типов приводятся к общему типу.
   Порядок такой: `long double` > `double` > `float` > (после продвижения) `unsigned long` > `long` > `unsigned` > `int`.
   Если у операндов одинаковый ранг, но разная знаковость, побеждает **беззнаковый**.
3. При присваивании значение приводится к типу левой части. Лишние старшие биты отбрасываются.
   Если значение не влезает в знаковый тип, результат зависит от реализации.
4. Преобразование `float` → целое отбрасывает дробную часть. Если результат вне диапазона — **UB**.

**Ловушка 1: знаковое сравнивается с беззнаковым.**
```c
int      n   = -1;
unsigned len = 10;
if (n < len) { /* NOT taken: n is converted to 0xFFFFFFFF */ }
```
Флаг `-Wextra` (`-Wsign-compare`) предупреждает об этом. Лечится приведением к общему знаковому типу
или проверкой `n < 0` отдельно.

**Ловушка 2: `~` и сдвиги на узких типах.**
```c
uint8_t a = 0x0F;
if (~a == 0xF0) { /* NOT taken: ~a is int 0xFFFFFFF0 */ }
if ((uint8_t)~a == 0xF0) { /* taken */ }
```

**Ловушка 3: переполнение `uint16_t * uint16_t` там, где `int` 32-битный.**
```c
uint16_t x = 0xFFFF;
uint32_t y = x * x;              /* UB: both promoted to signed int, 0xFFFE0001 overflows int */
uint32_t z = (uint32_t)x * x;    /* OK */
```

**Ловушка 4: умножение выполняется в типе операндов, а не в типе результата.**
```c
uint32_t us = ms * 1000;          /* if ms is 16-bit int on AVR: overflow before widening */
uint32_t us_ok = (uint32_t)ms * 1000u;
```

**Правило:** в выражениях с разными типами явно приводи к целевому типу **до** операции.
Смешанных знаковых и беззнаковых операндов избегай. Сборка с `-Wall -Wextra -Wconversion`
показывает большинство таких мест.

## Отношения и логика
`> >= < <=` старше, чем `== !=`, а они старше `&&`, который старше `||`.
Результат сравнения — `int` 0 или 1. «Истина» в условии означает любое ненулевое значение.
Функции вроде `isdigit` возвращают просто «не ноль», а не обязательно 1.

`&&` и `||` вычисляются слева направо и с **коротким замыканием**. На этом держатся проверки вида
`i < n && a[i] != 0`: сначала проверяется граница, потом идёт доступ к элементу.

**Ловушка:** `a < b < c` означает `(a < b) < c`, то есть сравнение 0 или 1 с `c`. Нужно `a < b && b < c`.
**Ловушка:** `if (x = 5)` — это присваивание, условие всегда истинно. Компилятор с `-Wall` предупреждает.
Если присваивание в условии задумано, оберни его в двойные скобки: `while ((c = getchar()) != EOF)`.

## Инкремент и декремент
`++n` сначала увеличивает, потом отдаёт значение. `n++` отдаёт старое значение, потом увеличивает.
Применяются только к lvalue: к переменной, `*p`, `a[i]`.

**Ловушка (UB):** переменная меняется дважды или читается и меняется без точки следования между ними:
`i = i++;`, `a[i] = i++;`, `f(i++, i++);`, `x = y++ + y;`.
**Правило:** в одном выражении — не больше одного побочного эффекта на одну переменную.

## Составное присваивание и `?:`
`x op= y` — то же, что `x = x op (y)`, только `x` вычисляется один раз. Обрати внимание на скобки:
`x *= y + 1` означает `x = x * (y + 1)`.

`c ? a : b` вычисляет только одну ветку. Тип результата — общий тип `a` и `b` по правилам преобразований.
**Ловушка:** `n > 0 ? 1.0 : n` всегда `double`. `u ? -1 : 0u` превращает -1 в `UINT_MAX`.

## Таблица приоритетов (сверху старше)
| Операторы | Ассоциативность |
|---|---|
| `()` `[]` `->` `.` постфиксные `++` `--` | → |
| `!` `~` префиксные `++` `--` унарные `+` `-` `*` `&` `(тип)` `sizeof` | ← |
| `*` `/` `%` | → |
| `+` `-` | → |
| `<<` `>>` | → |
| `<` `<=` `>` `>=` | → |
| `==` `!=` | → |
| `&` | → |
| `^` | → |
| `\|` | → |
| `&&` | → |
| `\|\|` | → |
| `?:` | ← |
| `=` `+=` `-=` и т. д. | ← |
| `,` | → |

**Главные ловушки приоритетов:**
- `x & MASK == 0` читается как `x & (MASK == 0)`. Нужно `(x & MASK) == 0`. Битовые `& ^ |` младше сравнений.
- `1 << n + 1` читается как `1 << (n + 1)`. `+` старше сдвига.
- `*p++` означает `*(p++)`: сдвигается указатель, а не значение. Значение увеличивает `(*p)++`.
- `*p.x` означает `*(p.x)`. Нужно `(*p).x`, то есть `p->x`.
- `a + b >> 1` означает `(a + b) >> 1`. Так и нужно, но лучше ставь скобки явно.

**Правило:** если приходится вспоминать приоритет, ставь скобки. Особенно вокруг `& | ^ << >>` и `?:`.

## Порядок вычисления
Порядок вычисления операндов **не определён**. Исключения: `&&`, `||`, `?:` и `,`.
Порядок вычисления аргументов функции тоже не определён. Запятые между аргументами — не оператор «запятая».

```c
x = f() + g();                    /* f or g may run first */
printf("%d %d\n", ++n, pow2(n));  /* WRONG: result depends on compiler */
push(pop() - pop());              /* WRONG: which pop is first? */

int b = pop(); int a = pop(); push(a - b);   /* OK: explicit order */
```

## Оператор «запятая» и `sizeof`
`a, b` вычисляет `a`, отбрасывает результат и возвращает `b`. Уместен в заголовке `for (i = 0, j = n-1; i < j; i++, j--)`.
`sizeof x` и `sizeof(тип)` вычисляются при компиляции и возвращают `size_t` (беззнаковый).
Операнд `sizeof` не вычисляется: в `sizeof(i++)` `i` не увеличивается.
