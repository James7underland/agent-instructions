# 01. Типы, размеры, константы, объявления

## Базовые типы и их размеры
В C всего четыре базовых типа: `char`, `int`, `float`, `double`. Размер задают модификаторы
`short` и `long`, знак задают `signed` и `unsigned`. Стандарт фиксирует только минимумы:
`short` и `int` не меньше 16 бит, `long` не меньше 32 бит, `sizeof(short) <= sizeof(int) <= sizeof(long)`.
Остальное определяет реализация. Фактические границы лежат в `<limits.h>` и `<float.h>`.

| Платформа (МК) | `int` | `long` | `double` | FPU |
|---|---|---|---|---|
| AVR (Arduino Uno) | 16 | 32 | 32 (!) | нет |
| ESP8266 (Xtensa LX106) | 32 | 32 | 64 | нет: `float` и `double` считаются программно |
| ARM Cortex-M0/M3 | 32 | 32 | 64 | нет |
| ARM Cortex-M4F | 32 | 32 | 64 | только `float` |
| ПК x86-64 (gcc, Linux) | 32 | 64 | 64 | есть |
| ПК x86-64 (MinGW, Windows) | 32 | **32** | 64 | есть |

**Правило:** когда важна ширина (регистры, протоколы, форматы файлов, счётчики времени),
используй типы из `<stdint.h>`: `uint8_t`, `int16_t`, `uint32_t` и т. д. Это **(C99)**, в K&R их нет.
Голый `int` оставь для индексов и небольших счётчиков, про которые точно известно, что им хватит 16 бит.

**Ловушка:** код с ПК «работает», а на AVR ломается, потому что `int` там 16-битный:
`int ms = 60 * 1000;` даёт переполнение, ведь 60000 > 32767.

```c
#include <stdint.h>

uint32_t timeout_ms = 60UL * 1000UL;   /* force 32-bit math on any target */
uint8_t  reg_value  = 0x5A;            /* exactly 8 bits */
int16_t  temp_c10   = -125;            /* temperature in 0.1 C units */
```

## `char` — это маленькое целое
`'A'` — это число, а не строка: код символа, тип `int`. `"A"` — массив из двух `char`: `'A'` и `'\0'`.
Знаковость «голого» `char` определяет реализация: на x86 он знаковый, на ARM обычно беззнаковый.

**Правило:** в `char` храни только текст. Байты данных храни в `uint8_t` или `unsigned char`,
маленькие знаковые числа — в `int8_t`.

**Ловушка:** `char c = 0xF0; if (c == 0xF0)` — там, где `char` знаковый, это ложь:
`c` расширяется до -16, а сравнивается с 240.

**Ловушка:** результат `getchar()` и `fgetc()` имеет тип `int`, потому что `EOF` не совпадает ни с одним `char`.
Если записать результат в `char`, цикл либо не закончится никогда, либо закончится раньше времени на байте 0xFF.

```c
int c;                          /* not char! */
while ((c = getchar()) != EOF)
    putchar(c);
```

## Константы
- Целая константа без суффикса получает первый подходящий тип из `int`, `long`, `unsigned long`.
  Для hex и oct в этот ряд добавлены ещё и `unsigned`-варианты.
  Суффиксы: `U` (unsigned), `L` (long), `UL`, **(C99)** `LL`/`ULL`.
- `0x1F` — шестнадцатеричная, `017` — **восьмеричная** (то есть 15!), `0b1010` — расширение GCC, в C99 его нет.
- Константа с плавающей точкой без суффикса имеет тип `double`. `1.5f` — это `float`.
- Константное выражение (`#define N 10`, `N*4+1`) вычисляется при компиляции.
- Макросы `UINT32_C(x)` и `INT64_C(x)` из `<stdint.h>` **(C99)** дают константу нужного типа.

**Ловушка (МК):** ведущий ноль делает число восьмеричным, `uint8_t pins[] = {010, 011};` — это 8 и 9.
Для «выравнивания колонок» нулями не пользуйся.

**Ловушка (МК, ESP8266 без FPU):** `x * 0.5` превращает всё выражение в программный `double`,
а это медленно и тянет лишний код. Если `float` действительно нужен, пиши `0.5f`. Ещё лучше — fixed-point
(см. скилл `embedded-c`).

```c
#define F_CPU_HZ   80000000UL      /* UL: value > 32767, stays unsigned long */
#define MASK_HIGH  0x80000000UL    /* explicit width, no sign surprises */
float k = 0.5f;                    /* float constant, not double */
```

## Escape-последовательности
`\n \t \r \0 \\ \' \" \a \b \f \v \?`, восьмеричная `\ooo` (до 3 цифр), шестнадцатеричная `\xhh`.
**Ловушка:** `"\x41BC"` — `\x` съедает **все** следующие hex-цифры, получается один символ
с огромным кодом, а это UB или предупреждение. Строку разбивай так: `"\x41" "BC"`.

## Перечисления `enum`
Константы перечисления имеют тип `int`. Если значение не задано, оно на 1 больше предыдущего, первое равно 0.
`enum` лучше цепочки `#define`: значения генерируются сами, отладчик показывает имена,
компилятор с `-Wswitch` предупреждает о пропущенном `case`.

```c
typedef enum { LED_OFF = 0, LED_ON, LED_BLINK, LED_MODE_COUNT } led_mode_t;
```

**Ловушка:** компилятор не проверяет, что в переменной `enum` лежит допустимое значение.
Данные, пришедшие извне (UART, EEPROM), проверяй вручную: `if (m < LED_MODE_COUNT)`.

## Объявления и инициализация
- Переменная объявляется до использования. **(C99)** Объявлять можно в любом месте блока и в `for (int i = 0; ...)`.
- Внешние (глобальные) и `static` переменные обнуляются автоматически, один раз до старта программы.
- Автоматические (локальные) переменные **без инициализатора содержат мусор**.
- `const` означает «через это имя менять нельзя». Попытка изменить `const`-объект — UB.

**Правило:** инициализируй локальную переменную там же, где объявляешь.
**Ловушка:** `int sum; for (...) sum += a[i];` — сумма начнётся со случайного значения.
Компилятор ловит это с `-Wall -Wextra` (`-Wmaybe-uninitialized`), но не всегда.

**(МК)** `const` для таблиц — это ещё и способ сэкономить RAM: на многих МК такие данные уходят во flash.
На ESP8266 есть нюанс с `PROGMEM`, см. скилл `esp8266-pio`.

```c
static const uint8_t crc8_table[256] = { /* ... */ };  /* read-only, may live in flash */
```

## Имена
Буквы, цифры, `_`, первая литера не цифра. Регистр различается. Имена, начинающиеся с `_` и заглавной буквы
или с `__`, зарезервированы для реализации. Имена на `_` в глобальной области тоже не используй.
Минимально значимые 31 символ **(C99: 63)** для внутренних имён.
