# 11. Стандартная библиотека и ввод-вывод (и что из неё годится для МК)

## Модель ввода-вывода
Текстовый поток — это последовательность строк, каждая заканчивается `'\n'`. Библиотека прячет разницу
между системами: на Windows преобразует CR LF. Стандартные потоки: `stdin`, `stdout`, `stderr`.
Ошибки пиши в `stderr`: тогда они видны, даже если вывод перенаправлен. Из `main` возвращай 0 при успехе,
иначе ненулевой код, либо вызывай `exit(код)`.

## printf и семейство
`printf(fmt, ...)`, `fprintf(fp, fmt, ...)`, `sprintf(buf, fmt, ...)`, **(C99)** `snprintf(buf, size, fmt, ...)`,
`vprintf`/`vsnprintf` для своих обёрток с `va_list`.

Спецификация: `%[флаги][ширина][.точность][длина]преобразование`. Флаги: `-` (влево), `+`, пробел, `0`, `#`.
Длина: `h`, `l`, `L`, **(C99)** `ll`, `z` (`size_t`), `j`, `t`. `*` в ширине или точности берёт значение из аргумента.

| Преобр. | Аргумент | Вывод |
|---|---|---|
| `%d %i` | `int` | десятичное со знаком |
| `%u %x %X %o` | `unsigned` | без знака |
| `%ld %lu` | `long` | |
| `%zu` | `size_t` | **(C99)** |
| `%c` | `int` | символ |
| `%s` | `char *` | до `'\0'` или до «точности» (`%.10s`) |
| `%f %e %g` | `double` (`float` продвигается) | |
| `%p` | `void *` | адрес |
| `%%` | — | знак процента |

**Ловушки:**
- **Несовпадение формата и типа — UB.** `%d` для `long`, `%u` для `uint32_t` там, где это `unsigned long`
  (ARM), `%f` для `int`. **Правило:** для типов из `<stdint.h>` бери макросы `<inttypes.h>`
  (`"%" PRIu32`) или явное приведение `(unsigned long)x` с `%lu`. `-Wformat` (в `-Wall`) ловит это,
  если формат задан литералом.
- `printf(s)` с пользовательской строкой — если в ней окажется `%`, программа прочитает мусор со стека.
  Пиши `printf("%s", s)`.
- `sprintf` не знает размера буфера. **Правило:** только `snprintf` и проверка возвращённого значения.
- **(МК)** `printf` с `%f` тянет в прошивку десятки килобайт и считает медленно. На AVR `%f` по умолчанию вообще
  не работает. На ESP8266 `printf` доступен, но выводи числа fixed-point: `"%ld.%02u"`.

## scanf и семейство
Все аргументы — **указатели**: `scanf("%d", &n)`. Самая частая ошибка — забыть `&`. Функция возвращает
число успешно прочитанных полей или `EOF`. **Проверяй результат.**
`%s` без ширины переполняет буфер, пиши `%15s` для `char buf[16]`. Надёжнее читать строку через `fgets`
и разбирать её `sscanf` или `strtol`.

## Файлы
`fopen` → проверка `NULL` → `getc`/`fgets`/`fread` / `putc`/`fputs`/`fwrite` → `fclose`.
Режимы: `"r" "w" "a"`, `+` — чтение и запись, `b` — двоичный. `"w"` **стирает** существующий файл.
Между чтением и записью в режиме `+` нужен `fflush` или `fseek`.
`ferror(fp)` и `feof(fp)` сообщают, почему остановилось чтение. `fclose` сбрасывает буфер на диск,
при выходе через `exit` это происходит автоматически.

**Правило:** проверяй результат **каждого** вызова ввода-вывода, включая `fclose` и запись: диск может
заполниться. Функция `perror` выводит описание ошибки из `errno`.

## Память: malloc / calloc / realloc / free
- `malloc(n)` — неинициализированная память или `NULL`. `calloc(n, size)` — обнулённая.
- `free(p)` — только для указателя из `malloc`/`calloc`/`realloc`. `free(NULL)` безопасен.
- **Ловушки:** использование после `free`, двойной `free`, утечка. Обходить список и одновременно освобождать узлы
  нужно так: сначала сохранить `next`, потом освобождать узел.
- `p = realloc(p, n)` при неудаче теряет старый блок, и он утекает. Нужен временный указатель.
- `malloc(count * size)` может переполниться при умножении, проверяй границы.
- Возвращаемое значение **всегда** сравнивай с `NULL`.

**(МК) Правило:** на микроконтроллерах динамическую память после инициализации не используют.
Куча маленькая, фрагментируется, время выделения непредсказуемо, а ошибка нехватки памяти появляется
через часы работы. Буферы делают статическими, пулы — фиксированного размера. Подробности — в `embedded-c`.
Это касается и Arduino-класса `String`: он тоже выделяет память в куче.

В главе 8 K&R показан аллокатор `malloc`: список свободных блоков с заголовком, выравнивание через `union`
с самым «строгим» типом, склейка соседних блоков при `free`. Отсюда понятно, откуда берутся фрагментация
и накладные расходы на каждый блок.

## `<stdlib.h>` — полезное
`strtol`/`strtoul`/`strtod` (с проверкой ошибок, см. `07-strings.md`), `abs`/`labs`
(**ловушка:** `abs(INT_MIN)` — UB), `div`, `qsort`, `bsearch` (сравнение через `const void *`),
`rand`/`srand` (слабый генератор, для криптографии не годится), `exit`, `atexit`, `abort`, `getenv`.

## `<assert.h>`
`assert(expr)` при ложном `expr` печатает файл и строку, потом вызывает `abort()`. Если определён `NDEBUG`,
`assert` исчезает. **Правило:** `assert` — для проверки инвариантов программы, а не для обработки внешних
ошибок (данные от пользователя или датчика). **Не** помещай в `assert` выражения с побочными эффектами:
в релизе они пропадут. **(МК)** Обычно делают свой `ASSERT`, который пишет в лог или останавливает МК через
watchdog, см. `embedded-c`.

## `<math.h>`
`sin cos tan atan2 exp log log10 pow sqrt fabs floor ceil fmod ldexp frexp modf`. Все работают с `double`.
Ошибки сообщаются через `errno` (`EDOM`, `ERANGE`). **(C99)** Есть версии для `float`: `sinf`, `sqrtf`.
На МК без FPU (ESP8266) используй `f`-версии или таблицы и fixed-point.
При сборке на ПК может понадобиться `-lm`.

## Прочие заголовки
- `<stdarg.h>`: `va_list`, `va_start(ap, last)`, `va_arg(ap, type)`, `va_end(ap)`. Нужен хотя бы один
  именованный параметр. `va_arg` с неверным типом — UB. `char` и `float` приходят как `int` и `double`.
- `<setjmp.h>`: `setjmp`/`longjmp` — нелокальный выход. Автоматические переменные, изменённые после
  `setjmp` и не объявленные `volatile`, после `longjmp` не определены. На МК почти не используется.
- `<signal.h>`: `signal`, `raise`. В обработчике сигнала можно безопасно писать только в
  `volatile sig_atomic_t`. Идея переносится на ISR.
- `<time.h>`: `clock`, `time`, `difftime`, `mktime`, `strftime`. `localtime`, `ctime` и `asctime` возвращают указатели
  на **статические** буферы, которые следующий вызов перезапишет.
- `<limits.h>`, `<float.h>`: `CHAR_BIT`, `INT_MAX`, `UINT_MAX`, `LONG_MAX`, `FLT_EPSILON`, `DBL_DIG`…
- `<stddef.h>`: `size_t`, `ptrdiff_t`, `NULL`, `offsetof(type, member)`.
- **(C99)** `<stdint.h>`, `<inttypes.h>`, `<stdbool.h>` (`bool`, `true`, `false`).

## Интерфейс ОС (K&R гл. 8) — идеи, полезные на МК
- Низкоуровневый ввод-вывод `read`/`write` работает с «сырыми» байтами и возвращает **фактически переданное**
  количество: оно может быть меньше запрошенного. Так же устроены драйверы UART и SPI:
  всегда проверяй, сколько передано.
- Буферизованный `getc` — это макрос над буфером: `--cnt >= 0 ? *ptr++ : fill()`. Отсюда идея
  кольцевого буфера между ISR и основным циклом.
- Системно-зависимые детали прячут за маленьким переносимым интерфейсом (`opendir`/`readdir`).
  На МК та же идея называется HAL.
