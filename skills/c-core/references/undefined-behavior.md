# Неопределённое, неуточнённое и зависящее от реализации поведение

Три категории из стандарта C (K&R, приложение A; C99, раздел 3 и приложение J):
- **UB (undefined behavior):** стандарт не накладывает **никаких** требований. Программа может «работать»,
  упасть или сломаться только после включения оптимизации (`-O2`). Компилятор вправе считать, что UB
  никогда не происходит, и выкинуть проверки, которые на это опираются.
- **Unspecified (неуточнённое):** допустимо несколько вариантов, реализация не обязана документировать выбор.
  Пример — порядок вычисления аргументов.
- **Implementation-defined (зависит от реализации):** реализация выбирает вариант и **документирует** его.
  Примеры — размер `int`, знаковость `char`.

Цель: в коде не должно быть UB. Код, который зависит от реализации, должен быть явно отмечен и проверен
на целевой платформе (`_Static_assert`, `#if`, `#error`).

## 1. Арифметика и целые числа
| Что | Категория | Как избежать |
|---|---|---|
| Переполнение **знакового** целого (`INT_MAX + 1`, `int16 * int16` вне диапазона) | **UB** | считать в более широком или беззнаковом типе; проверять заранее: `if (a > INT_MAX - b)` |
| Переполнение беззнакового | определено: по модулю 2^N | это нормально для счётчиков тиков и хешей |
| Деление или остаток на 0 | **UB** | проверять делитель |
| `INT_MIN / -1`, `INT_MIN % -1` | **UB** | |
| `abs(INT_MIN)`, `-INT_MIN` | **UB** | |
| Сдвиг на `>=` ширины (после продвижения) или на отрицательное число | **UB** | проверять `n < 32`; маска `n & 31` там, где уместно |
| Сдвиг влево отрицательного числа или сдвиг, при котором бит попадает в знаковый (`1 << 31` в 32-битном `int`) | **UB** | беззнаковые литералы `1u << n`, `1UL << 31` |
| Сдвиг вправо отрицательного числа | impl-defined (обычно арифметический) | делить явно или работать в беззнаковых |
| Преобразование в знаковый тип значения, которое в него не влезает (`(int8_t)200`) | impl-defined | проверять диапазон перед сужением |
| Преобразование `float`/`double` → целое вне диапазона (в том числе отрицательного в беззнаковое) | **UB** | ограничивать значение до приведения |
| Округление деления отрицательных | C89: impl-defined; **C99: к нулю** | |
| Размеры `short`/`int`/`long`, `CHAR_BIT` | impl-defined | `<stdint.h>`, `_Static_assert(sizeof(int) == 4, "")` |
| Знаковость «голого» `char` | impl-defined | `uint8_t`/`int8_t` для чисел, `(unsigned char)` для `ctype` |
| Представление отрицательных (дополнительный код и др.) | impl-defined (до C23) | не полагаться на побитовый вид отрицательных |

**Особенно важно для МК — неявное продвижение:**
- `uint16_t a = 0xFFFF; a * a` при 32-битном `int` — это умножение **знаковых** `int` и переполнение (**UB**).
- При 16-битном `int` (AVR) `uint16_t` продвигается в `unsigned int`, и та же строка определена.
  Код ведёт себя по-разному на разных МК.
- Лечение: `(uint32_t)a * a`.

## 2. Порядок вычисления и побочные эффекты
| Что | Категория |
|---|---|
| Объект меняется дважды между точками следования (`i = i++`, `i++ + i++`) | **UB** |
| Объект читается «не для вычисления нового значения» и меняется между точками следования (`a[i] = i++`) | **UB** |
| Порядок вычисления операндов `+`, `*`, `==` и т. п. | unspecified |
| Порядок вычисления аргументов функции | unspecified |
| `&&`, `\|\|`, `?:`, `,` | порядок гарантирован: слева направо |

Правило: не больше одного побочного эффекта на переменную в выражении. Где важен порядок — временные переменные.

## 3. Указатели и память
| Что | Категория |
|---|---|
| Разыменование `NULL`, неинициализированного или «висячего» указателя (после `free`, адрес локальной переменной вышедшей функции) | **UB** |
| Доступ за границы массива, в том числе чтение `a[N]` | **UB** |
| Указатель дальше чем «один за концом» или раньше начала массива (даже без разыменования) | **UB** |
| Разность или сравнение `<` указателей из разных объектов | **UB** |
| Изменение строкового литерала | **UB** |
| Изменение объекта, объявленного `const` (через приведение) | **UB** |
| Доступ к объекту через lvalue несовместимого типа (strict aliasing: `*(uint32_t *)&f` для `float f`) | **UB**; допустимо через `char *`/`unsigned char *`, `memcpy`, `union` (C99 TC3+) |
| Невыровненный доступ (`*(uint32_t *)(buf + 1)`) | **UB**; на ESP8266 это исключение 9 (LoadStoreAlignment) |
| Двойной `free`, `free` чужого указателя | **UB** |
| Перекрытие областей в `memcpy`, `strcpy`, `sprintf` | **UB**, нужен `memmove` |
| Чтение неинициализированной автоматической переменной | неопределённое значение, на практике UB |
| Преобразование указателя в целое и обратно | impl-defined; для этого есть `uintptr_t` (C99, `<stdint.h>`) |
| `malloc(0)` | impl-defined: `NULL` или уникальный указатель |

## 4. Функции
| Что | Категория |
|---|---|
| Использование результата функции, которая завершилась без `return` значения | **UB** |
| Вызов функции через указатель несовместимого типа | **UB** |
| Число или типы аргументов не совпадают с определением (без прототипа) | **UB** |
| `va_arg` с типом, не совпадающим с переданным | **UB** |
| Несоответствие формата `printf`/`scanf` типу аргумента | **UB** |
| Аргумент `isxxx()`/`toxxx()` не `EOF` и не значение `unsigned char` | **UB** |
| Рекурсия или большие локальные массивы при переполнении стека | стандарт молчит; на МК — порча памяти и сброс |

## 5. Препроцессор и лексика
| Что | Категория |
|---|---|
| Нераспознанная escape-последовательность (`"\q"`) | **UB** (обычно предупреждение) |
| `\x` с цифрами, дающими значение больше `char` | **UB** |
| `##`, дающий недопустимый токен | **UB** |
| Многосимвольная константа `'ab'` | impl-defined |
| Идентификаторы `_Upper`, `__x` и глобальные `_x` | зарезервированы, UB при определении |

## 6. Структуры, объединения, битовые поля
| Что | Категория |
|---|---|
| Padding и выравнивание полей структуры | impl-defined |
| Порядок, упаковка и пересечение границ битовых полей | impl-defined |
| Знаковость битового поля типа `int` | impl-defined |
| Чтение члена `union`, отличного от последнего записанного | C99 TC3/C11: представление переосмысливается (impl-defined результат); C89: impl-defined |
| Порядок байт многобайтовых типов | impl-defined; на ESP8266, AVR, ARM — little-endian |

## 7. Для МК отдельно (стандарт об этом молчит, но это ломает прошивки)
- Переменная, общая для ISR и основного кода, без `volatile`: компилятор кэширует её в регистре,
  и цикл ожидания становится бесконечным. См. `embedded-c`.
- Неатомарное чтение многобайтовой переменной, которую меняет ISR: на 8-битном МК `uint16_t` читается
  за две инструкции, а на ESP8266 и 32-битных МК так же неатомарны `uint64_t` и составные операции
  (`x++`, `x |= m`).
- Время жизни данных в DMA-буфере: буфер на стеке функции, которая уже вернулась.

## Инструменты, которые ловят UB
- Компилятор: `-Wall -Wextra -Wpedantic -Wconversion -Wshift-overflow=2 -Wstrict-aliasing=2 -Wcast-align`.
- На ПК: `-fsanitize=undefined,address` (UBSan и ASan в GCC и Clang; в MinGW поддержка ограничена),
  `valgrind` на Linux.
- Статический анализ: `cppcheck`, `clang --analyze`, `-fanalyzer` (GCC 10+).
- Модульные тесты на ПК с максимальными предупреждениями **и** с `-O2`: UB часто проявляется только
  при оптимизации.
