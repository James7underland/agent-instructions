# 06. Указатели и массивы

## Основы
- Указатель — это переменная, в которой лежит адрес. Каждый указатель типизирован: `int *p` указывает на `int`.
- `&x` — адрес объекта. Применяется к переменным и элементам массивов, но не к выражениям, константам,
  `register`-переменным и битовым полям.
- `*p` — объект по адресу. Это lvalue, ему можно присваивать.
- Объявление повторяет использование: `int *p;` читается как «`*p` — это `int`».

**Ловушка:** `int* a, b;` объявляет `a` указателем, а `b` обычным `int`. Объявляй по одной переменной на строку.
**Ловушка:** `*p++` сдвигает указатель. Чтобы увеличить значение, пиши `(*p)++` или `++*p`.

## Указатели как параметры
Функция получает копию указателя и через неё может изменить объект вызывающего: `swap(&a, &b)`.
Так же возвращают несколько результатов или отдельный статус ошибки.

**Правило:** указатель, по которому функция только читает, делай `const T *`. Это и документация, и проверка.
```c
size_t count_nonzero(const uint8_t *buf, size_t len);
```

## Массивы и указатели
- Имя массива в выражении превращается в указатель на элемент 0: `a` == `&a[0]`.
- `a[i]` **по определению** равно `*(a + i)`, а `&a[i]` равно `a + i`. К указателю тоже можно
  применять `p[i]`.
- Отличие: указатель — переменная, его можно менять (`p++`). Имя массива — нет (`a++` — ошибка).
- Параметр `int a[]` на самом деле `int *a`. Размер массива в функцию **не передаётся**.

**Ловушка:** внутри функции `sizeof(a)` для параметра-«массива» даёт размер указателя (4 байта на ESP8266),
а не массива. **Правило:** передавай длину отдельным параметром `size_t len`.
Длину массива в той же области видимости считает макрос:
```c
#define ARRAY_LEN(a)  (sizeof(a) / sizeof((a)[0]))   /* only for real arrays, not pointers */
```

**Ловушка:** выход за границы массива — UB. Компилятор не проверяет, на МК он тихо портит соседние переменные.
`a[-1]` допустим, только если `a` указывает внутрь большего массива.

## Адресная арифметика
- `p + n` указывает на n-й **объект** после `p`: сдвиг умножается на `sizeof(*p)`.
- Разность указателей `q - p` имеет тип `ptrdiff_t` и равна числу элементов между ними.
  Допустима только внутри одного массива.
- Сравнивать `< <= > >=` можно только указатели внутрь одного массива (или структуры).
- Адрес **одного за концом** массива (`a + N`) можно вычислять и сравнивать, но разыменовывать нельзя.
- Складывать указатели, умножать, делить и сдвигать их нельзя. Смешивать указатели разных типов без приведения
  тоже нельзя, исключение — `void *`.
- `0` (`NULL`) — единственное целое, которое можно присвоить указателю и с которым можно его сравнить.
  Нулевой указатель не равен адресу ни одного объекта.

**Правило (МК):** полуоткрытые интервалы `[begin, end)` с `end = a + N` — самая безопасная форма.
Середину ищи как `low + (high - low) / 2`: сумма `(low + high) / 2` может переполниться, а для указателей
она вообще запрещена.

```c
uint16_t sum_u8(const uint8_t *p, const uint8_t *end)
{
    uint16_t s = 0;
    while (p < end) {
        s += *p++;
    }
    return s;
}
/* usage: sum_u8(buf, buf + ARRAY_LEN(buf)) */
```

## `void *` и приведения
Любой указатель на объект можно превратить в `void *` и обратно без потерь. Так работают
`malloc`, `memcpy`, `qsort`. Разыменовать `void *` нельзя, сначала приведи его к нужному типу.

**Ловушка (UB, важно для МК):** приведение `uint8_t *` к `uint32_t *` с последующим чтением.
1. Нарушение выравнивания. На ESP8266 невыровненное 32-битное чтение даёт исключение
   `LoadStoreAlignmentCause` (Exception 9) и перезагрузку.
2. Нарушение strict aliasing: объект читается через lvalue несовместимого типа. Оптимизатор вправе
   сломать такой код.

**Правило:** собирать многобайтовые значения из буфера — сдвигами (это заодно фиксирует порядок байт)
или через `memcpy`:
```c
static uint32_t read_le32(const uint8_t *p)
{
    return (uint32_t)p[0]
         | ((uint32_t)p[1] << 8)
         | ((uint32_t)p[2] << 16)
         | ((uint32_t)p[3] << 24);
}
```

## Висячие и неинициализированные указатели
**Ловушка:** возврат адреса локальной переменной — после выхода из функции память переиспользуется:
```c
char *bad(void) { char buf[16]; /* ... */ return buf; }   /* UB for caller */
```
Верни `static`-буфер (не реентерабельно!), прими буфер от вызывающего или используй структуру по значению.

**Ловушка:** неинициализированный указатель указывает куда угодно. Если сразу нечего присвоить,
инициализируй его `NULL`. После `free(p)` пиши `p = NULL;`.

## Многомерные массивы
`int m[3][4]` — это массив из 3 массивов по 4 `int`, хранится по строкам: быстрее всего меняется последний индекс.
Индексы пишутся `m[i][j]`, **не** `m[i, j]`: там оператор «запятая», и это равно `m[j]`.

В функцию передаётся указатель на строку, поэтому все размеры, кроме первого, обязательны:
`void f(int m[][4], size_t rows)` или `void f(int (*m)[4], size_t rows)`.

**Отличие от массива указателей:** `int *b[3]` — это 3 указателя. Строки могут быть разной длины,
но их нужно инициализировать отдельно. Для таблиц строк это удобнее и экономнее:
```c
static const char *const month_name[] = { "?", "Jan", "Feb", "Mar" };  /* both pointer and chars const */
```
