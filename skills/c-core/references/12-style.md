# 12. Стиль (из K&R и практики прошивок)

## Из K&R
- **Магические числа — в именованные константы.** `#define`, `enum` или `static const` с понятным именем.
  Так понятен смысл, и значение меняется в одном месте.
- **Один оператор на строку**, пробелы вокруг бинарных операторов, отступ показывает вложенность.
  Стиль скобок выбери любой, но держи его единообразным.
- **Имена:** короткие для локальных индексов (`i`, `n`), длинные и говорящие для внешних и глобальных.
  Константы и макросы — ЗАГЛАВНЫМИ, переменные и функции — строчными.
- **Маленькие функции** с понятной задачей. Функцию, которая вызывается один раз, стоит завести,
  если она проясняет код.
- **Меньше глобальных переменных.** Они «всегда есть, даже когда не нужны», и связи между частями
  программы становятся неочевидными. Внутреннее состояние модуля — `static`.
- **Сначала понятность, потом краткость.** Идиомы вроде `while ((c = getchar()) != EOF)` и `*s++ = *t++`
  стоит знать, но не громозди из них нечитаемые выражения. Сложное указательное выражение разбей на 2–3 шага.
- **Проверяй граничные случаи:** пустой ввод, одна запись, переполнение буфера. Хорошие `while` и `for`
  при нулевом числе итераций сами делают правильное.
- **Сверяйся с тем, что делает функция.** Функция, которая где-то возвращает значение, а где-то нет, —
  признак ошибки.
- **Возвращай осмысленный статус** из `main` и функций. Сообщения об ошибках — в `stderr` с именем программы.
- `goto` — редко: для выхода из нескольких вложенных циклов и для общей очистки ресурсов.

## Дополнения для прошивок (общепринятая практика, MISRA-подобные правила)
- Фигурные скобки у **всех** `if`/`else`/`for`/`while`, даже вокруг одной строки.
- Каждый `switch` содержит `default`. Проваливание между `case` помечай комментарием.
- Типы фиксированной ширины (`uint8_t` и т. п.) для данных, регистров и протоколов.
- `const` везде, где значение не меняется: у параметров-указателей, у таблиц.
- Не смешивай знаковые и беззнаковые типы в одном выражении. Явные приведения там, где меняется ширина.
- Одна точка входа модуля — `module_init()`. Публичные функции с префиксом модуля (`uart_send`, `uart_init`).
- Проверяй все возвращаемые значения. Намеренно игнорируемое пометь `(void)f();`.
- Без динамической памяти после старта, без рекурсии, без `setjmp`/`longjmp` (подробнее — в `embedded-c`).
- Имена статических переменных модуля — с префиксом `s_`, глобальных — `g_`. Префиксы сразу показывают,
  что объект живёт дольше функции.
- Комментарии объясняют **почему**, а не **что**. У публичной функции в `.h` описаны назначение,
  параметры, возвращаемое значение, ограничения (можно ли вызывать из ISR, реентерабельна ли).

## Флаги компилятора — часть стиля
Собирай с `-std=c99 -Wall -Wextra -Wpedantic` (или `-pedantic`) и **без предупреждений**. Полезные дополнительные флаги:
`-Wshadow -Wconversion -Wsign-conversion -Wundef -Wstrict-prototypes -Wmissing-prototypes
-Wcast-align -Wswitch-enum -Wformat=2`. На ПК при тестах: `-fsanitize=address,undefined -g`.
`-Werror` превращает предупреждения в ошибки.
