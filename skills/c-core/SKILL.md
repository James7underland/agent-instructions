# c-core — надёжный C (C99) по K&R

Каталог скилла — папка с этим `SKILL.md`, пути ниже относительно неё.
Источник — K&R, 2-е изд. (ANSI C). Конспекты дополнены C99 и опытом МК, а в PDF-копии книги
есть опечатки в коде, поэтому примеры из книги дословно не переносить (см. `references/known-issues.md`).

## Порядок работы при написании кода
1. **Требования:** входы и выходы, диапазоны значений, единицы, ошибки, ограничения платформы
   (размер `int`, есть ли FPU, память). Неясное — уточни или явно запиши допущение.
2. **Интерфейс модуля (`.h`)** по `templates/module.h`: типы, коды ошибок, прототипы с описанием, include guard.
   Состояние — в структуре экземпляра (без `malloc`, без скрытых глобальных).
3. **Реализация (`.c`)** по `templates/module.c`: свой `.h` включён первым, всё внутреннее — `static`,
   аргументы проверены, магических чисел нет.
4. **Проверка по чек-листу** `references/review-checklist.md` и сводке `references/undefined-behavior.md`.
5. **Тест на ПК:** `gcc -std=c99 -Wall -Wextra -Werror -pedantic -O2` плюс `assert`-тест с граничными
   случаями. Прогнать и с `-O0`, и с `-O2`. Если есть — `-fsanitize=address,undefined`.
6. Показать результат: что сделано, какие допущения, как проверено (команда и вывод).

При **ревью** чужого кода: пройти чек-лист и выдать находки в формате «файл:строка → проблема → почему
(UB/ловушка) → исправление». Сначала опасные (UB, переполнения, границы), потом стиль.

## Главные правила (коротко)
- **Типы:** данные, регистры и протоколы — `<stdint.h>` (`uint8_t`, `int32_t`). `int` бывает 16-битным (AVR).
  `char` только для текста, знаковость `char` зависит от платформы.
- **Неявные преобразования:** узкие типы в выражении становятся `int`. `uint16_t * uint16_t` при 32-битном
  `int` — знаковое умножение с возможным UB. Приводи к нужной ширине **до** операции: `(uint32_t)a * b`.
- **Знаковое с беззнаковым:** `-1 < 10u` — ложь. Не смешивай, `-Wextra` предупреждает.
- **Биты** — только в беззнаковых, маски `1UL << n`. `1 << 31`, сдвиг на ширину типа и больше — UB.
  `(x & MASK) == 0` — скобки обязательны.
- **Порядок вычисления** не определён (кроме `&& || ?: ,`). `i = i++`, `a[i] = i++` — UB.
- **Указатели:** границы массивов, длина передаётся отдельно (`size_t len`), `sizeof` параметра — это
  размер указателя. Не возвращать адрес локальной переменной. Не приводить `uint8_t *` к `uint32_t *`.
- **Строки:** размер буфера всегда известен. `snprintf` и копирование с размером. Нет `gets`, `strcpy`
  в неизвестный буфер. `strncpy` не ставит `'\0'`. `strtol` с проверкой вместо `atoi`.
  `isdigit((unsigned char)c)`.
- **Макросы:** скобки вокруг параметров и тела, `do { } while (0)`, лучше `static inline`.
  В `.h` — include guard и никаких определений переменных.
- **Модули:** всё внутреннее — `static`, прототипы с `(void)`, возвращаемые ошибки проверяются.
- **Память на МК:** без рекурсии, без больших локальных массивов, без `malloc` после старта.
- **Время:** `now - start >= period` на беззнаковых — корректно при переполнении.

## Примеры (`examples/`, C99, собираются на ПК)
- `bit_ops.h/.c` — маски, поля, popcount, разворот бит, упаковка BE/LE без приведения указателей.
- `safe_string.h/.c` — `str_copy`, `str_append`, строгий разбор чисел (`parse_i32`, `parse_u16`).
- `pitfalls_demo.c` — классические ловушки K&R: неверная форма в комментарии, верная в коде, проверка `assert`.
Сборка: `gcc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -o pitfalls pitfalls_demo.c bit_ops.c safe_string.c`.

## Шаблоны (`templates/`)
`module.h` / `module.c` — модуль с include guard, кодами ошибок, структурой экземпляра, `static` для
внутреннего и комментариями к API.

Перед работой прочитай references/known-issues.md; после задачи допиши находки в references/ и строку в references/session-log.md.
