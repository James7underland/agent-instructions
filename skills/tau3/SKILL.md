# ТАУ-3 — рабочий процесс

Пакет: каталог `TAY_3` (оригинал **не трогать**; запуск из рабочей копии, задается переменной `TAY3_DIR` или аргументами).
Работать в отдельной рабочей копии (скрипты запускают из нее).
Каталог скилла — папка с этим `SKILL.md`.
Программы — только GUI (Delphi, Win32, 32 бит): нет COM/CLI. Управляем оконными сообщениями через pywinauto/pywin32
(Python 3.14 x64: pywinauto, pywin32, pillow, numpy установлены). Мышь и фокус пользователя не трогаются.

## В начале каждой задачи
1. Прочитай `references/known-issues.md` (обязательно) и хвост `references/session-log.md`.
2. По задаче: `references/programs.md` (что умеет каждая программа, как вызвать), `references/ui-map.md`
   (меню и окна каждой программы — снято обходчиком), `references/vrt-format.md` (файлы вариантов),
   `references/help/index.md` → нужная тема справки (методика, смысл параметров, ограничения),
   `references/forms/<prog>.summary.txt` (все формы/кнопки/подписи из exe), `references/capabilities-report.md`
   (что проверено и как, с числами сверки), `references/elements/` (типы звеньев и коды для VRT).

## Правила безопасности
- Оригинальный `TAY_3\` не менять; запуск — из `Работа\TAY_3\`. Перед правкой VRT пользователя — копия `.bak-ГГГГММДД-ЧЧММСС`.
- Не создавать `C:\TAY_3` (программы начнут читать/писать туда).
- Убивать только процессы, запущенные нами (`tau.py close` по pid). Если пользователь сам работает в той же
  программе — не трогать её, запустить свою копию нельзя (общие VRT) → предупредить.
- Никогда не выбирать «на принтер»; в `TUstForm` всегда «в файл».
- На вопрос «Использовать данные предыдущего счета?» ответ Нет стирает вариант (VRT) — по умолчанию Да.

## Инструменты (`scripts/`, запуск из Bash: `python "<скилл>/scripts/tau.py" …`)
Для кириллицы в выводе: `PYTHONIOENCODING=utf-8`. Все команды печатают JSON; если запущена одна программа, pid не нужен.

**tau.py** — драйвер GUI:
```
launch Linsys [--prev yes|no]           # старт + заставка + «данные предыдущего счета?»
ls [--controls]                         # окна (hwnd, класс, заголовок) и контролы (класс#N, текст, xy)
menu --win main                         # дерево всплывающего меню;   menu --win TGraForm "Аналитич"  — выполнить
menu --win main "Исследование системы->Переходная функция"   # можно только конец пути: "Переходная функция"
set --win TParmForm --ctl @330,30 3     # поле (порядок многочлена и т.п.): клик→текст→CM_EXIT (применение)
grid --win TParmForm --ctl @100,120 0,1=1 1,1=3 2,1=3 3,1=1 --ok @25,228   # ячейки TStringGrid (строка,столбец)
fill --win TValForm 0.5 3 0.5 1 --ok OK # нарисованные таблицы «Значения» (A от/до/шаг, B), «Частоты», «Xo», «tрег»
click --win W --ctl OK | --xy X,Y | --wxy X,Y (по снимку окна)   radio/select/keys — см. tau.py -h
answer [Yes|No|OK|Cancel]               # сообщения; текст сообщения — только на снимке (поле "shot")
shot --win TGraForm out.png | shot --all DIR      # PNG окон (PrintWindow, логический масштаб)
tofile --win TAnalFnForm                # «В файл» → текст <PROG>.tab (формулы, таблицы корней, результаты)
close                                   # убить процесс
```
Окно `--win`: класс (`TGraForm`, `TParmForm`, `TValForm`…), `main`, подстрока заголовка или hwnd.
Контрол `--ctl`: текст/подпись, `Класс#N` (как в `ls --controls`), `@x,y` (под точкой клиента), hwnd.

**crawl.py PROG** — автообход: вызывает каждый пункт меню, заполняет формы значениями по умолчанию (буквы=1, X°=1,
tрег=10), снимает все окна → `Работа\crawl\<prog>\` + `sheet.png` (контактный лист) + `report.json`.
**summarize.py CRAWL_DIR OUT.md** — сводка меню/окон. **vrt.py** — чтение/запись VRT (`show`, `roundtrip`, `poly`,
`set-elem`). **check.py** — независимая сверка (numpy): `step/impulse` (формулы как «Аналитич. формула»), `closed`,
`freq`, `routh`, `lqr`/`lqrm` (ANACON/KALMAN), `ztf` (Z-преобразование с ЭНП), `mul`, `prony`.
**elements.py PROG "W=x,y" …** — каталог библиотеки звеньев (буква=координаты на снимке главного окна).
**dfm.py** — формы из exe; **hlp.py** — декомпиляция справки WinHelp.
Готовые каталоги звеньев: `references/elements/README.md` (IMPULS, LINSYS2, LINSYS3, NLINSYS) и
`references/elements/control/README.md` (CONTROL). Снимки всех окон всех программ: `examples/sheets/<prog>.png`.

## Типовые сценарии
**Передаточная функция + график (LINSYS, OPTIM, ANACON, IDENTF, RTLZ — ввод таблицами):**
`launch` → `menu --win main "Задание п.ф. объекта"` → `ls --controls` (TEdit порядков, две TStringGrid, две OK) →
`set` порядок знаменателя → `grid` коэффициенты (столбец 1 = «Коэфф.», строка r = a_r по убыванию степеней) → OK
под таблицей → то же для числителя → `menu --win TParmForm "Закрыть"` → `menu --win main "Переходная функция"` →
`shot`, `menu --win TGraForm "Аналитич"` → `tofile --win TAnalFnForm`. Проверка: `check.py step --num … --den …`.
Быстрее — записать VRT файлом (`vrt.py poly Работа/TAY_3/LINSYS.VRT --den … --num … --den 1 --num 1`) и `launch --prev yes`.

**Структурные схемы (CONTROL, CASCAD, IMPULS, LINSYS2/3, MVACS2, NLINSYS, ASYMPT, SPECTR):** звенья задаются
типом из библиотеки + параметрами. Надёжно — правкой VRT (`vrt.py set-elem CONTROL.vrt W 12 …`, формат в
vrt-format.md, каталог типов — references/elements/) и перезапуском. В GUI: «Формирование элементов схемы» →
щелчок по букве звена на схеме (`click --win main --wxy X,Y` по снимку) → окно «Элемент схемы» (стрелки перебора
типов, OK — выбор) + «Параметры». Буквенные параметры A, B (C, D) задаются при построении графика в окне «Значения».

**Матричные задачи (ANACON2, ANACON3, KALMAN, OPTIM2):** «Ввод данных» — мастер TDRForm (Назад/Вперёд/Конец) с
таблицей для каждой матрицы; VRT — читаемый текст «ДАННЫЕ И РЕЗУЛЬТАТЫ СЧЕТА». Сверка: `check.py lqrm`.
