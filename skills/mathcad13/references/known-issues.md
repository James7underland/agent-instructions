# Грабли Mathcad 13 и как их обходить

Формат записи: **симптом** → причина → что делать. Новые находки дописывать сюда (в конец раздела).

## Автоматизация (COM)
- **Свойства региона пустые, `foreach` по `Regions` ничего не даёт** → typelib только win32, раннее связывание
  не работает для Region/MathInterface/Metadata/Windows → `InvokeMember` (функции `P`/`SetP`/`M`), цикл `for` + `Item(k)`.
- **`New-Object -ComObject` из 64-битного процесса ненадёжен** → запускать из `SysWOW64\...\powershell.exe` (mc.ps1 делает сам).
- **Процесс `mathcad.exe -Embedding` остаётся жить** → лист не закрыт перед Quit, или Mathcad повис при выходе →
  всегда `Close(2)`, пауза, `Quit(2)`; при необходимости убить **свой** PID (mc.ps1 делает это сам).
- **`Get-Process mathcad` показывает процесс, который «не убивается»** → это уже завершённый процесс
  (HasExited=True), пока кто-то держит дескриптор → фильтровать по `HasExited`.
- **Скрипт висит бесконечно** → модальный диалог Mathcad (сообщение, «сохранить?», падение с окном
  «Microsoft Visual C++ Runtime Library») → `SetOption(0,$false)` и таймаут в родителе (mc.ps1 `-Timeout`).
- **Mathcad падает при выходе после `MathInterface.XML = …`** → сохранить сразу после правки; предпочитать `xmcd.py set`.
- **«Quote expected» при установке XML** → XML передан через аргументы командной строки и потерял кавычки →
  передавать через файл.
- **`GetValue("σ")` — «value was not found»** → греческие буквы нужно экранировать (`\s`) → mc.ps1 переводит сам.
- **`SetValue` «не действует»** → в листе ниже есть своё определение этой переменной, оно перекрывает →
  менять определение (`xmcd.py set`) либо удалить его.
- **`SaveAs(..., 16)` дал HTML вместо RTF** → RTF через COM недоступен → Word-отчёт делать `report.py`.
- **`SaveAs(path)` без кода формата дал бинарный .mcd при расширении .xmcd** → всегда указывать код (18).
- **Window.Zoom не увеличивает картинки HTML-экспорта** → увеличивать шрифты `mathStyles` в копии листа.

## Формат / генерация
- **Регион исчез после загрузки** (число регионов меньше, чем в файле) → неизвестный MC13 элемент
  (например `ml:matrow` — оператор строки) или битый блок графика → сверять `region_count` из mc.ps1 с числом
  регионов в файле; строку матрицы брать `submatrix(M, i, i, 0, cols(M)-1)` или `transpose(col(transpose(M), i))`.
- **Результат-матрица «налезает» на определение** → Mathcad меняет высоты при пересчёте →
  `xmcd.py relayout` по пересохранённому файлу, повторять до «0 overlap(s)».
- **Порядок вычисления «ломается» после ручной раскладки** → Mathcad считает по `align-y`, а не `top`.
- **График молча пропал** → при переименовании идентификатора в блоке не обновлён байт длины
  (`[len+1][len]имя\0`) или имя не ASCII.
- **Кириллица в строке формулы превращается в «?@825B»** → математика MC13 не Unicode (берётся младший
  байт кода) → в формулах только ASCII/греческие; русский текст — в текстовых регионах и комментариях.
- **`1.5e-3` в XML** → xmcd.py разворачивает в `0.0015`; сам Mathcad хранит так же.
- **Имя переменной совпало с единицей/константой** (`F, A, s, m, g, L, R, c, e, π, δ, ε`) → зелёная волнистая
  черта, единица пропадает ниже → литеральные индексы (`F.1`, `L.p`); проверенный список — `math-xml-catalog.md`.
- **`10 kPa` → переменная не определена** → в MC13 нет kPa, kJ, MN → определить `kPa := 1000*Pa` (см. `units.md`).
- **`num2str(3.14)` = "3,14"** → локаль Windows с десятичной запятой.
- **Файлы данных не находятся** → относительные пути считаются от папки листа; копии листа класть рядом
  с оригиналом (report.py так и делает).

- **Весь файл «The contents of this file have been corrupted… Required attribute 'method' is missing»** →
  Mathcad проверяет XML по схеме, одно нарушение ломает весь лист (например `ml:genfit` без `method`) →
  сверяться с `schema\Math20.xsd`/`Worksheet20.xsd`; xmcd.py ставит `genfit method="optimized levenberg-marquardt"`.
- **`Minerr` возвращает неправдоподобный ответ** → с auto-method Mathcad выбирает не тот метод и выдаёт
  не решение МНК (x==1, x==3 → 1 вместо 2) → `method="levenberg" auto-method="false"` (xmcd.py так и делает;
  в чужих файлах проверять атрибуты `ml:Minerr`).
- **Лист «Unknown Error» при открытии через COM** → в нём скриптовые объекты (ползунки/кнопки, `mcscript.ocx`) →
  для пересчёта убрать регионы `<component clsid="d058c3d4-…">` из копии листа; остальное считается.
- **«…created with a newer version of Mathcad and cannot be opened»** → файл Mathcad 14/15 (`worksheet30`) →
  пересчитать нельзя, но `xmcd.py read` показывает формулы и сохранённые результаты. Prime `.mcdx` — не читается.
- **`region_count` из mc.ps1 меньше числа `<region>` в файле** → COM считает только регионы верхнего уровня
  (вложенные в area — нет) → сравнивать счётчики только для своих сгенерированных листов без областей.
- **`READFILE("x.xlsx","Excel")` — file I/O error** → MC13 понимает только .xls → пересохранить в Excel 97–2003.
- **CSV с `;` и десятичной запятой читается строками "2,5"**, `str2num("2,5")` — ошибка → переписать файл
  с точкой (Python) перед чтением.
- **Вектор-результат обрезан в отчёте** → больше 9 элементов Mathcad показывает прокручиваемой таблицей,
  в экспорт идут 16 строк → `v = @matrix`.

## PowerShell
- **Переменная «сама» поменяла значение/тип** → имена переменных нечувствительны к регистру: `$d` = `$D`,
  `$meta` = параметр `-Meta` ([string] превращает COM-объект в строку) → разные имена, не только регистр.

## Отчёты
- **Нижний индекс пропал в Word** → в python-docx `subscript`/`superscript` — один атрибут `vertAlign`,
  присваивание `None` второму стирает первый → report.py выставляет только нужный.
- **Последняя буква единицы на картинке чуть обрезана** (`kN·m`, `mm`) → особенность рендера Mathcad при
  увеличенных шрифтах; некритично. Альтернатива — `--scale 1` (без увеличения, но картинки мельче).
- **Подписи осей графика огромные** → шрифты графика берутся из mathStyles → report.py берёт графики из
  немасштабированного экспорта (второй вызов Mathcad).
- **Заголовки в Word не того шрифта** → у стилей python-docx тема-шрифты (`asciiTheme`) → report.py их удаляет.

## Графики (найдено 2026-09-25, курсовая по ТАУ)
- **Заданный предел оси не применяется (особенно отрицательный)** → в шаблоне у значения/минуса стоит бит 0x02
  («авто») → для пользовательских пределов side без 0x02 (`mcplot.py` делает сам).
- **График мелкий в экспорте (≈300×175 px)** → размер задаётся в `graphData` (+27/+31), а не в `shpRect` и не атрибутами
  региона → `mcplot.make_plot(size=(80, 48))`.
- **Все кривые одного цвета** → это матрица Y в одном следе; нужны отдельные выражения в списке Y
  (`f(t), g(t), h(t) vs t`) — `mcplot.py` строит дерево для любого числа кривых.
- **Файлы во временной папке сессии пропадали** → рабочие файлы держать в папке проекта.

## Графики: стиль Crossed закрывает крайние линии сетки
Симптом: рамка графика, найденная по зелёным пикселям, на несколько px уже реальной (ось X при y=0 внизу, ось Y при
x=0 слева). Причина: чёрные оси и засечки рисуются поверх крайних линий сетки. Что делать: брать bbox сетки ∪ длинных
чёрных линий (`mcfig.plot_area`). Числа под осью начинаются через ~8 px после засечек — при поиске блока чисел
пропускать засечки (skip=5) и считать разрыв ≥10 px.

## График с большим числом кривых молча исчезает (2026-09-25)
Симптом: после пересчёта в листе нет региона графика (например, 7 и больше кривых `f(t)` или 6 пар `Y, X`), ошибок нет.
Причина: номера узлов дерева выражения ≥ 0x40 кодируются как `40 xx`; старый генератор писал один байт.
Что делать: `mcplot.py` (исправлен) — `enc()` для id/parent/хвоста. Проверено: 9 кривых, 8 пар X–Y.

## Разрывы кривых на графике
`NaN` в векторе данных разрывает линию (проверено в MC13). Семейство отрезков (изоклины, касательные) удобно
собирать программой в одну матрицу: `M[k, 0] <- x; …; M[k, 0] <- NaN` и строить `col(M, 1)` от `col(M, 0)`.

## Подписи выражений Mathcad прилипают к цифрам оси (2026-09-26)
Симптом: после `mcfig.finish` слева остаются обрывки «.95», «w)», штрихи легенды. Причина: подписи трасс Mathcad
выровнены по левому краю региона и стоят вплотную к цифрам оси; у пунктирных трасс образец линии чёрный.
Что делать (сделано в `mcfig.clean`): ширину столбика цифр оси определять по строкам без легенды и стирать всё
левее него попиксельно; группы, начинающиеся в 10 px от левого края, — легенда.
Диапазон `x := a, b..c` в Mathcad: второе число — следующий элемент, а не шаг (`0.04, 0.0401..0.14`).

## Установка и пути (25.09.2026, quizyforu-eng)
- **`mcsheet.py`/`mcplot.py` падают с FileNotFoundError `<скилл>\...`** → пути к
  скриптам и шаблону графика были зашиты под компьютер автора (в `make_plot` — ещё и как значение аргумента по
  умолчанию) → теперь берутся относительно самого файла; Mathcad ищет `scripts/find_mathcad.py`, в mc.ps1 — `Find-McadDir`.
- **find_mathcad.py не видел COM-сервер, хотя PowerShell его видит** → в `LocalServer32` путь записан без кавычек и с
  пробелами (`C:\Program Files (x86)\...\mathcad.exe`), а 32-битная ветка — `HKCR\WOW6432Node\CLSID` (флаг
  `KEY_WOW64_32KEY` для HKCR из 64-битного Python её не открывает) → читать `WOW6432Node\CLSID` явно, путь до `.exe`.
- **Mathcad стоит в нестандартной папке** → задать переменную окружения `MATHCAD13_DIR` (папка с mathcad.exe); её
  проверяют и find_mathcad.py, и mc.ps1. Неверное значение просто пропускается, поиск идёт дальше.

## Символьный вывод и build-синтаксис (27.09.2026, FlosVacui)
- **`W(p)/p -> invlaplace, p` даёт «This variable is undefined»**, хотя численно всё считается → в W входят
  переменные, полученные через `root`, `lsolve`, `polyroots`, `match` (символьный процессор их не вычисляет) →
  в символьное выражение подставлять числа явно (генерировать строку из Python), например
  `1/((1.2073*p + 1)*(0.4973*p + 1)*p) -> invlaplace, p | float, 4`.
- **Звено 2-го порядка с вещественными корнями, а invlaplace выдаёт `cosh`/`sinh`** → Mathcad так записывает
  `1/(a2p²+a1p+1)` при D > 0 (это те же две экспоненты, не колебания) → для отчёта подавать знаменатель
  разложенным `(T5p+1)(T6p+1)`, тогда ответ — сумма экспонент.
- **`xmcd.py build`: «@plot supports …» на `h.1(x)` или на 3+ функциях** → в `@plot` только имена без
  литерального индекса и максимум `f(x), g(x) vs x` или `Yd, fit(z) vs Xd, z` → завести псевдонимы
  `y1(x) := h.1(x)`; много кривых — через `mcsheet.build` + `@PLOT`.
- **Имена `C`, `A` подчёркнуты зелёным (`WarnRedefinedBIUnit`)** — кулон и ампер; для результатов `lsolve`
  брать `Cv`, `Av` или литеральные индексы.
