# Стандарты разработки и архитектура на языке Python

Этот модуль определяет архитектурные принципы, стандарты кодирования, правила раннего обнаружения ошибок (Fail Fast), культуру тестирования и оформления для проектов на языке Python.

Модуль действует как системный промпт для любой нейросети при создании, модификации или рефакторинге кода на Python.

---

## 1. Абсолютные инженерные правила

1. **Архитектура — по согласованию:** не создавать новые файлы, не вводить новые внешние библиотеки, глобальные абстракции или дополнительные слои без прямого указания в ТЗ или явного согласования с пользователем.
2. **Минимальное изменение:** реализовывать ровно то, что требует задача. Не рефакторить соседний код, не менять стиль в не затронутых задачей модулях.
3. **Безопасность и запрещенные конструкции:**
   - Категорически запрещено использование `eval()` и `exec()`.
   - Запрещено использовать изменяемые объекты (`list`, `dict`, `set`) в качестве значений по умолчанию в аргументах функций (использовать `None` с инициализацией внутри тела).
   - Запрещен «голый» перехват исключений `except:` — только конкретные типы (`except ValueError:`, `except KeyError:`).
   - Все ресурсы (файлы, сетевые соединения, блокировки) освобождаются через контекстные менеджеры `with`.
4. **Сквозная цепочка интеграции:** при добавлении нового типа сущности или модели обязательно обновить всю цепочку: параметры, валидацию, сериализацию, экспорт в `__all__` и модульные тесты.
5. **Зависимости:** новые сторонние библиотеки вносятся в `requirements.txt` только по согласованию. Не подменять библиотеки стандартной библиотеки (например, `dataclasses`) тяжелыми внешними пакетами (`pydantic`, `attrs`), пока этого явно не требует ТЗ.

## 2. Архитектура и Объектно-Ориентированное Проектирование (ООП)

1. **Единая ответственность (SRP) и разделение общего и частного:**
   - Общая логика и общие поля определяются один раз — в базовом классе.
   - Класс-наследник содержит только свои специфические поля и переопределяемые алгоритмы.
   - Один класс не должен совмещать несовместимые роли: если наборы параметров расходятся, разделять их на разные типы.
2. **Полиморфизм и контракты:**
   - Вызывающий код работает с абстрактным базовым классом через единый интерфейсный метод одного имени. Запрещены ветвления `if isinstance(...)` по типам наследников в вызывающем коде.
   - Контракты оформляются через `abc.ABC` и декоратор `@abstractmethod`. Не использовать `Protocol`, пока ТЗ прямо не потребует утиной типизации.
   - При переопределении метода в наследнике использовать `@override` из модуля `typing` (начиная с Python 3.12). Декоратор `@override` ставится только на методы наследников, но **никогда** на сам `@abstractmethod` базы.
3. **Когнитивная нагрузка и правило семи ($7 \pm 2$):**
   - Не более 7 параметров в `__init__`.
   - Не более 7 публичных методов на класс (включая унаследованные).
   - Сложные составные вычисления декомпозируются на небольшие функции с понятной семантикой.
4. **Сохранение внешних контрактов:**
   - Если в проекте уже существует внешняя функция-фабрика или фасадный вызов, сохранять его работоспособность для обратной совместимости.

## 3. Идиоматичный Python и стандарты PEP

1. **Версия языка:** ориентироваться на современные возможности Python 3.10–3.12+ (объединение типов `float | None`, оператор сопоставления `match`, `@override`).
2. **Документирование модуля и явный экспорт (`__all__`):**
   - Первая строка каждого `.py`-файла в `src/` — краткий русский docstring в тройных кавычках `"""..."""`, поясняющий назначение модуля.
   - Публичные имена фиксируются списком `__all__` сразу после блока импортов:
     ```python
     """Модуль численных методов поиска корней нелинейных уравнений."""

     from collections.abc import Callable
     from typing import override
     import math

     __all__ = [
         "BisectionSolver",
         "NewtonSolver",
         "SolverResult",
     ]
     ```
   - Запрещен слепой импорт `from module import *`.
3. **Стандартные коллекции для аннотации типов (PEP 585):**
   - Использовать встроенные обобщенные типы: `list[float]`, `tuple[int, ...]`, `dict[str, Any]`.
   - Для вызываемых объектов импортировать `Callable` из стандартного модуля коллекций: `from collections.abc import Callable` (импорт из `typing` устарел).
4. **Фиксация слотов (`__slots__`):**
   - Для изменяемых классов, которым атрибуты присваиваются после создания, фиксировать `__slots__ = (...)`. Это предотвращает случайные опечатки в именах атрибутов (вызывая `AttributeError` немедленно, а не создавая паразитное поле в `__dict__`).
   - Для датаклассов указывать `@dataclass(slots=True)`.
   - Для абстрактных базовых классов (`ABC`) без собственных полей экземпляра указывать `__slots__ = ()`.
5. **Аннотации полей экземпляра (PEP 526):**
   - Метод `__init__` всегда аннотируется возвращаемым типом `-> None`.
   - Поля, инициализируемые значением `None`, обязательно снабжаются аннотацией union-типа:
     ```python
     self.step_callback: Callable[[float], None] | None = None
     ```
6. **Перечисления (`Enum`):**
   - Если числовые значения не несут физического смысла, генерировать их через `enum.auto()`.
   - Защищать перечисления от дублирования значений декоратором `@enum.unique`.
7. **Математические константы:**
   - Неинициализированные или недопустимые численные значения задавать через `math.nan` (не через строковый парсинг `float("nan")`).
   - Физические и математические константы класса оформлять как `ClassVar`:
     ```python
     from typing import ClassVar

     class FluidModel:
         GRAVITY: ClassVar[float] = 9.80665
     ```

## 4. Инварианты объектов и принцип Fail Fast

1. **Создание датаклассов только по именам полей (`kw_only=True`):**
   - Все датаклассы параметров обязаны объявляться с параметром `kw_only=True`:
     ```python
     @dataclass(frozen=True, slots=True, kw_only=True)
     class PipeParameters:
         diameter: float
         length: float
         roughness: float
     ```
   - Позиционное создание `PipeParameters(0.5, 1000.0, 0.0001)` вызывает ошибку `TypeError`. Это исключает тихие ошибки при изменении порядка полей.
2. **Ранняя валидация в `__post_init__`:**
   - Любое физически невозможное или численно некорректное значение (ноль диаметра, отрицательная длина, `NaN`, бесконечность) отсекается немедленно в момент инициализации:
     ```python
     def __post_init__(self) -> None:
         if not math.isfinite(self.diameter) or self.diameter <= 0.0:
             raise ValueError(f"Диаметр трубы должен быть конечным положительным числом, получено: {self.diameter}")
         if not math.isfinite(self.length) or self.length <= 0.0:
             raise ValueError(f"Длина трубы должна быть конечной и положительной, получено: {self.length}")
     ```
3. **Защита от вызова незаданных колбэков:**
   - Если объект был создан с необязательным полем `None`, публичный метод обязан перед вызовом проверить его наличие и выбросить информативный `ValueError`, а не падать внутри вызова с непонятным `TypeError: 'NoneType' object is not callable`.

## 5. Принцип DRY (Don't Repeat Yourself)

1. **Переиспользование логики:**
   - Если расчетный шаг, валидация или алгоритм уже реализованы — вызывай их напрямую.
   - Метод наследника, расширяющий поведение, вызывает `super().method()`, а не пересчитывает базовые величины заново.
2. **Модульные хелперы:**
   - Повторяющиеся блоки проверок (проверка сходимости, вычисление невязки, отсечение диапазонов) выносятся в модульные приватные функции с префиксом `_` (например, `_eval_residual`, `_clip_range`).
   - Вынос приватных хелперов на уровень модуля разгружает тело классов и сохраняет простоту их интерфейса.
3. **Границы DRY:**
   - В тестах не объединять содержательно разные тестовые сценарии в один нечитаемый цикл ради сокращения строк: структура Arrange / Act / Assert важнее слепой эстетики DRY.

## 6. Комментарии, docstrings и форматирование

1. **Docstrings:**
   - Все классы, публичные и защищенные методы, а также свободные функции снабжаются docstring на русском языке.
   - Для нетривиальных функций указываются блоки `Args:` и `Returns:`.
   - Не описывать подробно иерархию стандартных исключений: достаточно указать условия отказа.
2. **Комментарии «Зачем, а не что»:**
   - Однострочный `#` пишется только тогда, когда причина неочевидна из кода: физическое допущение, математический трюк, обход численной нестабильности.
   - Запрещено комментировать очевидные действия («создаем объект», «вызываем функцию», «это полиморфизм»).
   - Запрещены декоративные разделители вида `# ********************`.
3. **Математика и формулы:**
   - В комментариях пишется сама физическая формула, а не абстрактная ссылка «как в формуле (3) методички».
4. **Юникод в комментариях и docstring:**
   - Степени, индексы и греческие буквы пишутся Юникод-символами: `м³`, `м²`, `ρ`, `λ`, `ν`, `Δ`, `x₀`, `pₙ`, `εₓ`.
   - Записи `м^3`, `rho`, `p_н` запрещены.
   - В идентификаторах самого кода используются стандартные латинские ASCII-имена (`density`, `roughness`, `p_initial`).
5. **Размерности физических величин в тестах:**
   - Литералы параметров в тестах подписываются комментариями с единицами измерения:
     ```python
     # Arrange: параметры нефтепровода
     length = 150_000.0  # м
     diameter = 0.514    # м
     density = 850.0     # кг/м³
     ```

## 7. Стандарты тестирования (pytest)

1. **Структура Arrange / Act / Assert (AAA):**
   - Каждый тестовый кейс обязан содержать три явные фазы, разделенные комментариями:
     ```python
     def test_returns_correct_flow_rate_for_laminar_regime() -> None:
         """Проверяет расчет расхода в ламинарном режиме течения."""
         # Arrange: задаем параметры режима течения
         pipe = PipeParameters(diameter=0.1, length=100.0, roughness=1e-5)
         fluid = FluidParameters(density=900.0, viscosity=0.05)
         solver = HydraulicSolver(pipe=pipe, fluid=fluid)

         # Act: вычисляем расход при заданном перепаде давления
         result = solver.solve_flow_rate(delta_pressure=50_000.0)

         # Assert: проверяем соответствие аналитическому значению
         assert result.is_converged
         assert math.isclose(result.flow_rate, 0.0125, rel_tol=1e-3)
     ```
2. **Именование тестов:**
   - Файл теста: `test_<имя_модуля>.py`.
   - Имя функции теста: `test_<глагол>_<проверяемое_поведение>` (например, `test_raises_on_zero_diameter`, `test_returns_exact_root_for_linear_function`).
   - Имена тестов не должны содержать транслита.
3. **Проверка исключений:**
   - Исключения проверяются строго через контекстный менеджер `pytest.raises`:
     ```python
     with pytest.raises(ValueError, match="Диаметр трубы"):
         PipeParameters(diameter=-0.1, length=10.0, roughness=1e-5)
     ```
4. **Изоляция тестов:**
   - Тестовые файлы не должны зависеть друг от друга. Не импортировать фикстуры и тестовые данные из одного файла `test_*.py` в другой (выносить общее в `conftest.py` или локальные фабричные хелперы).
5. **Неприкосновенность упавших тестов (запрет подгонки тестов под код):**
   - Если тест упал — категорически запрещено изменять сам тест ради того, чтобы он формально прошел. Изменение тела теста для получения зеленого статуса — грубейшая антипрактика и самообман.
   - Причина падения всегда выявляется и устраняется в рабочем коде реализации.
   - Если причина сбоя заключается не в ошибке реализации, а вызвана осознанным и вынужденным архитектурным решением (или пересмотром спецификации), из-за которого поведение намеренно изменилось, агент **обязан остановить работу и запросить явное разрешение пользователя** на видоизменение теста, подробно аргументировав необходимость правок.
   - В любых ситуациях с падением тестов агент обязан действовать предельно аккуратно и советоваться с пользователем в обязательном порядке.

## 8. Научная визуализация и построение графиков (Matplotlib + ГОСТ)

1. **Единый академический стандарт графиков:**
   - Все иллюстрации, сохраняемые для отчетов и технической документации в каталоге `figures/`, обязаны генерироваться в строгом полиграфическом стандарте (детальная спецификация и программный шаблон зафиксированы в [doc_markdown.md](doc_markdown.md)):
     - **Шрифт:** исключительно Times New Roman (`font.family: "Times New Roman"`, математический набор STIX);
     - **Размеры кеглей:** базовый 16 pt, подписи осей 18 pt, засечки осей 15 pt, легенда 13 pt;
     - **Линии осей и засечки:** толщина 1.4 pt, засечки направлены **внутрь** (`xtick.direction: "in"`), толщина засечек 1.2 pt;
     - **Скрытие рамок:** верхняя и правая рамки графика скрываются (`spines["top"].set_visible(False)`, `spines["right"].set_visible(False)`);
     - **Сетка:** сплошная линия `#6a6a6a` толщиной 1.15 pt под графиками (`zorder=0`, `axisbelow=True`);
     - **Стрелки на осях:** черные полигоны `Polygon` на концах осей с динамическим удлинением на 12–14 pt;
     - **Подписи осей:** размещаются строго у стрелок (справа от оси X, сверху над осью Y);
     - **Числа на осях:** русская запятая во всех десятичных дробях через `FuncFormatter`;
     - **Угловые коллизии:** подавление засечки оси X в углу (`suppress_origin_x=True`) при ненулевом начале координат;
     - **Подавление конфликтующих делений сетки:** подавление цифр регулярной сетки (`suppressed_xticks`, `suppressed_yticks`) при близости проекций расчетных точек к шагу сетки с сохранением самой линии сетки;
     - **Штрихпунктирные линии проекций (`dashdot`, `-.`):** линии проекций от расчетных точек и экстремумов обязаны идти строго до координатной оси и завершаться на ней, не выходя за пределы оси в область подписей;
     - **Монохромные маркеры точек:** расчетные точки на кривых (точки на РАФХ, пики $A_1, A_2$) выполняются строгим черным цветом (`color="black"`) для контрастности и монохромной печати;
     - **Бесконфликтность выносных подписей:** подписи точек и стрелки выносятся в свободные квадранты без пересечения графиков и стрелок осей;
     - **Динамический клиренс легенды:** при колебательных процессах запас по высоте оси $y$ должен составлять не менее 20–25% от размаха, чтобы пики процесса не пересекали рамку легенды;
     - **Физический диапазон характеристик:** частотные годографы и РАФХ рассчитываются строго в границах физической реализуемости $[\omega_1, \omega_3]$ без паразитных ветвей вдоль осей;
     - **Чистота полотна:** категорический запрет `ax.set_title()` и текстовых плашек на поле данных графика; запрет упоминания внутренних имен скриптов автоматизации в тексте отчетов.
